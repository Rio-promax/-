## 2. 现有产品与教程的区别

2026-10-26 源码核对范围为当前问答知识索引、硅基流动适配和检索评估脚本。这里只陈述代码存在，不据此推断生产可用。

| 环节 | 当前证据 | 适用性判断 |
|---|---|---|
| embedding | [siliconflow_retrieval.py](../../../src/services/core/app/knowledge/siliconflow_retrieval.py) 请求 `Qwen/Qwen3-Embedding-8B`，维度 1024，批量 32 | 是云端稠密 embedding，和教程本地 BGE-M3 同时生成稀疏/稠密向量不同 |
| 本地检索与融合 | [ask_index.py](../../../src/services/core/app/knowledge/ask_index.py) 使用 SQLite FTS5 trigram/BM25、sqlite-vec；RRF 常数 60，候选上限规则 `max(20, 4*limit)` | 已具词法和稠密两路；BM25 不等于 BGE-M3 学习型稀疏向量。混合检索不要求先换 Milvus |
| 神经重排 | 云端适配请求 `Qwen/Qwen3-Reranker-8B`，混合路径可调用 | 已有模型重排调用；并不代表重排收益已实测，也不是 ColBERT 实现 |
| 切片 | profile 标记 `one-transcript-segment-v1` | 当前以已有字幕段为基础；总结流程的切片不能自动视为问答切片 |
| 评估 | [ai_ask_retrieval_eval.py](../../../src/services/core/tools/ai_ask_retrieval_eval.py) 比较 keyword/vector/hybrid，要求至少 60 道人工复核题，报告隐藏命中原文 | 有检索评估基础；尚不足以逐段调试和评价完整回答 |
| 其他查询策略 | 本轮在知识索引链路未发现 Text2SQL、自查询、多查询、HyDE、RankLLM、ColBERT 或完整查询路由 | 应按后续候选记录；不是对项目所有模块作不存在声明 |
| 产品开放与质量 | [现有 AI 问答方案](../2026-10/10-10_AI问答产品完善_解决方案.md) 记录云端真实接口、全库重建、性能及题卡待验收，人工金标准为 0，回答功能未开始 | 这些是文档记录，正式实施前须重新盘点运行状态和题集，不能直接当本轮实测结果 |

云端 embedding 不阻碍本地索引、融合和实验。LLM 改写、Text2SQL 生成、LLM 路由、RankLLM、LLM 压缩和回答另需生成接口；embedding/reranker API 不能替代文本生成。简单规则、融合、去重和确定性指标无需新模型。更换 embedding 模型、维度或输入文本后须建立对应新向量；只改融合或 reranker 通常可复用原向量。

模型微调与上述参数调优是不同工作：前者还需要合格训练样本及权重或供应商微调接口。当前没有证据可认定云端模型支持本品所需微调，先用失败样例证明需要，再核验服务能力。

## 3. 查询构建、Text2SQL 与分发

本节为产品候选设计。示例字段仅在实际保存、语义明确且可查询时启用；教程中的播放、点赞等统计字段不能覆盖本品现行“不持久化统计计数”规则。

| 策略 | 产品例子 | 建议执行方式 |
|---|---|---|
| 元数据过滤 | 在指定作者、来源或收藏夹中寻找某观点 | 解析为语义查询及结构化条件；验证字段、类型、比较操作与当前用户范围，过滤两路检索 |
| 排序/最值/聚合 | 找出最长的视频，统计本月归档数 | 用明确排序或聚合计算；不能只取语义最相近的一条代替数据库计算 |
| Text2SQL | 按时间、标签或来源分组统计，或关联资料记录 | 提供相关 schema、字段说明、术语和高质量示例；复杂 schema 可先检索相关知识，再生成 SQL |
| 组合查询 | 找到本月收藏中最长的视频，再说明其中的 RAG 原理 | 先确定合法 Content 集合，再检索该集合的原始证据；结构化结果与文字引用分别保留来源 |
| 查询路由 | 问题需要查正文、元数据/SQL，还是两者 | 对照规则、embedding 相似度与 LLM 路由；保留人工指定正确路径作为实验对照 |

少量固定意图可先生成受约束 JSON 指令，由代码编译参数化查询。复杂关联与聚合再引入 Text2SQL。数据库存在本身不代表已有 Text2SQL；模型生成 SQL 也不代表可直接执行。

SQL 执行候选契约：只暴露必要只读表/视图；校验表、字段、语句类型和用户范围；限制结果量、执行耗时及纠错次数；阻断写入和未授权对象。把数据库错误反馈模型时只提供必要诊断。保留 SQL、参数和结果来源供本地检查，模型不得扩大用户已经确认的资料范围。语法合法或执行成功仍需检验结果是否正确。

推荐查询计划包含原问题、独立检索问题、范围快照、过滤、排序/聚合、子问题、数据源路径与所选策略。原文指令和资料内容不应成为路由控制指令；缺少可查询字段时说明能力限制，不伪造字段或数据。

## 4. 重构、召回、重排与上下文处理

### 4.1 查询重构候选

| 方法 | 适用的失败现象 | 实验约束 |
|---|---|---|
| 追问补全/改写 | “它”“刚才那个”缺少明确实体，或用户措辞与字幕不同 | 只使用当前有效会话与范围；保留原问题，检查否定、实体、时间和范围不丢失 |
| 多表述查询 | 相同意图换说法后召回差异明显 | 原问题仍参与；限制扩展数，分别记录每条查询的增量证据与费用 |
| 子问题拆解 | 比较多份资料或同时询问多个维度时漏掉一部分 | 每个子问题独立检索；逐项核对必需证据，合并去重后仍保留子问题来源 |
| Step-back | 过于具体的问题难匹配，相关背景概念却能命中 | 与原问题并用；抽象问题命中不能代替对具体事实的证据要求 |
| HyDE | 简短问题与长文段在表达和粒度上差距大 | 生成假设文本后向量检索真实资料；假设文本不入证据库、不作引用，测量幻觉造成的检索漂移 |

### 4.2 召回与融合实验

对比 BM25 单路、稠密单路、RRF 和加权融合。加权融合必须先统一得分方向和量纲，明确 `α` 对应稠密路权重；BM25 原始分数、向量距离不能直接相加。归一化方法也是实验变量，不假定某个权重通用最优。

分别调整两路候选量、融合后候选量和最终 top-k；RRF 以当前 `c=60` 为基线，其他候选值由实验配置声明。先固定或关闭神经重排对比融合，再独立比较开启重排的净收益。保存足够大的原始候选池后可离线截取和重算；若需超出已保存候选池，必须重新召回。

### 4.3 重排选择

| 方法 | 角色与产品选择依据 |
|---|---|
| RRF | 基于排名融合多路结果，无需生成模型；保留为当前融合基线 |
| 当前云端 reranker | 对查询与候选相关性评分；比较开启/关闭及不同候选规模，不能把分数未经校准地当作可回答概率 |
| RankLLM | 用生成模型对候选排序；仅在复杂问题样例证明可能受益时实验，检查输出 ID、完整性、顺序稳定性和费用 |
| Cross-Encoder 类替代模型 | 对查询—文段成对评分；按中文、长字幕、数字和否定等切片比较，不能只看通用榜单 |
| ColBERT | 使用 Token 级后期交互；需要相应模型/服务与表示能力，现有单稠密向量 API 不直接提供该能力 |

MMR 主要平衡相关性与多样性，与神经相关性重排分别评测。重排只能重新排列已召回证据，无法恢复候选池里完全缺失的材料；先检查候选召回上限，再判断重排问题。

### 4.4 去重、压缩、校正与回答

先比较重复片段去重、相邻片段合并、句子窗口/父子片段扩展，再试基于句子相似度或 LLM 的抽取压缩。每种方法检查关键条件、数字、冲突、否定和出处映射；压缩后的内容必须仍能回到真实原文位置，不能生成不存在的时间戳。

校正候选流程是评估当前证据后决定正常回答、精炼、有限补查、澄清或拒答，并记录动作原因、次数及结果。教程示例包含联网补查；当前 AI 问答明确不联网，因此只采用范围内补查，不将 Web 搜索自动接入本产品。用户选定模型不可用时的处理仍遵循现有设置规则，不能借“校正”静默换服务。

回答生成需另建完整问答链路，保留真实 Content、材料版本、证据位置和范围快照；摘要与原文证据区分。资料冲突应保留分歧，证据不足不生成确定结论。

## 5. 本地 Python 实验工作流

目标是能像教程示例那样在本地执行、检查中间结果，并让实验与产品共用实现。现有评估脚本是起点，不另写一套与产品检索不同的演示算法。

1. 冻结语料快照、索引身份、问题集与模型/提示词版本；记录配置和运行标识。
2. 预览同一材料在不同切片配置下的原文、长度单位、重叠与原始时间/片段覆盖；识别证据是否被切断。
3. 在独立实验索引中建立候选切片：现有单字幕段、相邻段合并、长段按句拆分、句子窗口或父子片段；尺寸根据真实语料长度分布选择。
4. 单题 trace 显示原问题、改写/子问题、路由、过滤或 SQL、两路候选排名/得分、融合结果、重排分数及最终上下文；回答链路存在后再记录回答与引用。
5. 批量跑相同问题集，按实验矩阵只改变一个主要变量，计算分层指标和成本；候选固定时离线重算融合，避免反复调用 API。
6. 检查失败样例后选择配置，再跑未参与调参的留出集；将确认过的失败样例纳入后续回归。
7. 只有有收益且满足范围、引用与运行约束的配置才进入正式路径，保留配置版本和回退依据。

数据落点建议沿用项目规则：正式工具代码归 `product/src/` 交付入口；实验索引、候选缓存与运行产物归 `product/local/`，不写进原始归档。实际文件名与目录在实施时依现有 README 确定，本轮不创建实验代码或运行目录。

现有评估产物隐藏命中原文，不能为实验需求直接改成默认全量记录。原文 trace 应是明确启用的本地调试产物，不记录凭证；常规报告保持脱敏，能够用稳定标识追溯配置与结果即可。

## 6. 分层评测与发布门槛

### 6.1 数据与可比性

问题应包含精确术语/型号、人名数字、同义改述、跨段与跨资料、多条件过滤、排序聚合、冲突、无答案、范围限制、追问、仅摘要及资料内诱导指令。每题记录问题类型、可回答性、允许 Content、全部必需证据、来源版本和参考答案；路由与 SQL 题补人工正确路径及预期结果。

切片对比要把金标准绑定到原始来源证据范围，而非仅绑定易变的 chunk ID，避免换切片后指标失去可比性。分离调参集和留出集，避免同源近重复或同义题跨集合泄漏。合成题须人工复核；空金标准不能用模型自评自动填成“已通过”。

### 6.2 指标与判读

| 阶段 | 建议记录 | 判读注意 |
|---|---|---|
| 检索 | 单证据 Recall@K、全部必需证据命中率、MRR、nDCG、Precision@K、两路独有有效证据 | 分清“找到任一证据”与“全部证据齐全”；nDCG 需相关性标注，Precision 需足够完整的相关证据标注 |
| 查询构建 | 字段/操作/单位/过滤/排序/聚合正确率 | 错误过滤可能在召回前排除正确材料，应单独统计 |
| Text2SQL | 合法率、执行成功率、结果正确率、只读与范围约束、纠错收益 | 以结果语义正确为核心，不要求等价 SQL 字符串完全一致 |
| 重构/路由 | 意图保真、子问题覆盖、路径正确率、相对人工路径的损失 | 区分路由错误与检索器本身错误；记录未知或含糊问题处理 |
| 重排 | 前后 MRR/nDCG、前 K 证据完整性、延迟与费用 | 保持召回池一致；候选缺证据不能归因于精排 |
| 压缩 | 必需证据保留率、引用有效性、Token 减少、答案变化 | 缩短上下文不能以删掉关键限定为代价 |
| 校正 | 失败恢复率、正确样例退化率、额外查询次数与成本 | 防止无界循环，以及把不足资料变成无依据回答 |
| 回答 | 正确性、完整性、忠实度、相关性、引用精确率/召回率、拒答与冲突保留 | 忠实于上下文不等于答案本身正确；必须核对来源与参考答案 |
| 运行 | 分步骤及总 p50/p95 延迟、API 次数/Token/费用、失败率、覆盖与新鲜度 | 冷热缓存和环境分开报告；云端性能必须实测，不沿用本地模型旧数字 |

Ragas、LlamaIndex Evaluation 等用于借鉴或接入评测，不要求为此迁移主框架。可编程校验来源 ID、范围、SQL 与位置；生成质量可增加 LLM 裁判，但需固定评估器版本和规则、用人工样本校准并回看争议样例。不能把未经校准的模型总分当发布结论。

### 6.3 门槛管理

当前检索脚本有至少 60 道人工复核题及既有 Recall 门槛；这些只属于现有检索评估契约，不能直接充当 Text2SQL、路由或最终回答门槛。相关数值和既有方案见源码及第 2 节链接，实施前先校核有效版本。新增阶段以真实基线和业务风险确定门槛，不在本轮虚构达标率。

发布检查至少包括未授权范围命中、非法 SQL、无效来源引用和虚构时间戳的阻断案例；总体均分提高不能掩盖这些失败。分别记录自动验证、人工验收与未执行项，未确认的体验/语义质量仍为待人工验收。

## 7. 推进顺序、失败归因与未决项

建议顺序：题集与可追踪基线 → 切片及索引对比 → 两路召回与融合 → 当前 reranker 对比 → 查询构建与路由 → 有需求证据的 Text2SQL/重构 → 上下文处理与校正 → 完整回答和端到端回归。按真实失败类型选择下一步，不要求每个问题调用所有组件。

| 现象 | 优先检查 |
|---|---|
| 两路都没有必需证据 | 原始资料覆盖、切片、过滤、embedding 输入和索引新鲜度 |
| 单路命中，融合后丢失 | 候选规模、融合参数、归一化方向与范围一致性 |
| 候选中有证据，最终排名低 | 重排与 top-k，是否存在重复候选挤占 |
| 选错资料源或统计结果不对 | 路由、字段映射、SQL/聚合语义，而非先换 embedding |
| 证据正确但回答错误 | 上下文组装、压缩、提示词和回答模型 |
| 答案似乎正确但引用失效 | 来源映射、材料版本、时间/片段校验 |
| 成本或延迟上升 | 多查询数量、候选池、重排/压缩次数与缓存命中；先测量再减少路径 |

待决项：真实可查询元数据和业务视图；生成模型及配置复用方式；查询计划字段和路由类别；切片长度单位及候选参数；原文调试产物保留规则；金标准题集和人工复核安排；各阶段门槛；哪些策略形成正式需求。ColBERT、多向量表示、知识图谱和 Agentic RAG 需独立说明问题收益与额外成本，不因教程有章节就默认纳入实施。
