# 平台登录与授权方案：搜索参考

> 用途：电脑版产品的备用实现路线。产品只保存用户主动授权后的“平台连接记录”，不默认扫描浏览器全部 Cookie。优先使用官方授权；只有平台没有可用官方接口时，才使用产品专用浏览器会话或用户明确授权的浏览器桥接。

## 一眼看懂的技术路线

```text
平台连接页
→ 用户扫码/打开官方登录页
→ 验证“凭证能否访问目标接口”
→ 本机加密保存 Cookie、Token、刷新令牌或浏览器会话
→ 输入链接时按域名找到连接记录
→ 有效：直接读取；可刷新：刷新一次；失效：提示重新登录
```

连接状态：`未连接`、`检查中`、`已连接`、`已过期`、`需重新登录`、`需要人工验证`、`暂未适配`。

## 各路线怎么取舍

- 官方 OAuth/Token：优先级最高，权限和刷新规则更清楚；但需要平台审核或开发者资质，且不一定能读取所有网页内容。
- 二维码登录：适合 Bilibili 等平台，用户不需要把密码交给产品；必须保存并保护刷新令牌，并在每次任务前验证。
- 产品专用浏览器会话：适合小红书等依赖浏览器环境的平台；不要只复制一串 Cookie，要保留同一浏览器配置和 User-Agent。
- 浏览器扩展：只作为电脑端备用。必须由用户明确授权当前网站，不能默认读取所有网站登录态。
- 陌生网站：登录成功不代表已经支持内容提取；仍需要独立的来源适配器、正文/字幕/媒体获取逻辑。

## 产品落地检查清单

1. 连接成功后立即调用平台轻量接口，成功后才保存凭证。
2. 任务开始前检查连接；自动刷新最多一次，失败后显示“重新登录”。
3. 每个平台单独保存连接记录，可支持同平台多个账号，但不能覆盖错账号。
4. Cookie、Token、刷新令牌和浏览器会话只进本机加密存储，不进日志、知识库、导出文件或 ASR 请求。
5. 退出登录要删除当前平台凭证；换号要删除旧凭证后重新连接。
6. 公共公众号文章优先匿名读取；不要为了公开文章强制用户登录公众号后台。
7. 反爬、验证码、IP 风控和平台规则变化都要显示为具体状态，不能笼统显示“总结失败”。

## 参考资料使用规则

官方文档用于确认授权边界；GitHub 代码用于借鉴登录、会话、字幕和错误处理的实现路径。小红书、知乎部分项目使用内部或逆向接口，只能作为后备研究样例，不能当作长期稳定或官方保证；上线前必须重新验证平台规则和接口可用性。
