### 原因

**1. 垂直空白的根因（唯一根因，已用 CDP 定量确认）**

- 触发器：`.inline-controls` 在 680 块 `style.css:1419-1422` 被设为 `flex-direction: column`。`div.inline-controls.library-controls` 同时带这两个 class，所以手机上 `.library-controls` 是**列向** flex 容器。
- 冲突声明：`.library-search-field`（`style.css:5915`）的 `flex: 1 1 320px`（`:5917`）—— 这个 `320px` 是**为桌面横排写的宽度预算**。
- 计算后果：列向容器的主轴是垂直方向，`flex-basis: 320px` 于是被解释成**高度**。实测 `getComputedStyle` 得 `flex-basis: 320px`、`height: 320px`、`rect.h = 320`。
- 视觉后果：表单高 320px，但其内部输入框只有 38px，又被 `align-items: center` 垂直居中 → 输入框落在 320px 盒子的正中间，上下各约 141px 纯空白。这就是用户看到的「搜索框悬在页面中间、上下大片空白」。
- 连带后果：`.library-controls` 408px → `.page-header` 451px → 首卡 top = 844px。

**2. 收藏夹四个按钮竖排的根因（独立根因，同样定量确认）**

- `style.css:1771`（一个既有 680 块内）有 `.favorite-folders-heading .button { width: 100% }`。
- 该规则特异性 0,2,0，命中 `.favorite-folder-heading-actions` 内的全部四个按钮，把它们拉成 316px 全宽；容器 `flex-wrap: wrap` 于是把四个按钮折成四行，实测 316×170。
- 注意：这条规则只声明 `width`。仅加 `flex: 0 0 auto` **无效**（实测仍是 316px），必须同时把 `width` 重新声明为 `auto` 才能覆盖。

**3. 标题两行截断：一条我先误判、后被实测推翻的结论（实施中发现，非派单项；此处为 R2 补丁更正）**

- 背景：`.library-card-title` 的基规则（`style.css:3051`）用 `display: -webkit-box` + `-webkit-line-clamp: 2` 做两行截断。标题在行式布局里变成了 grid 子项，我曾据此推断 grid 子项会被 blockify 成 `flow-root`、clamp 随之完全失效。**这个推断是错的，本段予以撤回。**
- 推翻证据一（受控测试）：`getComputedStyle` 在 **flex / grid / block 三种上下文**下都返回 `display: flow-root`，而 `-webkit-line-clamp` **仍然生效**——单行容器里测得 2 行 / 40px。所以「blockify 让 clamp 失效」不成立，display 计算值与 clamp 是否生效没有因果关系。
- 推翻证据二（视觉 + 逐字节）：390px 视口下把首张卡片截图放大，第二行末尾**本来就有省略号**（可见 `…让外层…`）。R2 补丁前后同一裁剪区域截图 md5 **完全相同**（`bd8818824cf28bbfa1d15095970b26c1`），说明省略号在补丁前就已存在。
- 那 57.9px 是什么：它是 grid 子项被行高/`align-content` 拉伸后的**盒子高度**，不是文字行数；把 `line-height` 钉成 `1.35` 后该盒子变成 37.8px，与 2 行文字高度一致。也就是说当初「3 行」的读数来自盒子而非文字。
- 现在的实现：`line-height: 1.35` + `max-height: 2.7em` 保留，作为「即使某引擎不支持 clamp，行高也不会超过两行」的兜底；另补一条无前缀 `line-clamp: 2`（与项目里 `:2684` / `:3477` / `:4437` / `:6279` / `:6816` 五处既有写法一致）。Chrome 156 实测 `CSS.supports('line-clamp','2') === false`，所以这条声明在本机是**惰性**的，真正起截断作用的是基规则的 `-webkit-line-clamp: 2`。

**4. 其他**

- 无封面的卡片（34 张中 9 张，`data-cover-state="missing"`）由 `createSourceCover` 的 `showFallback()` 把**标题**写进封面里的 `.source-cover-fallback-title`。用户截图里「标题出现两次」即此，不是重复渲染。行式布局下封面只有 104px 宽，该文字必然溢出。

全部规则位于新增块 `style.css:6885-7036`（单一 `@media (max-width: 680px)`）。

**① 列表改单列**（`:6887`）

```

  grid-template-columns: minmax(0, 1fr);
  gap: 8px;

```

**② 卡片改行式**

标题的 `line-clamp: 2` 是 R2 补丁补上的无前缀写法（与项目里 `:2684` / `:3477` / `:4437` / `:6279` / `:6816` 五处既有写法保持一致）。实测 Chrome 156 的 `CSS.supports('line-clamp','2')` 为 **false**，因此这条声明在本机浏览器上是**惰性的**（加与不加截图逐字节相同）；真正起截断作用的是基规则的 `-webkit-line-clamp: 2`（实测生效），`max-height: 2.7em` 只作为最后的行高兜底。

封面占位文字的处理选择「隐藏」而非「压成 2 行」：104px 宽的封面里即使 9px 字号也放不下一个中文标题，而标题就在右侧同一样内，保留只会造成重复与溢出。隐藏后 `.source-cover` 仍有 `border: 1px solid` + `background` 的占位面，不会塌成空白洞。实测 `overflowingCovers: []`。
