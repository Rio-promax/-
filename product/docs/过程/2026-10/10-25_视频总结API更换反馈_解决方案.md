# 10-25 视频总结 API 更换反馈 · 解决方案

## 目标

让用户只凭 API 地址和密钥就能直观看到可用总结模型；选择模型后自动验证并保存。模型列表支持常见的顶部下拉刷新，状态复用设置页已有反馈，不增加单独的模型获取按钮。

## 已确认行为

| 编号 | 需要解决的现状 | 目标行为 |
|---|---|---|
| R1 · 接口可用性 | 用户无法判断当前 API 是否可访问、鉴权成功并返回内容。 | 模型发现调用当前 API；选中模型时使用现有最小总结请求验证。视频总结端到端成功仍单独人工验收。 |
| R2 · 模型选择 | 模型列表在 10 个以内时可紧凑展示，超过 10 个时小下拉框难以浏览；输入行未占满可用宽度。 | 10 个以内显示紧凑列表；超过 10 个使用可搜索、每页 10 项的弹窗；模型输入行铺满父容器。移除总结模型“保存”按钮，选中模型后自动验证并保存完整配置；手动填写后按 Enter 提交。 |
| R3 · 自动发现与缓存 | 配置已有 API 时需点击独立按钮获取模型，重开页面后候选列表丢失。 | 打开模型下拉时，如当前配置尚无本次会话的最新结果，自动获取模型。返回目录保存在本机，按服务商、规范化 URL 和协议计算指纹；不保存 API 密钥或原始 URL。仅成功且服务支持目录时用新结果覆盖旧缓存；失败时保留同一配置的旧目录。 |
| R4 · 协议与选择界面 | Chat Completions / Responses 含义不直观；模型 ID 下方有服务商说明，选择区显得杂乱。 | 协议标签保留英文名称并补充中文本意；说明 URL/密钥负责连接与认证、协议决定请求格式和接口路径。移除模型 ID 下方服务商说明及多余 Query 文案，保留清爽的模型选择区。 |
| R5 · 目录刷新 | 当前手动重取依赖“获取模型”按钮。 | 移除该按钮。在紧凑列表或大弹窗列表滚动位置位于顶部时，向下拖动至少 56px 并松开即重新获取目录；向上拖动仅用于正常浏览。加载和失败反馈沿用现有状态提示；刷新完成后返回列表，失败时保留旧候选。下拉打开仍会在目录过期/配置变化后自动请求。 |

## 实施边界与验收

- 只修改总结设置页、模型目录缓存/刷新交互及本方案对应的任务记录。
- 配置字段变化仍沿用现有去抖自动发现。模型选择的保存继续调用现有最小文本请求；验证失败时不保存新配置。
- 目录刷新失败不清除同一 API 配置的本地缓存。切换 URL 后旧缓存不作为新 URL 的候选；新目录成功返回后覆盖单条本地缓存。
- 自动检查：`node --check product/src/services/core/app/ui/app.js` 和本轮文件 `git diff --check`。
- 人工验收：短列表与超过 10 项弹窗均可向下拖动刷新；向上拖动可正常滚动；无目录时可重试；慢响应、失败时状态清晰且旧列表保留；选择模型后自动验证并保存；用配置生成视频总结。

## 协议简释

- Chat Completions 使用对话消息格式及 `/chat/completions` 接口。
- Responses 使用 `input` 输入及 `/responses` 接口，返回另一种响应结构。
- URL/密钥字段提供服务器地址和认证；调用协议决定应用采用哪种请求与解析方式，需选择服务商支持的类型。
