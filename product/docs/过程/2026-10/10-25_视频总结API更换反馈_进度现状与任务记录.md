## 任务记录

- 用户决定：打开模型列表时自动获取；选择模型触发保存流程，保存前沿用现有最小文本连接验证，不在获取目录时发送总结生成请求。
- 自动发现从 API 地址、API 密钥或调用协议字段提交，以及服务商切换后触发；去抖 700ms。输入过程中清理旧模型和旧验证状态，避免把未完成的密钥发送出去。
- “获取模型”按钮改为模型列表顶部向下拖动刷新；打开下拉时若当前配置尚无最新目录则自动获取。接口不提供目录时，仍允许手动填写模型 ID 并按 Enter 触发最小连接验证和保存。
- 真实 API 核实：模型查询接口返回 161 个候选模型；当前 `qwen3.7-flash` 最小请求返回成功消息“总结模型连接成功”。这证明服务可鉴权并返回文本响应；本轮未提交视频素材做完整总结。
- 视频总结调用链：保存前的 `/api/v1/settings/summary/test` 使用所选模型发送短文本请求；实际总结通过同一保存配置调用总结 API，传入带时间范围的转写分块，非空返回文本解析后保存。外部调用失败会作为任务错误反馈。
- 用户补充的界面要求：模型不超过 10 项时保留紧凑列表；超过 10 项时打开可搜索、分页的模型弹窗；协议名称保留英文并增加中文含义及简短用途说明；移除总结模型 ID 下方的 Qwen 服务商提示，并修复输入框和下拉箭头之间的空白。
- 后续界面改造以 `9364cfb` 为基线，仅修改总结设置 UI 及本记录；脚本语法和 diff 检查通过，未运行测试套件，人工验收待用户确认。
- 用户补充的自动保存要求：移除“保存”按钮；选择模型后立即执行最小连接验证并保存服务商、URL、协议、密钥和模型配置；手动填写模型 ID 后按 Enter 提交保存。成功返回的模型目录在本机缓存，不保存密钥或原始 URL；URL/服务商/协议变更触发重新获取，成功后覆盖当前缓存。
- 用户补充的目录刷新要求：移除独立“获取模型”按钮；紧凑列表或弹窗列表在顶部向下拖动并松开时重新获取，向上拖动保留浏览/滚动用途；刷新反馈沿用设置页已有状态提示。
- 方案与实现基线：本轮决策写入 [10-25 视频总结 API 更换反馈 · 解决方案](10-25_视频总结API更换反馈_解决方案.md)；目录刷新阈值为 56px，开始/完成/失败均复用既有状态区。
- 协议选择说明：Chat Completions 与 Responses 影响请求路径、请求结构和响应解析；API URL 与密钥本身不能决定服务商期望哪一种协议。
- 本轮自动获取、自动保存与拖动刷新改造以 `8074850` 为基线，仅修改总结设置 UI、对应解决方案及本记录；静态检查通过，未运行测试套件，人工验收待用户确认。
- 基线：`master`，实施前 HEAD 为 `9c418a5`；实施前工作区已有大量其他改动。本轮只提交总结设置、对应检查及本记录。
