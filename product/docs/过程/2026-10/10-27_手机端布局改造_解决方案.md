## R1 底部五标签导航与基础适配

### 现状

1. `index.html:5` 原为 `<meta name="viewport" content="width=device-width, initial-scale=1" />`，**缺 `viewport-fit=cover`**。缺它时 iOS 不会把页面铺到刘海/底部横条区域，`env(safe-area-inset-bottom)` 恒为 `0px`。
2. 手机端导航原本是**顶部横条**，不是底部标签栏。生效规则在 `style.css:4522` 起的 `@media (max-width: 680px)` 块内：
   - `.sidebar { border-right: 0; border-bottom: 2px solid var(--desk-line); padding: 12px 14px; }`
   - `.brand { display: none; }`（已隐藏，本轮沿用）
   - `.navigation { grid-template-columns: repeat(4, minmax(0, 1fr)); }` → **5 个按钮排 4 列**，「设置」被挤到第二行单独占位。
   - `.nav-button { justify-content: center; min-height: 38px; padding: 6px; }` → 触控高度 38px，低于 48px。
   - `.nav-icon { display: none; }` → 图标全部隐藏，只剩文字。
   - `.connection { display: none; }`（已隐藏，本轮沿用）
   - `.main-content { padding: 22px 16px 34px; }`
3. `style.css` 共有 **16 个** `@media (max-width: 680px)` 块（起始行：1379、1544、1597、1607、1623、1765、2139、2525、3698、4522、4791、4837、4905、5111、6574、6688；其中 4837 为 R1 补丁新增）。同一选择器在多块中重复，**后出现的块覆盖前面的块**。

### 原因

1. **派单给出的行号指向的是死规则。** `style.css:1379` 块内的 `.sidebar { gap: 14px; padding: 14px 16px; }`、`.navigation { repeat(4, ...) }`、`.main-content { padding: 24px 18px 36px; }` 早已被两处更晚的规则覆盖：
   - `style.css:2139` 块的 `.navigation { repeat(3, ...) }`、`.main-content { padding-inline: 18px; }`；
   - `style.css:4522` 块的整套移动外壳声明（见「现状」第 2 点）。
   只改 1379 块，手机上不会有任何变化。
2. **文件后段还有一层桌面外壳在覆盖。** `style.css:3750` 起「Desktop product shell」以**顶层选择器**重新声明了 `.app-shell { min-height: 100vh }`（3765-3769）、`.sidebar { padding: 22px 14px 18px; gap: 26px }`（3801）、`.navigation`（3832）、`.nav-button { min-height: 44px; padding: 9px 10px; font-size: 13px }`（3836）、`.main-content { padding: 28px clamp(...) 48px }`（3896），另有 `.app-shell { height: 100vh }`（4827-4828）。这些顶层规则**晚于**所有更早的媒体查询块。CSS 同级选择器按源序决定胜负，媒体查询本身不提升优先级——所以手机端规则必须写在 4522 块（位于 3765/3801/3836/3896 之后、4828 之前）才能真正生效。
3. 因此移动端规则必须落在**足够晚**的 680px 块里，且「足够晚」对 `.app-shell` 与其余组件并不是同一条线：
   - `.sidebar` / `.navigation` / `.nav-button` / `.nav-icon` / `.main-content` —— 落在 `style.css:4522` 起的 680px 块（该块在 4630 结束，**晚于** 3765/3801/3832/3836/3896 的全部冲突声明，是唯一同时声明这 5 个选择器的移动块）。
   - `.app-shell` 的高度 —— **不能**落在 4522 块。因为 `.app-shell` 还有一条顶层 `height: 100vh`（4827-4829）排在 4522 块之后，`min-height` 无法压缩显式 `height`（`100vh` + `min-height:100dvh` 的实际高度仍是 `max(100vh, 100dvh) = 100vh`）。所以 R1 补丁另开一个 680px 块（4837-4842）重新声明 `height: 100vh; height: 100dvh;`，见 R1-13。

### 方案

全部改动均在 `@media (max-width: 680px)` 内完成，实际触及 **4 个 680px 块**（此前本文只提到 4522 一块，表述不完整，现更正）：

| 680 块起始行 | 本轮改动 | 是否生效 |
|---|---|---|
| `1379` | `:1390` 的 `.navigation` 列数 `repeat(4)` → `repeat(5)` | **不生效**（死规则，被 2139 块与 4522 块覆盖） |
| `2139` | `:2141` 的 `.navigation` 列数 `repeat(3)` → `repeat(5)` | **不生效**（死规则，被 4522 块覆盖） |
| `4522` | 底部标签栏主体 10 条（`.app-shell` 的 `min-height`、`.sidebar`、`.navigation`、`.nav-button`、`.nav-icon`、`.nav-lock-badge`、`.main-content`、`input/textarea/select`） | 生效 |
| `4837` | R1 补丁：`.app-shell { height: 100vh; height: 100dvh; }` | 生效 |

即：**导航 5 等分在 3 个 680 块里被同步统一为 `repeat(5, ...)`，其中 2 处是不生效的死规则**（保留改动只是为避免同一断点内同时出现 `repeat(3)` / `repeat(4)` / `repeat(5)` 三种互相矛盾的字面量）。

逐条对应派单条目：

1. **安全区前提**：`index.html:5` 加 `viewport-fit=cover`，改为 `content="width=device-width, initial-scale=1, viewport-fit=cover"`。文件其余部分未动。
2. **导航 5 等分**：`.navigation` 改为 `grid-template-columns: repeat(5, minmax(0, 1fr))`，与桌面 DOM 顺序一一对应（内容接入 / 任务 / 知识库 / AI 问答 / 设置）。
   - 生效处：`style.css:4548`。
   - 同时把同断点内另外两处同选择器一起对齐为 5 等分（`style.css:1390`、`style.css:2141`）。这两处是死规则，改它们不改变渲染，只为避免同一断点内出现 `repeat(3)` / `repeat(4)` / `repeat(5)` 三种互相矛盾的字面量。
3. **侧栏改为固定底部标签栏**（`style.css:4532-4541`）：
   ```
   position: fixed;
   z-index: 40;
   right: 0;
   bottom: 0;
   left: 0;
   padding: 4px 4px calc(4px + env(safe-area-inset-bottom));
   ```
   保留该块原有的 `border-right: 0` / `border-bottom: 2px solid var(--desk-line)`（底部边缘，视觉上不可见，未改）。**未重写背景色**：深色背景继续由桌面规则 `style.css:5298`（`background: var(--theme-sidebar)`）提供，白天 `#4e3024`、夜间 `#000000`，主题切换行为不变。
4. **`.brand` 隐藏**：该块原本已有 `.brand { display: none; }`（`style.css:4543`），本轮沿用，未重复定义。
5. **`.nav-button` 竖向标签形态**（`style.css:4551-4560`）：`flex-direction: column; align-items: center; justify-content: center; gap: 2px; min-height: 48px; padding: 6px 2px; font-size: 11px; text-align: center;`。`* { box-sizing: border-box }`（`style.css:7-9`）保证 `min-height: 48px` 即按钮总高，触控目标达标。
6. **图标恢复显示**（`style.css:4562-4564`）：块内原为 `.nav-icon { display: none; }`，改为 `display: grid;`。图标尺寸/描边沿用桌面基规则 `style.css:3871-3879`（22×22、`border: 1px solid currentColor`），未改尺寸。
7. **`.nav-lock-badge` 隐藏**（`style.css:4576-4578`）：新增独立块 `display: none`。HTML 未动，`#nav-ask` 上的 `aria-disabled="true"` 与 `title="即将开放"` 保留，无障碍语义与长按提示仍在。
8. **`.main-content` 让出底栏**（`style.css:4570-4572`）：`padding: 16px 14px calc(64px + env(safe-area-inset-bottom));`。底栏实际高度 = 4 + 48 + 4 + 安全区 = 56px + 安全区，64px 留出 8px 余量。
   - 说明：左右内边距最终由更晚的顶层规则 `style.css:4633-4635` 的 `padding-inline: var(--main-gutter)` 决定（约 22px）。**这是刻意保留**——`#intake-mode-tabs` 用 `margin: -28px calc(var(--main-gutter) * -1)` 与该 gutter 对齐，若强行把 `padding-inline` 改成 14px，内容接入页的页签条会横向溢出。底栏高度靠的是 `padding-bottom`，不受影响。
9. **iOS 聚焦缩放护栏**（`style.css:4579-4585`）：新增独立块 `input, textarea, select { font-size: 16px; }`。已核对全文件：本条规则（`style.css:4584`）之后没有任何规则以元素选择器或 `.field input` 一类高优先级选择器改写这三类控件的 `font-size`，故该规则在本断点内全局生效。
10. **动态视口高度**（补丁后的真实状态）：分两处、缺一不可。
    - `style.css:4528-4529`（4522 块内）：`.app-shell` 补 `min-height: 100vh;` + `min-height: 100dvh;`，给旧浏览器留降级。
    - `style.css:4837-4842`（R1 补丁新增的 680px 块）：`.app-shell { height: 100vh; height: 100dvh; }`。
    - **为什么必须有第二处**：顶层 `.app-shell { height: 100vh }`（4827-4829）源序在 4522 块之后、同特异性。`height` 是显式值，`min-height` 压不动它 —— `height:100vh` + `min-height:100dvh` 的实际高度是 `max(100vh, 100dvh) = 100vh`，所以**补丁前 `100dvh` 从未参与布局**。补丁后 680px 下 `height` 被覆盖为 `100dvh`，iOS 工具栏展开时 `.app-shell` 等于可视高度，底栏与 `padding-bottom` 补偿才真正对齐。桌面（>680px）仍走 4828 的 `height: 100vh`，未改。
    - 未改 `style.css:4828` 那一行本身：QA 已判定改它会牵动 `.settings-view` 的内部滚动上下文，需重跑设置页回归；用后置覆盖可以在不动它的前提下达到同样效果。

改动未触及的任何一类：`app.js`（`git diff` 为空，与 `bfece10` 逐字节一致）、全部 Python 文件、后端接口、桌面端（>680px）CSS。

桌面端零变化的取证方式（可复算）：把 `style.css` 中**所有** `@media (max-width: 680px) { ... }` 块按花括号配对整块剔除，再把注释与空白归一化，然后逐字节比较 —— `bfece10`（父提交）与补丁后的工作副本**完全一致**（`identical outside 680 blocks: true`），对 R1 提交 `2263db9` 与补丁后工作副本做同样比对也是 `true`。即：除 680 断点内的声明外，全文件（含 760/900/1100/620/520/920 等其他断点、全部顶层桌面规则、主题色规则）一个字符都没变。

## 附录 · 派单行号与实测行号的差异（非格式基线节）

派单称「移动断点起始于 `style.css:1379`，其中现有规则包括 `.app-shell{display:block}`、`.sidebar{gap:14px;padding:14px 16px}`、`.navigation{repeat(4)}`、`.nav-button{text-align:center}`、`.main-content{padding:24px 18px 36px}`」——该描述与实际文件内容一致，但**这块不是生效块**。实测：
