## 二、已确认的产品行为与选择前提

| 需求 | 已确认行为 | 成立前提／不得误写为已完成 |
|---|---|---|
| R1 · 设置 | embedding 和回答 LLM 分别选本地／API，可混合；未配置不能开启问答 | 本地与外部各自可探测可用性；选择外部 API 即按设置发送必要文本，无额外确认 |
| R2 · 证据 | 原文、字幕、已保存 OCR 为主要证据；总结作主题辅助；仅摘要来源显式标记 | 不重新识别视频画面；仅摘要不能伪装成原文引用 |
| R3 · 覆盖 | 存量自动补建，新内容入库后增量建立；不完整时只搜索已处理内容并提示 | 索引状态、失败数和覆盖范围可追踪；“默认全库”不得掩盖未处理内容 |
| R4 · 范围 | 默认全库；内容、文件夹、标签可选并有确认按钮 | 选择限制本轮及后续检索；已有回答保持范围快照 |
| R5 · 回答 | 事实与跨内容综合、连续追问；冲突列出处；不足时说明且不越界 | 每轮重新检索；用户资料不能作为系统指令或外部操作 |
| R6 · 引用 | 句／段旁标志，点击标志附近展开全部出处，点击直达 | 引用由程序映射；没有位置时退到详情，不编造时间点 |
| R7 · 对话／反馈 | 本地保存和手动删除对话；每条回答分类纠错 | 不把 14 天索引期限套到对话；反馈可追踪到检索／回答／引用环节 |
| R8–R9 · 向量寿命 | 向量可长期存储；按模型／版本／切片／原文身份匹配复用；停用旧索引 14 天后删 | 活跃索引不删除；内容变化需重算相关片段；切换期间只搜新索引已处理内容 |
| R10–R11 · 本地能力 | 所选模型不可用则暂停；最终离线索引＋检索＋本地 LLM 问答 | 首次允许下载模型；下载后断网可用；首验电脑为当前开发者电脑，不自动切外部 API |

## 四、技术选择表：当前选择、备选、成立前提

| 选择项 | 当前选择与备选 | 选择原因、代价与后续改选条件 |
|---|---|---|
| 文档读取 | 复用归档正文／字幕／OCR／摘要；未来复杂 PDF／Word 再评估 Docling | 当前问答直接使用已保存文字。先盘点原文与位置；解析器只在现有接入缺口真实出现时新增 |
| embedding | 本地 Qwen3-Embedding-0.6B、BGE-M3；可配置外部 API 候选 | 固定中文样本比较证据找回、建索引与提问耗时、内存、成本；模型变化必须隔离索引并回归 |
| 向量库 | **启动阶段选 SQLite**，评估 FTS5／sqlite-vec；Qdrant 为备选 | SQLite 与现有本机数据库一致，减少新增服务和备份链；须固定切片与向量，验证搜索正确性、范围过滤、耗时、恢复、切回及 14 天清理。Qdrant 向量功能更专门，但增加独立服务和跨库同步；若 SQLite 不达冻结门槛，再依据同条件对照改选 |
| 构建方式 | FastAPI＋SQLAlchemy 内直接编排；同后端内引入 LlamaIndex 组件 | FastAPI／SQLAlchemy 保留。固定库和规则，比较节点身份、定位、增量更新、部分索引、版本切换的实现复杂度及回归结果 |
| 检索 | 原文切片的关键词＋向量候选，按排名融合；重排为条件候选 | 首先分测关键词、向量、混合。只有找回了证据却排序失准的样本，才引入重排对照；不以框架默认分数代替真实评测 |
| 回答 | 先复用兼容外部接口；本地运行时与中文 LLM 候选在 M3 测 | 固定证据，分别测试事实、拒答、冲突、引用、速度；本地模型在目标电脑断网实测后定型 |

**对照隔离：**比较数据库时固定分块、embedding、向量、关键词侧与融合算法；专用库的原生混合检索另作增量试验。比较构建方式时固定数据库、模型、切片、提示词和样本。若某候选无法保持功能等价，记录差异而非把指标直接并排。平台性能测试在相同电脑和数据量下重复运行，记录冷／热状态。

## 五、研发评测与变更回归

1. 从现有知识库准备可复核的“问题→正确原文／内容 ID／位置”样本，覆盖事实、名称数字、同义、跨内容、冲突、无答案、限定范围、追问与仅摘要；保留未用于调参的题。样本数按每类失效风险确定，先不把 50–100 个候选题量写成通过率保证。
2. 分开记录 `Recall@5/10`、正确证据名次、范围越界、回答事实、拒答、引用映射、点开来源、p50／p95 时延、建库时间、内存、磁盘和费用。每个失败题归因于资料缺失、切片、检索、排序、生成或引用。
3. 已接受的质量试点门槛和性能试点值按本节用户决策记录执行；当前单次全库建库与 20 条查询只作为性能基线，正式放行需先冻结重复测量次数、资源证据要求和评测题集。门槛未有充分证据时 M2 不标“验证通过”。全库索引未完成时专门核对覆盖提示。
4. 后续换 embedding／切片：重建受影响向量并完整重测找回；换关键词／重排：重测找回与排序；换回答 LLM／prompt：重测事实、拒答和引用；换库／框架：检查等价结果、近邻找回、过滤、性能和恢复。保持一套固定回归集并逐步加入真实失败题。
5. 实施代码时，按 M1→M3 每次提交后记录自动检查和待人工验收。未经实际运行，不把此文档中的验收描述写成“通过”。

### 5.1 评测资料的制作与冻结

1. **盘点真实输入**：在当前知识库抽取不同来源的内容，记录内容 ID、来源类型、正文／字幕／OCR／摘要是否存在、可用位置（段落、页码、时间）和更新时间。只读盘点；不要用总结反推不存在的原文。记录总内容数、可索引数、仅摘要数、无文本数，作为覆盖率分母。
2. **制作题卡**：每题写 `case_id`、题型、问题、允许范围、预期证据内容 ID 与原文位置、可接受答案要点、是否应拒答、冲突来源、归档版本。题型至少覆盖单内容事实、数字／专名、同义问法、跨内容综合、冲突、库内无答案、范围内无答案、追问、仅摘要、部分索引。跨内容题明确所需的每条证据；无答案题也要说明为何无答案。
3. **分组与冻结**：题卡分为开发调参集和封存回归集，同源内容的近似问法不得跨组泄漏。先由人核对金标准；有争议的题移出计分集并记录原因。保存题集版本、内容快照／哈希、切片规则版本、模型与参数、运行环境。真实失败题以后追加为新版本，不改写旧版本的期望结果。
4. **样本不足时**：记录缺少的题型和原因，补采真实内容后再评分；不得把缺失类别当成零失败或宣称整体达标。不得把题卡通过率推断为所有用户问题的准确率。

### 5.2 分层验证方法

| 层次 | 固定输入与动作 | 记录的证据 | 失败定位 |
|---|---|---|---|
| 内容到切片 | 用同一归档快照运行提取、切片、增量更新与删除；抽查切片能回到真实原文 | 内容／切片 ID、哈希、来源类型、位置、覆盖与失败计数 | 原文缺失、解析、位置、切片或同步 |
| 召回 | 对题卡分别运行关键词、向量、混合检索；限定题先应用范围过滤 | 正确证据是否入 top-5／top-10、首个正确名次、各路候选、越界数；跨内容题记录必需证据是否全部找回 | 召回缺失与融合排序分开；不能用回答质量掩盖召回失败 |
| 重排（条件执行） | 仅对“候选含正确证据但前列不足”的题，固定召回候选比较有／无重排 | 正确证据名次变化、漏失、延迟、资源 | 重排确有净收益才保留 |
| 固定证据回答 | 绕过检索，给回答模型相同金标准证据；运行事实、综合、冲突、拒答题 | 答案要点、无依据断言、冲突呈现、拒答、引用标记、耗时 | 生成／提示词问题，与检索问题隔离 |
| 端到端 | 从提问到范围过滤、检索、生成、引用展开／跳转；追问再检索 | 题卡逐题通过／失败、真实引用 ID 与位置、范围快照、用户可见状态、p50／p95 | 按资料、切片、检索、排序、生成、引用或交互归因 |
| 状态与恢复 | 模拟处理中、失败、重试、切换、切回、过期、断网、重启 | 索引状态迁移、已处理范围、旧向量复用数、删除对象、无隐式回退 | 状态机、持久化、任务恢复或 UI 提示 |

`Recall@k` 的分母是有可核对证据的题；“全部证据找回率”另统计跨内容题，不把单条命中当作综合题成功。无答案、仅摘要和范围内无答案题分别统计拒答／标记正确率。引用正确率逐条核对真实内容与位置；无位置只能跳详情。运行记录同时保留原始逐题结果与汇总，不只留平均分。

### 5.3 技术候选的对照路径

| 决策 | 先固定什么 | 只改变什么 | 定案材料与前提 |
|---|---|---|---|
| 文档读取补充 | 当前已保存的文字及来源位置 | 对确有读取缺口的格式增加解析器 | 缺口样本、抽取完整度和真实定位改善；没有缺口则沿用现有归档，不新建解析链 |
| embedding | 题卡、切片、检索器、top-k、目标电脑 | embedding 模型及其必要规范化参数；不同维度各建独立索引 | 各题型召回、索引耗时、问题向量时延、内存、磁盘、API 费用；须满足本地最终必达项 |
| 数据库 | 相同切片、同一批已生成向量、过滤条件、融合算法 | SQLite＋FTS5／sqlite-vec 或 Qdrant 的存取适配 | 结果等价性、范围过滤、建库／查询、恢复、备份、清理、部署复杂度；若效果不同先定位实现差异 |
| 框架 | 已选数据库、模型、切片、问答规则、题卡 | 直接编排或 LlamaIndex 组件 | 比较可定位引用、增量／删除、部分索引、切回、可调试性和维护量；不得让组件默认行为改变产品契约 |
| 检索融合 | 同一索引、题卡与范围 | 关键词、向量、融合及可选重排 | 逐题召回与排序、额外时延；范围越界为否决项；重排只为有证据的排序问题引入 |
| 回答模型 | 同一检索证据与提示词约束 | 外部或本地回答模型 | 固定证据回答和端到端结果分开；本地候选还须在目标电脑断网测质量与资源 |

每轮对照先跑小样本排除接口不通，再在封存题集上运行；记录版本、配置、数据规模、冷／热启动、重复次数与异常。选择结果写为“候选—数据—取舍—未覆盖风险”，不凭单项最高分决定。若无候选达到冻结门槛，回到失败归因修正切片／检索或扩大候选，再复测；不得通过降低原定门槛或缩小题型范围宣称通过。

### 5.4 放行门槛如何确定

M1 首轮基线只用于暴露问题，不追认通过。质量门槛及性能试点值（当前电脑、33 份／8,300 片段快照：热态全库融合检索 p95 ≤5 s、建库 ≤30 min、完整进程树 RSS 峰值 ≤4.5 GiB）已由用户接受；20 条热态查询和单次全库续建仅是基线。已完成的 33/33 run 从 752 个既有向量点续建，1,426.625 秒包含本轮冷 worker 启动，但不是空向量库全新建库时间，不能据此判定 ≤30 min 建库门槛。正式性能放行所需重复测量次数、资源证据要求、题集版本／快照和环境仍待冻结。**已接受门槛不代表 M1 已通过；执行者不得自定新增数值。**

先于数值门槛的硬性不变量：检索不得越出已确认范围；回答不得引用不存在或未处理的内容；引用位置不得伪造；模型不可用不得隐式切 API／关键词单路；活跃索引不得按 14 天过期删除；切回不得混用不匹配向量。任一不变量失败即不能放行对应阶段。固定题集达标仍需下表中的人工验收，不能以自动评分代替。

#### 已接受的质量与性能试点门槛

以下质量与性能试点值已由用户接受，不代表统计置信度或正式性能放行，也不授权 M2。用户选择亲自审核现有 12 张题卡，但尚未提交逐题审核结果；它们仍是草稿，不能计入人工金标准。正式性能放行前仍须冻结重复测量次数、资源证据要求和题集版本。

| 项目 | 已接受的试点值 | 解释与限制 |
|---|---:|---|
| 人工审核固定题集 | 至少 60 题；上文 10 类每类至少 5 题，允许一题覆盖多类 | 题卡需人工确认问题自然、答案要点与全部证据；另留封存回归题，避免调参泄漏。数量是试点规模，不代表统计置信度 |
| 可回答题召回 | 总体 `Recall@5 ≥ 90%`；每个关键题型 `Recall@5 ≥ 80%` | 分母只含有人工核实证据的题；跨内容题还需单独报告全部必需证据找回率 |
| 跨内容完整证据 | `Recall@10 ≥ 85%` 的题级全部证据找回率 | 只有找到所有题卡指定证据才记成功，不能用单条命中代替综合题成功 |
| 无答案／范围内无答案 | 两类分别至少 `90%` 正确拒答或说明不足 | 题卡须证明该范围内无可回答证据；未审核题不得计分 |
| 硬性不变量 | 固定用例中越界结果、虚构引用、伪造时间均为 `0` | 任何一例即阻止对应候选放行；人工抽查仍需通过 |
| 热态全库融合检索与建库 | 当前电脑、33 份／8,300 片段快照：融合检索 p95 ≤5 s；建库 ≤30 min | 用户已接受性能试点值；20 条热态查询与单次全库建库只作基线，正式性能放行前冻结重复测量次数和评测题集 |
| 内存／磁盘资源上限 | 当前电脑、33 份／8,300 片段快照：完整 embedding worker 进程树 RSS 峰值 ≤4.5 GiB；磁盘上限未定 | 用户已接受 RSS 试点值；c 轮单次完整生命周期采样峰值为 3,580,018,688 B（约 3.33 GiB），距上限约 1.17 GiB；仍须按正式重复规程核验，不以系统可用内存代替进程树峰值 |

**冻结状态：**质量试点门槛与热态全库融合检索 p95 ≤5 s、建库 ≤30 min、完整进程树 RSS 峰值 ≤4.5 GiB 的性能试点值均已由用户接受。正式性能放行所需重复测量次数、资源证据要求和评测题集版本仍待冻结；磁盘上限未决定。M1 质量尚未通过，M2 不启动。

### 5.5 关键场景的可执行验收

| ID／类别 | Given／When／Then：可观察结果 | 验证路径 |
|---|---|---|
| V1 · 首建与增量（R2–R3） | 已有可索引归档且选择 embedding；首次启动索引、随后新增／修改／软删除／恢复内容；覆盖计数与真实成功数一致，修改片段更新、删除内容不再返回；恢复时按当前内容哈希重建或复用匹配切片，恢复后重新可检索，原归档文字不被改写 | 自动：用固定小库比对索引前后 ID／哈希、删除与恢复后的命中和覆盖计数；人工：查看进度与新内容可问答 |
| V2 · 部分索引（R3–R4） | 索引只完成一部分时提问；仅已完成且在确认范围内的内容参与，界面明确“仅搜索已处理内容”及覆盖进度；失败项不计覆盖 | 自动：暂停任务后检查返回 ID 集合；人工：查看提示与结果 |
| V3 · 范围（R4–R5） | 选择内容／文件夹／标签并按确认按钮；后续问题只搜范围内；范围内无证据时说明不足；更换范围后旧回答及其引用不变 | 自动：同题在不同范围比较命中集合和历史快照；人工：检查选择区、确认与历史 |
| V4 · 回答（R5） | 对事实、跨内容、追问、冲突、无答案题提问；每轮重新检索；冲突分别列出来源，无答案不编造，结论可对应证据 | 自动：题卡逐题判定并保存证据；人工：阅读代表题回答 |
| V5 · 引用（R2、R6） | 回答有单条或多条出处；点击句／段旁标志，就地展开该处全部真实来源；点来源直达可用位置；仅摘要标明“依据摘要”；无位置退到详情 | 自动：引用 ID、位置与原文映射；浏览器：展开、收起、跳转、摘要标记 |
| V6 · 对话与反馈（R7） | 保存对话后重启并继续；手动删除后不再出现；标错可选三类；删除会话不删除知识库或索引 | 自动：保存／重启／删除与数据隔离；浏览器：列表与反馈流程 |
| V7 · 切换与期限（R8–R9） | 从 A 切 B；旧 A 保留 14 天，新 B 只搜已处理内容；期限内切回 A 仅复用身份及原文哈希匹配的向量；过期清理只删停用索引，活跃索引仍在 | 自动：可控时钟覆盖到期前／到期／切回／原文变化；人工：观察覆盖提示 |
| V8 · 模型失败与离线（R1、R10–R11） | 未配置、选定模型不可用、断网三种状态分别测试；显示可操作原因且不隐式切换；在目标电脑先下载模型再断网，仍能新增内容索引、提问、生成和引用 | 自动：配置／故障注入与请求行为；实机：断网完整路径、资源记录 |

异常优先级按后果划分：**必测**为错误引用、范围越界、模型混用、删除后仍返回、活跃索引误删及隐式外发；**应测**为任务中断恢复、重复入库、内容更新与索引同时发生、API 超时、模型启动失败；其余低概率且可恢复问题按实际证据补测。失败时保留原文和历史对话，记录失败内容与重试入口；不得把失败内容计作已覆盖。AI 需对照 V1–V8 填写实际证据，不能仅因测试脚本存在而标通过。

### 5.7 AI 执行者的规划与实施路径

1. **只读准备**：按 [AI 代码执行标准化方案](../../基线/规则/AI代码执行标准化方案.md) 核对当前分支／未提交改动、四张基础思维导图、有效方案、归档模型、内容保存／删除事件、设置接口和 UI。盘点现有可复用字段与缺口，标注“代码事实／已确认产品要求／待测候选／待用户决定”。保护工作树中的他人改动。
2. **先列追踪表**：以 R1–R11、V1–V8 映射本轮实施范围、具体代码入口、数据变更、依赖、验证动作、预期结果与人工验收。把 M1、M2、M3 拆成可独立验证的提交，不把尚未建设的阶段标为延期完成。
3. **M1 顺序**：资料盘点与题卡 → 稳定切片／来源映射 → 索引身份与状态、存量回填、增删改及软删除后恢复 → 检索单路与融合对照 → 候选决策与门槛冻结。恢复内容按当前原文哈希重建或复用身份匹配的切片，并恢复覆盖计数；索引数据结构变更前写最小迁移、旧数据处理和回滚办法；每步通过对应 V 项再进入依赖步骤。
4. **M2 顺序**：设置与可用性门槛 → 问答 API／范围过滤／每轮检索 → 回答约束、冲突与拒答 → 就地引用／直达 → 会话与反馈 → 端到端题卡和浏览器路径。验证前后端契约和实际运行版本；关键 UI 路径需实际浏览器证据。
5. **M3 顺序**：本地模型安装／配置 → 四种 embedding×回答组合 → 切换／切回与 14 天清理 → 故障状态 → 断网完整链 → 全部受影响项回归。所选模型不可用时暂停问答，不能暗中使用旧索引或云 API。
6. **失败与交还**：可查证的接口、数据、性能问题先诊断并在授权范围内修复复测；关键产品决策冲突或所有候选不达门槛时，只暂停受影响工作，附逐题证据和明确选项请用户决定。每轮在本文件进度表记录自动结果；人工项始终留“待人工验收，用户填 1/0”，得到用户确认后才改状态。

**实施产物最小集：**更新本方案的追踪与选择结论、可复跑的题卡与脱敏逐题结果、必要代码／数据库迁移、针对实际风险的自动检查、浏览器或目标电脑验收记录。题卡和运行证据的具体路径由实施时按项目现有目录确定，不新增平行的状态源。外部 API 凭据不写入题卡、日志或提交。
