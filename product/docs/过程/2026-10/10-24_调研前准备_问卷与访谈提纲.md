## 修订说明：为什么取消题目数量上限

上一版按外部技能规则把题目砍到 12 道。用户 2026-10-25 裁决：**先广纳问题，最后再裁决**。取消上限的理由与保留的规则如下：

| 项目 | 处置 | 理由 |
|---|---|---|
| "每题 ≤12 / ≤15"硬上限 | **取消** | 上限是为"一次投放、一份问卷"设计的。本阶段是题库制：先写全，再按决定裁。上限只是投放版的约束，不是题库的约束 |
| "每题标注服务目标" | **保留** | 没有目标的题裁不掉，也没法判断该不该投 |
| "行为题在态度题之前" | **保留** | 态度题会污染后面的行为回忆 |
| "不问想要什么功能" | **保留** | 见第七节，这条不是上限而是方法 |
| "甄别在前、开放题靠后" | **保留** | 顺序错了会让不合格样本污染整卷 |
| "Likert / NPS 量表" | **仍不采纳** | 本阶段判定全是粗比例阈值，不是均值。量表会让数据显得比实际更精确 |

一句话：**题库可以长，投放版不能长。**长的是题库，短的是每一次发出去的东西。

## 方法来源

先读了三份现成的问卷技能，采纳其硬规则，不采纳与本阶段无关的部分：

| 来源 | 采纳 | 不采纳 |
|---|---|---|
| `alaimo-labs/ai-first-skills` · `design-survey` | 每题标注服务的目标；甄别在前；开放题靠后；**结尾招募区块**（问卷同时是访谈招募工具）；**分布表进问卷**（渠道、偏差、触达量、独立链接、目标 n）；触达量填 `unknown` 不编数字；投放前先算渠道能否凑够 n | 12 题上限（理由见上） |
| `gtmagents/gtm-agents` · `survey-design` | 目标单一；配额与甄别；**验证题**；跳过逻辑；QA 清单（手机一屏、选项随机、匿名、导出）；单次 <10 分钟 | 激励方案、跨语言 QA（本阶段不需要） |
| `Owl-Listener/designer-skills` · `survey-design` | 导语写目的/时长/匿名、不预设答案；**行为题在态度题之前**；禁止引导性、双重问题、负载词、超长回溯期、行话；选项互斥且穷尽 | Likert/NPS/SUS 量表（理由见第二节） |

- 一句话结论：**问卷只能确认比例，不能发现问题。**"为什么"只能来自访谈。

## 一、调研要回答的六个决定

没有决定就没有问题。以下任一未定，后面的题都白问：

1. **做给谁**：三类障碍人群先服务哪一类。
2. **先做哪个形态**：独立软件 / 插件 / 托管。
3. **能不能收钱**：收多少、怎么收。
4. **交付门槛能不能过**：装环境、填 Key、交登录态，哪条是硬墙。
5. **值不值得继续**：如果明天消失，用户会不会损失什么。
6. **平台是否已经替我们做了**：B站笔记、小红书收藏夹、抖音收藏，用户是否已在用且觉得够用。新增项，见 §3.3 与 PRD v8.2。

> 第 6 条是本轮新增的决定，也是最容易推翻前五条的一条。它一旦成立，前面所有"愿不愿意装"的讨论都失去意义——因为需求本身已经有免费替代。

## 二、问卷能问什么，不能问什么

- **能**：比例、频率、已发生的行为、选择偏好（二选一或多选一）。
- **不能**：为什么、会不会用、想要什么功能、愿付价格的心理值。
- **为什么不用量表**：本阶段的判定都是粗比例阈值（>50%、<20%、>40%），不是均值。Likert 适合测满意度与态度变化，本阶段没有这类指标；加了只会让数据显得更精确。
- **假设题只能看方向**：P1 是二选一，不是收入预测。
- **关于手机端这类问题**：见第七节。问"你愿意为手机端单独使用吗"是废题，因为它同时踩了三个坑——问意愿、问不存在的东西、双重问题（手机端 / 单独 / 使用）。正确的问法是问**已经发生的跨端行为**。

## 三、样本量与可行性算术

| 有效份数 | 抽样误差（95%，p=0.5） | 能做什么 |
|---|---|---|
| 50 | ±14pp | 只能看极端倾向，判不了阈值 |
| 100 | ±10pp | 勉强判 >50% / <20% |
| **200** | **±7pp** | **达标线**：四条判定线都够用 |
| 300 | ±6pp | 上限；再做细分交叉仍不稳 |

- **300 份不等于 300 人看到。** 社群分享的回复率经验值 5%～15%（经验值，非本文实测）；按 10% 且扣 15% 无效卷，200 有效需触达约 **2350 人**。
- **投放前先算这一步。** 若各渠道合计触达不足 800 人，预计有效卷 <70 份，判不了任何阈值——此时不要发，改扩渠道，或直接做 15 人访谈。
- 目标定 **200 有效**，300 为上限；力气花在渠道数与分层上，不花在凑份数上。
- **付费样本单独计**：付费来的份数不进这 200 份的主样本，单独出一份对照。理由见第五节的偏差说明。

### 4.2 付费渠道（新）

用户 2026-10-25 提出"问题的询问也可以通过付费方式"。可行，但必须先说清它的**性质变化**：

> 付费带来的不是"更好的样本"，而是**另一类样本**：为报酬答题的人，不代表会为产品付钱的人。付费渠道的价值在于**补齐你自己触达不到的人群**（比如不用 B站的、不用小红书的、三四十岁的职场人），不在于提高代表性。

| 类型 | 具体可选 | 计价单位 | 能补什么 | 主要偏差 |
|---|---|---|---|---|
| 在线样本面板 | 问卷星样本服务、腾讯问卷样本、Credamo 见数、Prolific、SurveyMonkey Audience | 按份计费 | 快速凑份数、可设配额（年龄／职业／城市） | **职业答题者**：答得快、答得浅、为通过甄别而编答案 |
| 付费受访者招募 | User Interviews、Respondent（境外为主） | 按人计费（含受访者酬劳） | 能约到具体画像的人，做 30～60 分钟访谈 | 单价高；中国区供给稀 |
| 付费内容分发 | 小红书／B站 KOC 代发、社群群主投放 | 按条或按群 | 拿到真实受众的答案，不是面板职业答题者 | 受众由 KOC 决定，你控制不了配额 |
| 付费深度访谈（本人渠道内） | 从问卷 opt-in 里约，给答谢 | 按人 | 转化率最高：人已经被筛过一遍 | 样本仍限于你自己的受众圈层 |

- **单价不预设**：上述平台报价随地区、配额、样本稀有度变化，本文不给数字，投放时按当期报价回填。给一个占位列：`单价____ / 预计份数____ / 小计____`。
- **付费样本必须加防敷衍机制**：① 甄别题里放一道只有真用户答得出的题（如"你上一次打开收藏夹是哪天"）；② 保留验证题；③ 答题时长 <90 秒的整份剔除；④ 开放题答案长度 <10 字的不计入分析。
- **不要用付费样本回答"愿不愿付费"**：他们为钱而来，对价格的敏感度和真实用户不同。这类题只在自有渠道和访谈里看。
- 建议预算优先级：**付费深度访谈（10 人）> 付费社群投放（补人群）> 样本面板（只用来凑分母）**。前两项能拿到"为什么"，第三项只拿到"多少"。

- 每渠道单独链接或加渠道参数，否则事后无法分渠道看偏差。
- 只用自己的一个渠道，会系统性高估"愿意用"的比例——至少再加一个触及不到你现有受众的渠道。
- 触达量填 `unknown` 是允许的，编一个数字才是错的。

## 五、题库的三层与裁决规则

用户要"广纳问题最后裁决"。落地形态是三层：

| 层 | 内容 | 用途 |
|---|---|---|
| **L1 投放版**（14 题 + 开放题 + 招募） | 只放"服务六个决定中至少一个、且必须有比例数据"的题 | 社群投放，主样本 200 份 |
| **L2 扩展题库**（约 60 题，按主题分组） | 服务同一批决定，但不需要比例、或只对部分人成立 | 深度版问卷（付费受访者，25 题）、访谈前预填、访谈追问清单 |
| **L3 备选池**（争议题） | 方法上有争议（假设题、价格题、量表题），先留着不投 | 等 S2 有真产品后再启用 |

### 裁决规则（把 L2 裁成 L1 时用）

每题按三个维度打分，**任一维度为 0 就裁掉**：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| **服务哪个决定** | 说不出服务六个决定中的哪一个 | 间接相关 | 直接对应某条判定线 |
| **证据强度** | 只能得到意愿／想象 | 得到取舍偏好 | 得到已发生的行为或已花的钱 |
| **投放成本** | 需要解释、需要产品截图、触碰隐私 | 普通多选题 | 单选、一眼能答 |

- 裁完如果 L1 超过 15 题，按"服务决定的分数"从低到高删。**15 不是规则，是经验**：社群投放超过 15 题后完成率明显下滑（经验值，未实测）。
- 被裁掉的题不删，移到 L2，由访谈和深度版承接。**题库只增不删，投放版每次重裁。**

### 三个投放版本

| 版本 | 题量 | 投给谁 | 目的 |
|---|---|---|---|
| **α 社群版** | L1，14 题 | 自有渠道 + 付费社群 | 主样本，出比例 |
| **β 深度版** | L2 里选 25 题 | 付费受访者、opt-in 且愿填长卷的人 | 补交叉分析（付费人群 × 不敢交登录态 这类组合） |
| **γ 预填版** | 10 题 | 已约好的访谈对象，访谈前 3 天发 | 让访谈时间花在"为什么"上，不花在收集事实 |

## 六、L1 投放版正文（社群版）

> 以下 `> 目标` 为内部注释，粘贴进问卷工具时删掉。

**导语**

> 我们在了解大家怎么管理从 B站、小红书、抖音、知乎上收藏的内容。14 道题，约 5 分钟，匿名，不收集账号信息。没有标准答案，请按最近实际发生的情况回答，不用考虑"应该怎样"。

### 甄别区

**S1** 最近半年，你常用哪些平台收藏内容？（多选）
B站 / 小红书 / 抖音 / 知乎 / 微信公众号 / 浏览器书签或稍后读 / 其他 / 都不用（→ 结束问卷）

> 目标：决定 2（做给谁）。分层用，判断取数覆盖面。

**S2** 这些平台上的收藏和点赞，加起来大概多少条？
不到 100 / 100–500 / 500–2000 / 2000 以上 / 说不清

> 目标：决定 5（值不值得继续）。验证"囤积"是否真实存在，对应总 PRD §2.1 第三类人群。

**S3** 过去 12 个月，你有没有为"收藏、笔记、稍后读、知识管理"这类工具花过钱？
有，年费约 ___ 元 / 有，一次性买断约 ___ 元 / 没有

> 目标：决定 3（能不能收钱）。**最关键的一题**。付费行为比痛点可信，决定样本是否合格。
> 追问项（L2）：花了钱的那几个，现在还在用吗？——测"付过费但流失"，比"付过费"更强。

### 事实回溯区（问上次，不问"会不会"）

**Q1** 上周，有没有出现过"想找以前存过的东西，但想不起来在哪个平台或什么标题"？
0 次（→ 跳到 Q5）/ 1–2 次 / 3 次以上

> 目标：决定 5。痛点频率。选 0 次的人跳过 Q2、Q3、Q4。

**Q2** 最近那一次，最后怎么解决的？
一次就找到了，1 分钟内 / 找了几处才找到，5 分钟内 / 找了很久（5 分钟以上）才找到 / 没找到，放弃了

> 目标：决定 5。把"结果 + 耗时"合成一个成本构念，对应总 PRD §4.2 隔日找回率。

**Q3** 那次你主要靠什么找？
平台内搜索 / 浏览器搜索 / 翻收藏夹或历史记录 / 问人 / 问 AI / 干脆换了份新资料

> 目标：决定 2、5。现在的替代动作，决定"找回"要和谁竞争。

**Q4** 找到之后你做了什么？（多选）
看了一眼 / 复制了其中一段 / 贴到自己的文档或笔记里 / 发给别人 / 又存了一次

> 目标：决定 6。**新增题**。如果多数人止步于"看了一眼"，那这个产品的价值就不是"归档"，而是"让人愿意打开看"——这会推翻归档优先的方案。

**验证**：Q1 选"0 次"但 Q2、Q3、Q4 有答案 → 该份标记不可信，剔除。

**Q5** 一条 30 分钟以上的视频，你通常怎么处理？
先完整看完 / 先看几分钟再决定 / 先找文字版或目录 / 直接跳过 / 先收藏，以后再说

> 目标：决定 5。验证"先理解再精读"这个核心假设（总 PRD §2.2 场景一）。

### 平台原生能力区（新增，直接服务决定 6）

**N1** 你知不知道 B站有「视频笔记」功能——可以在播放器里记笔记、绑定时间点、点一下跳回那段？
知道，用过 / 知道，但没试过 / 不知道

> 目标：决定 6。**先测认知，再测使用**。不知道的人不是"不需要"，是"没被平台告知"。

**N2**（N1 选"知道，但没试过"或"不知道"时问）如果知道有，你会用它吗？
会 / 看视频类型 / 不会

> 目标：决定 6。**这是全卷唯一保留的假设题**，因为它是"已知功能的态度"，不是"不存在的功能"。

**N3**（N1 选"知道，用过"时问）你现在还用吗？
一直在用 / 偶尔用 / 用过几次就不用了

> 目标：决定 6。**弃用率比使用率更有信息**：用过就不用了，说明功能存在但没解决真问题。

**N4** 你有没有想过把自己在某个平台上的笔记或收藏导出来？
想过，也做过 / 想过，不知道怎么弄 / 没想过

> 目标：决定 6。B站笔记**不支持原生导出**，这是平台留下的唯一缺口。若"想过也做过"的比例高，导出就是真需求；若集中在"没想过"，说明导出是伪需求。

### 跨端区（替换"愿不愿用手机版"）

**M1** 你最近一次在手机上看到值得存的内容，后来在电脑上找过它吗？
找过，找到了 / 找过，没找到 / 没找过 / 我基本不在手机上存东西

> 目标：决定 2。**这是跨端问题的行为版。**不问"要不要手机版"，问跨端是否真发生过断裂。

**M2** 你手机上现在装了哪些用来"稍后读 / 笔记 / 收藏"的 App？（多选 + 其他）
Cubox / 微信收藏 / 小红书收藏 / Notion 或 Obsidian / 系统备忘录 / 浏览器稍后读 / 没装 / 其他

> 目标：决定 2、3。装了什么、用不用，比"愿不愿意装新的"可信。

### 交付容忍度区

**D1** 如果安装要 10 分钟、下载约 2GB 组件，你会？
装 / 犹豫一下，但会试 / 放弃 / 我基本不装这类工具

> 目标：决定 4。装机门槛。判定线 >40% 选"放弃"→ 独立软件降为后置。

**D2** 如果要你自己去某个网站注册，再复制一串 Key 粘进来，你会？
自己就能搞定 / 要人一步步带着做 / 放弃

> 目标：决定 4。BYOK 门槛。决定 S0–S2 是否只能做纯 BYOK。

**D3** 如果软件要读你的平台收藏，需要把该平台的登录状态交给它，你会？
可以接受 / 看是哪个平台 / 不能接受 / 我不需要这个功能

> 目标：决定 2、4。**分发形态的分水岭**。>50% 选"不能接受"→ 放弃托管。

**D4** 你更希望它是？
独立软件 / 现有工具的插件（如 Obsidian、浏览器插件）/ 网页，不想装东西 / 都行，能解决问题就行

> 目标：决定 2。入口形态偏好。选项顺序随机。

### 付费区

**P1** 假设只能二选一，你选哪个？（A/B 顺序随机）

## 八、访谈提纲（40 分钟，10 人）

**从问卷的 opt-in 池里选人**，不再另外找。开场先说："我不是来验证我的想法的，我是来听你实际怎么做的。"

### 第一段 · 一次真实的找回（12 分钟）

让他当场打开手机或电脑演示，不要只听描述。

1. 上一次想找的是什么？现在能找给我看吗？
2. 你记得的是标题、平台，还是那句话本身？
3. 翻了几个地方？中间有没有想放弃的时候？
4. 找到之后你做了什么——只是看，还是复制、贴到别处？
5. 那一次花了多久？如果它没找到，会怎样？

### 第二段 · 一次"存了没用"（10 分钟）

1. 打开收藏夹，挑一条三个月前的，你还会打开它吗？
2. 当时为什么存？现在还记得当时的用途吗？
3. 如果这条今天消失，你会损失什么？
4. 你的收藏里，大概多少是"存的时候有用、后来没用过"的？

### 第三段 · 平台已经做了什么（8 分钟，本轮新增）

1. 你知道 B站有视频笔记吗？（不知道就现场演示一遍）看完你觉得它能解决你的问题吗？
2. 你用它记过什么？后来回去看过吗？
3. 为什么不用它——是不知道、不好用，还是不需要？
4. 你有没有把平台上的东西导出来过？怎么导的？导出来放哪了？
5. 如果 B站笔记能导出，你还需要别的工具吗？

> 这一段是全套访谈里最可能"一票否决"的部分。如果 6/10 的人说"平台自带的够了"，产品就得改定位，不是改功能。

### 第四段 · 跨端与入口（5 分钟）

1. 你手机上存的东西，后来在电脑上找过吗？找到了吗？
2. 如果这个东西只能在电脑上用，你还会用吗？
3. 你希望它出现在哪——浏览器里、微信里、还是一个单独的窗口？

### 第五段 · 顾虑与边界（5 分钟）

1. 让陌生软件代你读收藏，你最担心什么？账号安全、隐私，还是别的？
2. 内容涉及工作或私事时，你还会让 AI 处理吗？什么情况下不会？
3. **如果只能留三个功能，你留哪三个？**（先让他自己说，再给列表让他删到三个）
4. 如果它只能做一件事，你希望是哪件？为什么？

> 第 3 题是强制取舍：只问"要不要"，答案全是"都要"；让他删才是真答案。

### 收尾（可留）

- 你身边有谁也在为这件事烦？能不能介绍一位？（滚雪球）
- 如果我做出第一版，你愿意试用两周吗？

## 九、发布前的问卷分享（pre-launch）

用户 2026-10-25 提出"其他网上类似的、在产品发布前的问卷分享"。这里给一套可执行的，依据见下。

| 做法 | 具体 | 产出什么 |
|---|---|---|
| **概念页 + 问卷**（smoke test） | 一页说明"它做什么 + 一张示意图"，下面接 8 题问卷（J1–J7） | 是否看懂、谁会要、邮箱捕获率 |
| **Waitlist** | 同一页收邮箱，写明"上线才通知，不发广告" | 唯一"有成本"的意向信号 |
| **预售 / 早鸟价** | S2 阶段才做。先收钱后交付，退款条款写清 | 唯一真实的付费信号 |
| **公开渠道预热** | Product Hunt、BetaList、Indie Hackers、V2EX、即刻、少数派 | 陌生人样本，非朋友 |
| **付费分发** | 小红书/B站 KOC、社群群主 | 见 §4.2 的偏差说明 |

**外部资料的三个阈值（来自 zigpoll 的验证指南，2026-10-25 查）**：

| 指标 | 弱 | 强 |
|---|---|---|
| 顶格意向（10 分制只计 9–10） | < 20% | > 35% |
| 邮箱捕获率 | < 10% | > 25% |
| 开放题里的反对理由 | 空泛（"不适合我"） | 具体且可改（"我不想交登录态"） |

- **这三条与第六节的判定线不冲突，用途不同**：判定线判"要不要继续"，这三条判"这一版概念页行不行"。
- **邮箱捕获率是本阶段最该看的数**：说"会用"是免费的，留邮箱不是。
- 一条纪律：**概念页不放产品截图，只放示意图**。放真实界面会让回答变成对设计的评价，而不是对需求的判断。

## 十、证伪题与判定线

**证伪题（访谈第五段必问）**：如果这个工具明天消失，你会损失什么？

- 答得出具体损失（某份资料、某个结论、某次引用）→ 真需求。
- 只答"挺可惜的""应该有点不方便"→ 不是用户。

**判定线**：与方案 R4 触发器一致，投放前写死，事后不许改。

| 观察 | 判定 | 动作 |
|---|---|---|
| D3"不能接受" > 50% | 登录态是硬墙 | 放弃托管，走开源 + 宿主入口 |
| P1 选 B（98 元/年）< 20% | 付费意愿不足 | 不做订阅，走开源 + 赞助或买断 |
| D1"放弃" > 40% | 装机是硬墙 | 优先做插件/网页入口，独立软件后置 |
| S3"没有付费" > 85% | 样本不合格 | 补招，不急着分析 |
| 访谈"明天消失"答不出具体损失 > 6/10 | 需求不成立 | 停在模板，不投产品 |
| **N3"用过几次就不用了" > 50%（在用过的人里）** | 平台原生功能不好用 | 这是机会，不是威胁：说明平台做了但没做透 |
| **N1"不知道" + N2"不会"合计 > 60%** | 平台原生已够用 | 收缩到"跨平台 + 导出"，不再做单平台笔记 |
| **N4"想过也做过" > 30%** | 导出是硬需求 | 导出升为一级能力，不做也要给 |
| **M1"找过没找到" > 40%** | 跨端断裂真实存在 | 手机端从"要不要"变成"必须"；先做 PWA 或分享入口 |
| **J7 邮箱捕获率 < 10%**（概念页） | 概念页没说服力 | 改写概念页，不是改产品 |

## 十一、QA 与预测试

**预测试**：先给 20～30 人填（朋友、同事，不计入正式样本）。

1. 单题退出率最高的那道，是题目问题，不是人的问题。
2. 有人问"这题什么意思"的，当场改措辞。
3. 手机上一屏看不完（选项要横向滚动）的题，改成更短的选项。
4. 全程是否 ≤5 分钟。
5. **条件题有没有真的跳对**：N2/N3 只看 N1 的答案；Q1 选 0 次的真跳过 Q2–Q4。

**投放前检查清单**

- 导语写了目的、时长、匿名，且没有预设答案。
- 每题只问一件事；没有"和/及/并且"。
- 选项互斥且穷尽，有"其他/说不清"。
- D4、P1 选项顺序随机。
- S1 选"都不用"、Q1 选"0 次"、N1 的分支在工具里真的生效。
- 每渠道独立链接或渠道参数。
- 导出 CSV，保留时间戳与渠道字段。
- 内部注释（`> 目标`）已从投放版本删除。
- **付费渠道版本另加**：甄别题里放一道只有真用户答得出的题；声明"这份问卷的报酬与你的答案无关，请按实际回答"。

## 十二、投放与回收纪律

1. 题目里不出现产品名、截图、功能演示——避免讨好型回答。
2. 不加"你会用吗""你觉得好不好"这类假设题（N2、J4 是唯一例外，已标弱证据，不单独作为结论）。
3. 每次投放记录渠道、日期、份数；单渠道不超过 40%。
4. **先看 S3 分布再分析主体题**；S3 不达标就不出结论。
5. 结论只写比例与区间，不写因果；因果只能引自访谈原话。
6. 回收后先剔除（验证题矛盾、答题 <60 秒、全选同一项），再算分母。
7. **付费样本与自有渠道样本分开统计**，不要合并成一个分母；两者偏差方向不同，合并会互相掩盖。

## 十三、两用设计：产品要比例，面试要证据

用户 2026-10-25 补充：这个产品的始源目的是面试——先突出产品功能与产品经验，其次才是真正运行。

**这不改变调研要做什么，但改变"什么算做得好"。**

| | 产品视角 | 面试视角 |
|---|---|---|
| 样本量 | 200 份才够判阈值 | 200 和 300 没区别，和 20 有区别 |
| 最值钱的产出 | 比例与区间 | 具体的人、具体的话、具体的取舍 |
| 失败案例 | 要藏起来 | **最值钱的部分** |
| 定价 | 必须验证 | 讲清逻辑比给出数字得分高 |
| 功能清单 | 越准越好 | 越能说明"砍了什么"越好 |
| 分发 | 要传得开 | 能讲清"为什么现在不做分发"就够 |

**三条结论：**

1. **一次调研，两份产出。** 同一批数据，产品侧出比例表，面试侧出"原话摘录 + 决策记录"。不额外做第二次。
2. **付费样本的优先级要下调。** 面试官会问"这些人你从哪找的"。面板上买来的陌生人答不出完整故事，讲不圆。预算优先给"你自己渠道里约到的 10 场深度访谈"——那能产出一句被记住的原话。
3. **必须记录被否决的选项。** 面试里最有说服力的不是"我做了什么"，是"我本来要做 A，因为 X 改成 B"。所以方案文档里每个"待决策"最终都要有裁决记录和理由，不能只留结论。

**面试要采集的三种素材（调研时顺手记，不额外花时间）：**

| 素材 | 什么时候采 | 长什么样 |
|---|---|---|
| 用户原话 | 访谈录音转写里挑 3–5 句 | "我知道它存过，但懒得找，直接重搜了" |
| 一次失败判断 | 每轮调研后写 200 字 | "我以为装机是最大障碍，结果 8 个人里 6 个卡在'交登录态'" |
| 一个被砍掉的功能 | 每次取舍后写一句 | "砍掉了公开笔记，因为那是复刻平台" |

**一条纪律**：PRD 里不写"本产品用于面试"。PRD 是产品文档，写动机会让它失去专业性；动机记在方案文档的"产品问题 8"里，两份文件不混。

**顺带修正一处此前的建议**：如果首要目的是面试，"几百份问卷"的边际价值低于"十场能复述的访谈"。两百份证明"不是拍脑袋"，十场提供"能讲的故事"——两者都要，但先做后者，前者用来托底。
