**用户原话区（逐字，不许改写）**

- U-01-2 · 纠正「顶端」为「前端」

  > 1.第一张图对齐指的是这里的前端对齐，原本前端有一个下拉的符号，我希望把这个符号挪到其他地方然后前端就可以对齐了。而修改之后的查看子级这个界面完全可以不需要啊，因为已经有了一个那个下拉符号来查看子级。@image#1:Clipboard_Screenshot.png

- U-01-3 · 纠正符号落点

  > 嗯，不要第一个不要移到左侧前方，这样的话和阶段那个按钮会弄混，可以把它放在已完成的旁边。然后可以在图片的右上角加一个合集的标识。

- U-01-4 · 局部修改约束

  > 需求：针对上述问题，先不进行代码修改，而进行一轮把修改之后的样子图片展示给我，只对问题地方进行局部修改 @skill:refactoring-ui

**AI 解释区**

「前端对齐」指水平左端对齐，不是垂直顶端对齐。真实原因在 `collectionRowHtml(group)`：父行在复选框之后、封面之前多渲染了一个 24px 的 `.job-expand` 按钮，加上 `.job-card` 的 `gap: 16px`，封面左缘比普通任务行右移约 40px。用户不要新增「查看子级」界面，也不要把符号移到右侧操作列（会与阶段按钮混淆），而是把符号放到「已完成」状态文字旁；另外在封面右上角补一个蓝色「合集」角标来承担父集合的识别职责。

## R1 父集合前端对齐＋合集角标

- 状态：已实施，待人工验收。
- 现状：`app.js` `collectionRowHtml(group)` 的 DOM 顺序为 `复选框 → .job-expand → jobCover() → .job-card__main → .job-card__count`；`.job-expand` 24px + `gap:16px` 使封面右移约 40px。
- 原因：下拉入口被放在封面之前，占了水平首列；用户希望封面左缘与普通任务行一致。
- 方案：把 `.job-expand` 从封面之前移到 `.job-state` 之后（保留 `data-act="job-expand"` 与 `data-group-key`，`onAction` 的 case 零改动）；给 `coverHtml(content, withDuration, cornerText)` 加可选第三参，仅在父集合行输出 `<span class="cover__corner">合集</span>`，其余调用点不传、输出不变；CSS 加 `.cover__corner`（`.cover` 已有 `position: relative`）蓝色胶囊，以及 `.job-card--group .job-expand { display: inline-grid; vertical-align: middle; margin-left: 6px; }` 让符号紧贴「已完成」。
- 验收：[自动] `node --check` 通过；源码文本契约中 `data-act="job-expand"`、`data-group-key`、`已完成 ${group.completed} / ${group.total}` 仍存在；[浏览器] 父集合行封面左缘与普通行对齐、「已完成」旁有下拉、封面右上角有「合集」；点击下拉仍能展开子项；[人工] 符号不与阶段按钮混淆。

## R2 阶段符号化＋排队第X/共Y

- 状态：已实施，待人工验收。
- 现状：`jobRowHtml()` 输出文字按钮「阶段」/「收起阶段」；`jobStagesHtml()` 的 waiting 分支输出 `排队第 ${queued} 位`，且只要展开就会出现，与状态行无关联。
- 原因：文字按钮宽度不固定，行间不对齐；排队缺少「共几个」分母，且用户要求只在按下阶段之后出现。
