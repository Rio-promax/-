## 4. 硬证据（全部可复现）

### 4.1 已解决的真问题 ①：滚动完全不生效

**根因**：旧脚本挑"`scrollHeight` 最大的元素"然后赋值 `scrollTop`，挑中的是 `overflow:visible`
的伪容器 —— **内核对这种元素静默忽略赋值**（不报错、不抛异常，只是纹丝不动）。
证据：旧报告里 `最后一次滚动状态："ok top=0 h=1222 ch=707"`，连续 8 轮 `top` 恒为 0。

**修法**：改用**内核真实滚轮事件**（不再由脚本猜容器）。内核自己做命中测试，沿 hover 链
自己找该滚哪一层，并真实产生 scroll 事件与视口变化，懒加载哨兵才有机会被触发。

**隔离对照实验**（`scroll-probe-spike/`，本地自造长页面，避免拿线上页面当基准）：

| 场景 | CDP 真实滚轮 6×420px | JS 赋值 `scrollTop` |
|---|---|---|
| 文档级长页 | 0 → **2520** | 2520 → 5040 |
| 内部 `overflow:auto` 容器 | 0 → **2520**（滚轮**自动命中**了内部容器） | 2520 → 5040 |

> 附带发现：未登录的小红书 explore 页**一个 `overflow:auto/scroll` 容器都没有**
> （`containers=0`），且文档高度在测量中途从 4386 缩到 661 —— **线上页面不能当基准**。

### 4.2 已解决的真问题 ②：自动滚动"半路收工"

**根因**：收工判据只看"连续 N 轮没有新响应"，**不看页面是否真的到底**。

证据（00:38 那轮）：滚动停在 **13827px**，而页面高 **18469px**，
`视口已到底 = False`，底部还挂着「加载中」，却已经收工 → 少抓。

**修法**：收工判定改为"**必须 `atBottom=true` 且文档高度不再增长**"；未到底时阈值放宽到
60 轮，确实到底后才收紧到 12 轮；另外"到底后先耐心等 15 秒"再确认收工。

修后（00:59 那轮）：位移 **835 → 41699px**，`视口已到底 = True`，页面高 **42406px**。

### 4.3 已解决的真问题 ③：条目字段解析

接口返回是**扁平结构**（`note_id` / `title` / `type` / `user.nickname`），
旧代码按 `id` + `note_card.*` 取 → 27 条全部跳过、得 0 条。改为 `IdKeys={note_id,id,noteId}`
且两种结构都认。

### 4.4 拟人化滚动的实际参数（说明白：这是"像人"，不是"绕过风控"）

- 一次"甩滚轮"拆成连续 **2~6 个小增量**（单次 70~190px，间隔 35~130ms，偶尔"手停"一下）。
- 四种模式按概率混合：常态浏览 66% / 回看（先上拨再下拨）12% / 快速掠过 10% / 长停顿 12%。
- 轮与轮间隔 **200~3800ms 随机**；步长 120~660px 随机。
- **仅此而已**：没有做 UA / 指纹 / 节流对抗。这条要如实告诉用户，别把它说成"反风控机制"。

### 4.5 核心证据：424 vs 259（01:05 那轮，完整数据）

**采集侧**：
- **26 个响应（= 26 页）/ 去重后 259 条**；每页恒定 **10** 条，末页 9 条。
- 请求里写的是 `num=30`，**服务端每页只回 10 条**。

**分页链 26 步严格衔接**（节选，完整见归档报告）：
```
#1  请求=6a9d75050000  返回=6a8f0d270000  has_more=True   10条
#2  请求=6a8f0d270000  返回=6a0d9d380000  has_more=True   10条   ← 与 #1 返回完全一致
#3  请求=6a0d9d380000  返回=6a5d02ee0000  has_more=True   10条
...
#26 请求=6629fc840000  返回=6446874a0000  has_more=False   9条   ← 服务端说：没有了
```
> 每一步的**请求 cursor 恒等于上一步的返回 cursor**，26 步无跳无重
> → **抓取层一页都没漏。**

**页面自己怎么说**（DOM 结构快照，逐字 dump）：
```
DIV.reds-tab-item.sub-tab-list  >> 笔记
DIV.reds-tab-item.active        >> 收藏
DIV.reds-tab-item.sub-tab-list  >> 点赞
DIV.reds-tab-item.active        >> 笔记・424      ← 收藏子页签，页面自称 424
DIV.reds-tab-item                >> 专辑・1
DIV.reds-tab-item                >> 文件・2
```
- 一级页签是「**笔记 / 收藏 / 点赞**」；「收藏」下还有子页签「**笔记・424 / 专辑・1 / 文件・2**」。
- 用户 09-20 的截图显示 **423**，次日为 **424** —— 这个数字会随收藏动作变化，**不要当常量**。

**矛盾点（下一个接手者最该追的线索）**：
底部提示始终是「**加载中**」，其 DOM 祖先链为 `SPAN < DIV.feeds-loading < DIV.loading` ——
**同时服务端 `has_more=false`**。前端没有收到 / 没有处理"没有更多"的终止信号。

**稳定性**：三次独立运行分别是 **27页/268条**、**26页/258条**、**26页/259条**
→ 条数会浮动，说明它是"当时的服务端快照"，不是一个固定截断值。

**缺口**：424 − 259 = **165 条**。

### 5.2 待验证的假设（按推荐顺序）

**H1 · 失效/私密/已删除的收藏被页面计入、被接口过滤**

**H2 · web 端每页上限**

## 6. 复现手册（精确到命令）

### 6.1 环境前提
- Windows，已装 .NET SDK（`C:\Program Files\dotnet\dotnet.exe`）+ WebView2 运行时。
- **本机不要用 Bash**（bash 启动太慢，用户已明确要求停用）；用 PowerShell 当启动器。
- **两个 shell 都读不到输出**：PowerShell 的 stdout 会被吞（连 `Write-Output` 都不返回）；
  它自己的 `>` 重定向写的是 **UTF-16LE**，Read 工具会判为二进制拒读。
  → 定式：**让脚本/命令自己把结果写成 UTF-8 文件，再用 Read 工具读**。

### 6.2 构建（**先杀掉正在跑的壳**，exe 被占用会导致覆盖失败）
```powershell
Get-Process -Name LoginShell -ErrorAction SilentlyContinue | Stop-Process -Force
Set-Location 'D:\Codex\codex-视频ai产品\product\local\experiments-platform-shell\login-shell'
$out = (& "C:\Program Files\dotnet\dotnet.exe" build -c Release -v q -nologo 2>&1 | Out-String)
$exe = '...\login-shell\bin\Release\net10.0-windows10.0.17763.0\LoginShell.exe'
# 把 RC / EXE_LASTWRITE / 含 error 的行写成 UTF-8 文件后再读
```

### 6.3 启动（GUI **必须走 WMI**）
```powershell
$dir = 'D:\Codex\codex-视频ai产品\product\local\experiments-platform-shell\login-shell\bin\Release\net10.0-windows10.0.17763.0'
$si = ([wmiclass]'Win32_ProcessStartup').CreateInstance(); $si.ShowWindow = 1
$cmd = '"' + (Join-Path $dir 'LoginShell.exe') + '" --diagnose'   # 去掉 --diagnose 即交互式
([wmiclass]'Win32_Process').Create($cmd, $dir, $si)
```
- 必须用 `dangerouslyDisableSandbox=true` 且在有 GUI 会话的前提下执行。
- `run_in_background` / `Start-Process` 拉起的 GUI 进程**在本机会话结束即被回收**，不要用。

### 6.4 读结果
用 Read 工具直接读 `%TEMP%\wb-shell-collect-stats.txt`（或 Archive 里的副本）。
一轮诊断约 5~6 分钟。

## 7. 已知陷阱（全部实际踩过）

1. **exe 被占用** → 构建"成功"但 exe 没更新。构建前先 `Stop-Process`，构建后核对 `EXE_LASTWRITE`。
2. **GUI 进程存活**：只能 WMI `Win32_Process.Create` + `ShowWindow=1`；后台任务方式不行。
3. **Chromium 不读 `HTTP_PROXY`**：本壳已用 `AdditionalBrowserArguments="--proxy-server="` 显式清空，
   否则它会去读注册表里的系统代理。
4. **同一文件在同一条消息里发多个 Edit 会互相覆盖**（实测丢过 5 处）→ 同文件**一条消息只发一个 Edit**，
   改完用 Grep 核对新串是否真的落盘；收尾再做一轮总核对。
5. **别按 `python*` 宽匹配杀进程**（会连自己一起杀）。
6. **别删** `%LOCALAPPDATA%\wb-shell-login-userdata`（登录态在里面，删了要重新登录）。
7. **tab 数字会变**（423 → 424），不要把某一轮的数字当常量。
8. **壳启动后置顶 4 秒**这是为了让 WMI 拉起的窗口不被埋在别的窗口后面，会自动取消，不是异常。
9. **`wb-shell-captured-raw.txt` 每条响应只留前 1200 字符**，而 `cursor` 字段常排在 `notes` 数组之后
   → 光看这个文件会看到"cursor 断链"的**假象**。分页链要看 hook 在网络层就地解析的结果
   （诊断报告里的"分页链"一行），不要用落盘样本反推。
10. **页面 tab 与侧栏文本会混在 `document.body.innerText` 尾部**（页脚版权、侧栏 profile 卡片都在末尾），
    读"人眼所见页面底部"时要注意区分主区与侧栏。
