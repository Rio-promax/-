# 第一部分 · 当前手法（已验证可行）

## 1.1 一句话

**在真实浏览器里借页面自己的签名函数发请求，密度压到约 2 条/分钟。**
证据：269/269 成功、30 批全程未降档、命中人机验证 **0 次**。

## 1.2 四层结构 · 每层用了什么

| 层 | 做什么 | 来源 |
|---|---|---|
| ① 列表层 | 提供 269 条的 `note_id` + `xsec_token` | **复用**已有数据，本轮未重抓 |
| ② 详情层 | 调 `/api/sns/web/v1/feed` 拿正文/图片/视频地址 | **借签名**（本手法的核心） |
| ③ 请求头 `X-S-Common` | 随每个请求带上的环境指纹（332 字） | **借**（沿用页面产出的缓存值） |
| ④ 附件下载 | 图片/视频落盘 | **直连** CDN，不涉及签名 |

## 1.3 "借" 与 "自写" 的边界（别混）

**借的三样**
1. `x3` —— 页面自带的 `window.mnsv2(...)` 现场算出，本脚本未实现该算法。
2. `X-S-Common` —— 332 字固定值，从 `%TEMP%\wb-common-cache.txt` 读取（该文件 09-23 12:02 生成）。
3. TLS 指纹 / Cookie / Referer —— 请求由页面自己的 `fetch` 发出，全部是浏览器真实值。

**自写的只有一层外壳**
`XYS_` + 自定义 base64（脚本内 `mkXs`）。它只把 `x3` 装进 JSON 再编码，**不含签名算法**。

**明确没做**：`_webmsxyw` 那类纯算法逆向。本手法不依赖逆出签名算法。

## 1.4 节流参数（核心，别随手改）

| 参数 | 值 | 位置 |
|---|---|---|
| L0 | 批 8 条 / 批间**真静默** 4 分钟 | `LADDER[0]` |
| L1 | 批 4 条 / 批间真静默 8 分钟 | `LADDER[1]` |
| 条间抖动 | 1.3 ~ 2.7 秒随机 | `GAP_EXPR` |
| 命中验证上限 | 2 次（第 2 次即停手） | `MAX_VERIFY` |
| 网络类失败重试 | 每条 3 次 | `NET_RETRY` |

"真静默" = 不发任何请求（不探活、不预取）。
实测：269 条约 **2 小时 16 分**，折合约 **2 条/分钟**。每批进程本身只跑约 40 秒，其余全是静默。

## 1.5 证据（可复核）

- `product/local/experiments-platform-shell/captured/2026-09-23/xhs-all/抓取报告.txt` 原文行：`抓到 269/269 条；命中验证 0 次`
- 30 个批次全部标记为 `梯度 L0`，无一行 `降档` / `!!!`
- 列表源：`product/local/experiments-platform-shell/captured/2026-09-21/xhs-favorites-269.json`（269 条，**09-21 12:14** 生成）
- `X-S-Common` 缓存：332 字节，09-23 12:02

## 1.6 已知薄弱点（诚实清单）

1. **密度上限未知**。09-23 15:0x 那次 461 就是"8 条连发、约 21 秒/条"触发的 → 触发变量是密度，不是累计次数。
2. **解除条件未知**。一旦被标记，**单次请求也会被拦**（15:14 单条页面式也被 302 到 `/login`）→ 风控落在**账号/会话层，不在通道层**。"换个通道就安全"不成立。
3. **`X-S-Common` 是缓存值**，时效性未验证。若出现大面积 406 且只有它是变量，第一件事是重新从页面取一份新值。
4. **没有公开 API**，全靠页面。页面改版 → 整条链断。
5. **单次样本**。一次 269 条干净 ≠ 每次都会干净，风控阈值本身会变。

# 第二部分 · 降级方案（登记，本轮不实施）

## 2.1 触发信号（什么算"出问题了"）

判定逻辑已在 `xhs-borrow-fetch.py::judge()` 内实现，分三态。

| 信号 | 含义 | 归入 |
|---|---|---|
| HTTP 461 / 471 | 服务端要求人机验证 | verify |
| HTTP 406 | 签名或会话被拒 | verify |
| HTTP 429 | 限流 | verify |
| code −100 / −101，或 msg 含"验证/登录" | 登录失效 | verify |
| HTTP 200 + code 0 + items 为空（同批 **≥2 条**） | 疑似静默风控 | verify |
| 其余（超时、5xx） | 网络类，**不计入验证次数** | other（按条重试 3 次） |

## 2.2 五级降级阶梯

| 级 | 触发 | 做法 | 代价 | 状态 |
|---|---|---|---|---|
| **D0** | 正常 | 现状不动：L0 批 8 / 静默 4 分 | 269 条 ≈ 2h16m | ✅ 现役 |
| **D1** | 首次命中验证 | 自动降到 L1：批 4 / 静默 8 分，重试本批 | 时长翻倍 | ✅ 已实现（自动） |
| **D2** | 同上 | 弹**可见窗口**请人工过一次验证，完成后重试本批 | 需要人在场 | ✅ 已实现（`pause_for_human`） |
| **D3** | 接口通道持续被拒，但账号勉强可用 | **改走拟人**：页面内逐条导航，只读页面自带 `__INITIAL_STATE__`，不构造请求、不碰签名 | **20~45 秒/条** → 269 条约 **1.5~3.4 小时** | ⚠️ 脚本已有（`xhs-extract-all.py`），仅验证过 23 条 |
| **D4** | 账号被要求重新登录 / 验证过不去 | **停手**：保留已落盘数据，人工重登或过验证后重跑（脚本自动跳过已完成） | 全人工 | ✅ 已实现（resume + 第 2 次命中即停） |

**D3 补充事实**：拟人路线不是没试过。09-21 用 `xhs-extract-all.py` 已走通并落了
`product/local/experiments-platform-shell/captured/2026-09-21/extracted/xhs-notes-extracted-full.jsonl`（**23 条**全量正文）。
它被借签名取代的唯一原因是**慢**，不是不可用。

## 2.3 兜底与明确不做

**兜底**：已落盘数据 + `notes.jsonl` 续跑（重跑自动跳过已完成条目，不重复请求）。

**明确不做**
- 不做纯算法逆向（`_webmsxyw` 一类）—— 收益（省页面渲染）远小于维护成本
- 不建定时任务（本项目常驻流程只走按需 Skill，不挂调度）
- 不换账号、不多账号轮换
- **不做任何绕过人机验证的尝试**（验证一律交人工）

## 2.4 若将来要实施 D3，只需做两件事

1. 给 `xhs-extract-all.py` 加"从已有列表源续跑"的入口，确认 269 条能续上（当前它读的是同一份 `xhs-favorites-269.json`，应已可直接跑）。
2. 用 20 条试跑，核对正文完整度与 `xhs-all/data/notes.jsonl` 是否可对齐（两边字段名不同，需要一次映射）。

# 附 · 术语速查

| 词 | 指什么 |
|---|---|
| 借签名 | 借页面自己的签名函数发请求，不自己实现签名算法 |
| 拟人 | 页面内滚动/点击/逐条打开，只读页面已渲染内容，不构造请求 |
| `x-s` / `x-t` | 主签名与时间戳，由 `window.mnsv2` 产出 |
| `X-S-Common` | 随请求带的环境指纹，332 字，本手法用缓存值 |
| `xsec_token` | 每条收藏链接里的访问令牌，调详情接口必需 |
| `LoginShell.exe` | 本机 C# + WebView2 壳程序（Edge 内核），不是虚拟机、不是云端 |
