## 四层关系与轻量图边界

> 本次修订：四层是组织关系视图，不是四个向量库；检索表示采用文档导航、笔记、原始证据三层，按实际材料允许缺层。完整最新规则见[执行契约](../规则/RAG执行契约.md)及[本轮方案](../../过程/2026-11/11-06_跨平台知识库检索与工具调度_解决方案.md)。

用户通过收藏夹／标签组织内容，通过总结阅读与 AI 问答理解内容。机器内部采用以下四个逻辑层；同一内容 ID 连接各层，不为每层新建用户文件。

| 层 | 保存与职责 | 是否在轻量图中 |
|---|---|---|
| L1 用户组织数据层 | 收藏夹、用户标签及内容归属；作者、平台、媒体类型等现有属性 | 收藏夹、用户标签、作者、平台、媒体类型参与关系投影；时间仅沿用业务字段，不建图节点／边 |
| L2 内容分类层 | 32 项规范主题多选关联及单独命名的正式检索细标签；候选细标签在普通存储中仅作加权特征，用户标签保持独立 | 是；与 L1 构成轻量图的简洁关系表示 |
| L3 总结检索层 | 已有概述／总结及其段落索引，用于“讲了什么”、宽泛理解、跨篇比较 | 否；图只保留能访问该内容材料的 ID |
| L4 原文证据层 | 字幕、正文及原始位置，用于原话、数字、条件和冲突核实 | 否；图仅以 ID／位置引用连接，不内嵌正文 |

“内容分类层”指主题等短分类表示；“总结检索层”指长文本寻找与理解，两者不再统称“内容层”。时间位置属于 L4 的来源定位属性，不额外新建一层。文档级表示在图外保存标题、短概述及有依据的主题词；L3 和 L4 是两种独立文本检索层，L1／L2 不与其长文本同池竞争候选。

**图内数据白名单：** 内容 ID，收藏夹／用户标签／平台／作者／媒体类型关系，主题 ID／固定名称，正式细标签 ID／短名／短定义／状态，受控关系类型，主次角色、讨论程度，必要加工状态、版本及依据 ID／位置引用。时间字段可从已有内容记录读取，但不建时间节点／关系。图不保存单篇“具体讲了什么”的描述，不新增概述或总结字段。主题及正式细词可以有公共短定义以统一含义，该定义不是视频内容摘要。

示例：内容 V1 → 平台 B站、类型视频、作者 A1；V1 → 主要主题“美食餐饮”，确有旅行露营内容时可另关联“旅行户外”；采用个人经历或日常过程记录结构时，可同时关联 Vlog。“教学”等词不写为新主题。完整总结及字幕仍从 V1 的既有归档记录读取。

**执行分工：** 入库时 LLM 从图外材料提取规范主题及候选细词；自然语言问题交给 LLM 合并解析对象与答复点并直接提出工具动作，程序校验范围／参数后执行查询、遍历和计数。取得材料后由 LLM 检查答复点支持度，决定是否补查或生成；图计算本身不让模型重新计算数值。

# 一、项目目标与整体执行顺序

产品需要完成六类任务：

1. 找到某一份具体资料。
1. 列举符合条件的一组资料。
1. 解释内容中的具体问题。
1. 合并总结、比较多份资料。
1. 探索对象、方案和决定之间的关系。
1. 根据已有资料，为用户形成有依据的行动建议。

系统分为三条相互衔接的流程：

**资料准备流程**

读取归档快照 → 检查材料 → 清洗与定位 → 内容卡与主题 → 分块 → 建立文本和向量索引 → 建立关系索引 → 校验并发布可用版本。

**用户查询流程**

接收问题与范围 → 理解任务 → 解析对象与条件 → 制定执行计划 → 执行检索或集合查询 → 检查证据与覆盖 → 必要时补查 → 生成对应结果 → 校验并交付。

**持续维护流程**

内容变化或用户反馈 → 定位受影响数据 → 更新派生索引 → 运行回归评测 → 发布或回退。

普通 RAG、轻量图关系检索和结构化查询是查询执行阶段的不同能力，可以组合使用。并非每次都先进行图检索，也并非所有任务最终都需要生成一段长回答。

# 二、统一约束与实现基线

以下约束及共用检查适用于全部步骤；后续只描述该步骤特有的动作。

| **约束** | **具体要求** |
| --- | --- |
| 资料范围 | 用户选中的内容、收藏夹或标签，约束所有检索、图遍历、SQL 和生成步骤 |
| 来源可追溯 | 总结性回答能回到所用内容及总结版本；原话、数字、说话者等具体事实能回到原文位置。模型总结与主题关联不能冒充原文证据；不要求每次宽泛回答都扫描字幕 |
| 版本一致 | 同一次执行记录所用资料与索引版本；不能无提示地混用修改前后的证据 |
| 完整性诚实 | 分别记录图覆盖、建图材料覆盖及主题分类质量；已发布完整图可直接执行受支持口径的集合统计，完整建图不等于语义判断零漏标 |
| 执行有界 | 限制补查次数、图遍历深度、候选规模、模型调用和费用；达到限制后交付明确的部分结果 |

**共用检查 C1–C5：** C1 内容及关系依据属于当前范围且仍有效；C2 来源及索引身份兼容；C3 引用能定位所用总结版本或原文位置；C4 集合按内容 ID 去重且计数来自实际集合；C5 覆盖说明与已处理材料、未知项及剩余预算一致。证据汇总、交付前和恢复任务时复用这份检查，不另维护一套口径。

**覆盖记录：** 建图时逐篇记录内容及材料版本、主题加工状态、关系版本；记录目标集合中已完成、待处理、失败及待修正的内容。查询时核对当前范围是否被兼容的图版本完整覆盖；条件可由已有属性及主题规则表达时，直接数据库计算，不重新逐篇调用模型。查询补建或新语义判断时，另存“匹配／不匹配／未确定／未处理”的本轮状态；未知不能当作不匹配。只做候选召回时仍称“找到的相关内容”。

初期技术形态继续采用：

- 本地保存归档、业务数据、全文索引、向量和轻量关系表。
- 云端 API 承担 embedding、重排、信息抽取、查询理解和生成。
- 正常使用无需本地大型模型。
- 完整轻量关系图采用本地关系表及可重建查询视图；“完整”指内容及约定关系的覆盖，未要求专用图数据库或全库自由实体图。

**切块实施边界：** 总结按段落、字幕／ASR／正文按来源及顺序组成有界结构化 chunk；模型只建议边界，程序校验序号、来源覆盖、顺序与 UTF-8 字节上限。当前每篇最多 6 次／总计 20 秒，每次最多输入 10,000 字节与输出 128 tokens；失败回退有界规则切块并留状态，不在查询时调用切块模型。查询向量检索到字幕／ASR 块后，回答证据需要上下文时只补前 1 块＋命中块＋后 1 块，标记 matched／adjacent 并保留原始段 ID 和真实时间；不为每句字幕独立向量化，不插值伪造位置。chunk 上限 2,400 UTF-8 字节，embedding 模型上下文 32,768 tokens 另行用保守 UTF-8 字节上界校验。模型建议、规则回退、缓存、profile 与版本迁移按执行契约及构建方案记录；保留旧 profile 供回滚，不静默全库外发重建。比较和综合按问题取相关段落，不默认把长总结一次塞入模型。

**数据契约边界：** 复用已有内容标识；片段身份必须区分所属内容及索引版本，文本哈希用于变化检测，不承诺重切后标识不变。证据对齐使用原始位置。主题为版本化的规范平面词表，一篇内容可关联多项；不存主题父子关系或推导上位主题，不将来源平台分区 ID 当作本品 ID。元数据允许缺失及修正，归档快照与当前字段分别处理。

## 总结强度与细标签的新增边界

用户选择简要 `quick`／标准 `standard`／详细 `deep`，默认标准，记录到对应总结版本，不用 `light/full` 替换现有枚举。三档处理同一材料范围，区别在输出详略；材料等级、原文是否可用及索引覆盖分别记录。旧数据强度未知时不按长度猜测，不额外生成完整版备份。用户入口见知识库 PRD CP-12，分档 Prompt 与字段见[执行契约 §3](../规则/RAG执行契约.md#3-用户总结强度与元数据)。

内部检索细标签采用候选→正式→休眠／失效的独立状态。有材料依据时每篇抽取 1～5 个，少于 5 个不凑数；无有效概念时允许 0 个；仅参加检索特征，不入生效图视图。正式词需满足去重行为事件、材料支持、同义复核、开发者审核及容量条件，才建本地关系边；“强关联”不代表事实置信度更高。32 项规范主题不随细词晋升改变，完整统计不以标签命中数量替代范围检查。完整参数及 P-TAG／P-MERGE 见[执行契约 §4](../规则/RAG执行契约.md#4-内部细标签生命周期-r1)。

# 三、资料准备流程：从原文到可查询知识库

## 职责划分

主题及分类契约集中在步骤 3；两层检索单位和索引分别在步骤 4、5；步骤 6 建设全库轻量关系图并区分后续对象关系扩展；步骤 7 发布图覆盖和集合查询视图。小样本抽查用于发现问题；模型新增调用、索引文本量和问答输入量随评测记录，不凭抽查或数据库返回计数证明结果完整。

## 步骤 1：读取资料快照，确定本次处理对象

**输入：** 已有总结与原始字幕，分别记录来源和版本。已有总结直接进入总结检索层表示与索引；原始字幕经轻量清洗和定位后进入原文证据层，原字幕继续归档保留。

**操作：**

1. 获取内容 ID、来源位置。
1. 判断哪些是原文，哪些是生成总结或用户笔记。
1. 检查正文是否为空、是否仅有局部内容、是否能够定位原始位置。
1. 对比上次处理记录，确定新增、修改和无需重建的内容。

**输出：** 本次待处理内容清单及其材料状态。

**检查点：**

- 同一内容的版本变更，用户确认修改后进行更新。
- 仅有摘要的资料可以参与摘要层寻找，但不能冒充拥有完整原文。
- 处理失败项进入明确的待处理清单。

**遇到的问题：** 资料存在，但正文缺失或损坏。

**处理方式：** 保留内容卡片和可用元数据，标记当前可用能力，避免直接删除或伪造完整知识表示。

## 步骤 2：清洗文本，同时保留原文位置

**输入：** 内容的原始文件。

**操作：**

1. 处理断行、重复字幕、页眉页脚、格式残留。
1. 识别模板宣传、广告和无关说明，降低其检索优先级。
1. 规范已经确认的术语和别名。
1. 保存清洗文本与原文之间的位置对应关系。

**输出：** 可重建的内部检索文本及原文位置映射；不覆盖归档原文，不再清洗已有总结。

**检查点：**

- 数字、单位、否定和条件不能在清洗中丢失。
- 原文不被覆盖。
- 不进行事实观点类修改。

**遇到的问题：** “清洗后更流畅”，但原文的限制条件消失。

**处理方式：** 清洗优先采用确定性规则；模型参与的修改保留记录，并对关键事实进行抽查。

## 步骤 3：综合三平台的规范主题词表（32 项设计稿）

每份内容维护简洁属性记录，包含内容 ID、标题、作者／平台／媒体类型及时间等已有字段。图投影只关联收藏夹、用户标签、作者、平台、媒体类型、主题和正式细标签；发布时间保留在业务记录供其他路径筛选，不创建时间节点／边。总结和原文保存在图外归档；加工主题时按 ID 读取，不复制到图节点，不生成逐篇长描述。

**设计原则：** 基于 2026-10-30 保存的小红书、抖音、B站资料作本品设计归纳；合并同义或同一覆盖范围的来源分类，用具体对象或讨论方向替换模糊兜底项。以下不是平台官方词表，不使用知乎新增类别作为本轮设计输入。

此表是分类覆盖映射，不是“全部互为同义”的别名表。“彩妆”比“美妆护肤”窄，“露营”比“旅行户外”窄，不能直接将整个宽类集合当作细节查询结果。

**多主题与语义交叉：**

- 同义类不重复建节点；相关但范围不同的类可并存，不设置必须远离的最小语义距离。
- 确有多个讨论方向时分别关联，逐条保留依据与主要／次要角色，不为凑数补标签。
- 主次角色与实质讨论／提及的讨论程度分开，次要主题也可能有实质讨论；不能自动排除次要主题。具体判据见执行契约 §2；词表外细概念不等于查询粒度 detail。
- 名称、人物或物品仅出镜不足以建立关联；材料不足保留未确定，不强行贴类。
- 单主题内按内容 ID 去重；跨主题“或”取并集、“且”取交集。各主题数量之和可以超过内容总量，不能相加当作总库数量。

示例：RAG 开发教程可关联人工智能、科技数码、教育学习；AI 手机功能测评可关联人工智能、科技数码；露营做饭可关联旅行户外、美食餐饮；跑步训练或球赛内容均归入运动健身，不重复贴体育与健身两个标签。是否同时标注取决于材料，不凭标题套用全部标签。

**广义附属与交叉的区别：** 同义名称或适合统一收纳的广义附属项，归入一个规范主题；仅因共享更宽泛上位概念，不无限合成“知识／生活／娱乐”等兜底项。人工智能作为本品高频检索方向保留，可与科技数码交叉；医疗健康聚焦疾病、医疗与健康知识，运动健身聚焦运动与训练，两者不因都有关健康而自动合并。摄影摄像与科技数码按影像技法／设备技术的实际讨论重点判断，允许多选。

**用户标签与细节查询：** 用户标签独立维护，仅在用户选择时限定范围。RAG 等细词可作为内部候选／正式检索细标签，但不新建第 33 个规范主题，也不是人工智能的同义别名。材料不足时分别记录已检查无匹配、待处理或未确定；这些是加工状态，不是“其他”主题。

**逻辑数据契约：** 优先复用或扩展已有存储。

| 记录 | 最小字段与约束 |
|---|---|
| `topic` | 本品规范 ID、名称、公共词表短定义及版本；本稿为上列 32 项，无维度、父 ID 或运行时 AI 新增入口，不存单篇描述 |
| `topic_alias` | 主题 ID、经确认的真正同义别名及版本；来源覆盖映射、细概念和相关词不能直接写成同义别名 |
| `content_aspect` | 内容 ID、主题 ID、主次角色、讨论程度、AI 推断／人工修正来源、生效状态、依据 ID／位置／版本、分类模型及提示词版本；同一内容和主题当前仅一条生效边，重试不重复写入 |

**参数标准：** 主次主题数量及细词参数按执行契约首轮初值实施并在固定题集验证；不得把未实测初值写成准确率结论。规范主题可合法交叉，语义相近不能直接合并；细词真正同义合并另用 P-MERGE 复核。

**执行：** 复用总结材料 → 按各主题定义判断 → 选取有依据的多项主题及角色 → 校验 ID、数量、来源与重复边 → 保存关联及加工状态。总结不足时按需读原文，图中只留依据引用。原平台分区保留为来源元数据，不直接替代内容判断。

**输出：** 内容属性、规范词表／真正同义别名及内容—主题关联。来源对照见[调研记录](../../过程/调研/B站分区参考与RAG分层路由核对.md)，具体名单与边界待人工验收。

## 步骤 4：形成允许缺层的三种材料表示

**总结检索层 L3：** 保存／索引已有概述和总结段落，通过内容 ID 连接图外归档，供机器理解“主要讲什么”“有哪些学习要点”等宽泛问题。图负责集合筛选，L3 负责文本理解，二者不共用一个长文本节点。纯主题计数与列举在 L1／L2 完成；词表不能表达的语义查找才进入 L3 发现候选。

**原文证据层 L4：** 带原始位置的正文、章节或字幕片段，供机器回答“谁说了这句话”“具体数字是多少”“这项条件如何表述”等细节问题。可在一篇或问题限定的多篇内容内检索，不要求用户先打开证据层；总结检索层缺少必要依据时也可按需下钻。

**切分与关联（当前实现）：**

1. 总结按段落形成结构化 chunk；字幕／ASR／正文先按来源顺序成组，再依据模型建议的边界形成有界 chunk，不逐句向量化。模型仅提边界，程序验证边界完整、有序、来源一致及预算；未配置、超时、拒答或输出无效时回退到有界规则切块并记录原因。
1. 每个 chunk 保存内容 ID、来源类型、来源段 ID、ordinal、真实原文定位及 profile 身份；字幕时间只沿用来源实际给定的起止点，不插值伪时间。既有章节可复用，不新建不必要父表。
1. 模型边界建议按单篇 ≤6 次、总计 ≤20 秒，每次输入 ≤10,000 字节、输出 ≤128 tokens；chunk ≤2,400 UTF-8 字节。embedding 上下文 32,768 tokens 是独立限制，按保守 UTF-8 字节上界校验，正则词数估算不冒充 tokenizer。
1. 作者、平台、收藏夹从业务关系读取，不复制为每块独立事实；过滤副本为可重建字段。chunk 边界版本写入 profile，升级仅索引当前明确处理内容，新归档继续增量索引；受控重建由既有入口确认，不自动静默全库外发，旧 profile 保留回滚。

**输出：** 内容检索单位、证据片段及它们的对应关系。

**检查点：**

- 所有证据片段能回到所属内容。
- 概括性回答可依据总结并标明来源类型；精确数字、原话和关键条件按需核实原文，不将总结冒充原文。
- 更换分块规则后，评测金标准仍能通过原始位置对齐。

**困难：** 小 chunk 更容易定位到具体证据，但单块可能缺少上下文；扩展过多会引入无关内容。

**检索时扩展上下文：** 字幕／ASR 命中块默认以需要上下文的证据窗口展开前 1 块＋命中块＋后 1 块；相邻片段只作为 prompt evidence，不参与向量相似度排名，分别标记 matched／adjacent_previous／adjacent_next。按同内容、同来源及 ordinal 去重并控制预算；提交模型前保留来源 refs、ordinal、真实时间及内容标题。引用复用详情跳转；无可靠时间回到详情。检索表示变化升级索引身份，不修改归档原文。

## 步骤 5：构建普通 RAG 所需索引

**操作：**

1. 对标题、作者、内容卡、已有总结和原文建立适合各字段的词法索引。
1. 对总结 chunk 与结构化原文 chunk 分别生成 embedding，保留层级标记；总结层不压成一条无限长向量，字幕也不以单句作为独立向量。每个新 chunk profile 单独记录模型身份与覆盖状态。
1. 两层独立召回和重排，按问题选择入口；需要组合时按内容及问题合并，避免长视频的大量字幕块挤占内容级候选。
1. 保存模型身份、维度、文本哈希和索引版本。
1. 建立元数据过滤与范围查询能力。
1. 支持按 Content 分组返回结果，避免长文档占满候选。

**输出：** 内容级检索、片段级检索和结构化过滤能力。

**检查点：**

- 查询向量与索引向量使用兼容的模型身份。
- 删除或失效内容不参与当前查询。
- 原文检索能补救内容摘要未提及某个主题的情况。

**失败处理：** 某批 embedding 失败，只标记该批失败并支持重试；不得把部分成功写成全库完成。

## 步骤 6：建设覆盖全库的轻量关系图

**目标：** 全部有效入库内容都有简洁内容节点，与主题记录并列连接，关联已有属性／元数据；规范主题从既有 32 项选择，不另建规范主题维度或下级节点；正式检索细标签以独立对象建立内容关联。图内不存总结、字幕、内容概述或逐篇长解释，材料只以 ID／版本／位置引用连接；查询借此关联、跳转、展开、平铺和筛选。“全库”始终指当前用户有权访问的有效入库资料。轻量指关系类型受控、存储和维护简单，不指只覆盖少量内容。常规主题统计不依赖查询时从头扫描全文。

| 对象与关系 | 实现及查询用途 |
|---|---|
| 内容及固有属性 | 内容 ID 连接标题、平台、作者和媒体类型等已有字段；发布时间可从原记录筛选，但不创建时间节点或时间关系；字段缺失明确记录，不猜测 |
| 收藏夹／用户标签—内容 | 读取当前业务关系限定范围，与 AI 主题独立；在多个收藏夹内的同一内容仍是一个节点 |
| 内容—AI 主题 | 关联当前规范词表中的一项或多项，带主次角色、讨论程度及材料依据引用和版本；不保存长文本依据 |
| 主题词表及别名 | 本稿 32 项平面主题和真正同义别名；不建设规范主题父子边，内容跨主题命中仍按内容 ID 去重 |
| 内容—正式检索细标签 | 正式词关联材料支持的内容，可附有依据的粗主题归属；作者／平台仍从来源内容读取，不造自由实体树；候选词不进生效图 |

**建图与维护：** 枚举目标库全部有效内容 → 复用元数据和业务关系 → 对缺失或过期内容补做主题加工 → 校验主题及关系 → 发布对应覆盖版本。新增内容增量加入，材料或主题定义变更更新受影响关联，删除及范围调整按当前有效关系生效；失败项保留节点和加工缺口，不伪装为“无主题”。元数据直接读取现有字段，必要的图投影可重建，不复制第二套事实源。

**关联、跳转与平铺：** 程序从收藏夹／标签定位内容集合，按类型或作者等属性筛选，再沿内容—主题关联展开；已有条件用数据库执行，无需 AI 解释关系；最终统一投影为去重内容集合，再排序、分页或计数。“平铺”仅指查询结果展开，不改变用户收藏夹组织；两个内容共享主题也不因此复制出全量内容—内容边。遍历受当前范围、允许关系和预算约束。

**完成标准：** 目标库内容节点覆盖完整；属性缺失与主题加工失败可识别；生效主题边能定位加工材料和版本；无悬空关系、重复生效边或词表外主题；完整性发布门槛见步骤 7。图覆盖与分类质量分别验收，图遍历本身不能纠正漏标或误标。

**后续对象关系扩展：** 真实问题需要方案依赖、人物观点或决定演变时，再增加带方向、时间、条件和原文依据的对象边；实体合并可撤销，共现不当作因果。当前全库轻量图不要求自由实体抽取、社区报告或 Microsoft GraphRAG 完整架构，相关背景见[官方说明](https://microsoft.github.io/graphrag/query/overview/)。

## 步骤 7：发布图覆盖、集合查询视图与索引状态

**集合查询视图：** 当前内容属性、收藏夹／用户标签、32 项主题内容关联，以及正式细标签的受控跨篇关联。候选细词只进普通检索索引；复用关系表，频繁昂贵的查询再预计算，不建全量闭包。规范主题覆盖与正式细词覆盖分开报告，细词尚未晋升不妨碍已有规范主题计数。

**发布覆盖：** 对目标库记录有效内容总数、已关联内容节点数、主题加工完成／待处理／失败／过期数、主题体系版本及图版本。主题加工完成必须经过步骤 3 的约束校验，并记录所用总结或原文范围；没有主题边不能代替加工完成标志。

**查询可用门槛：**

- 范围内图关系均为当前有效版本，主题加工完成且口径受支持时，可直接按图执行完整集合查询及统计，无需本轮重复读取每篇材料。
- 范围内有未完成或过期项时，先补建相关缺口；无法完成则返回已确认集合与缺口，不能将图中暂缺的边当作“不匹配”。
- 新问题无法由现有主题及属性表达，或要求当前材料未覆盖的细节时，才进入按需语义补检及关系更新。

全文、向量、总结、转写及图分别公布覆盖并复用已有任务状态，失败可单独重试；单项完成不代表全部就绪。仅有总结时允许总结检索层检索并标明无法核查原文；未完成对象关系的内容仍可普通检索。

# 四、用户查询流程：从一句问题到可执行计划

## 步骤 8：接收问题，固定当前上下文和范围

**输入：** 原始问题、当前页面、用户选中内容、收藏夹或标签、会话状态。

**操作：**

1. 确定本轮允许访问的内容集合。
1. 解析“这些”“上面那个”“刚才的三个”等引用。
1. 获取上一轮真实结果集合，而不是仅凭聊天摘要猜测。
1. 记录本轮范围与资料版本。

**输出：** 本轮查询上下文。

**检查点：** 用户改变范围后，不能继续引用原范围之外的资料。

若指代有多个可能对象，且会显著改变结果，先澄清；不影响主要执行的次要歧义可以说明假设后继续。

## 步骤 9：合并查询理解与直接工具计划

保留原问，提取对象、范围、关注点、覆盖和输出要求，直接形成工具参数与答复点；查询改写不增加条件，不生成互斥类型。明确ID/结构化操作由程序处理，歧义影响对象选择才澄清。工具和JEV边界以执行契约§5、§7–9为准。

## 步骤 10：实体匹配与条件校验

**操作：**

1. 将主题名称匹配到主题及别名。
1. 将作者、项目、收藏夹匹配到真实对象。
1. 区分“发布时间”和“归档时间”。
1. 检查字段、单位、排序和聚合是否受支持。
1. 对同名对象保留多个候选，必要时澄清。

**输出：** 可以执行的对象 ID、过滤条件与仍待确认的语义条件。

**困难：** 用户自然语言中的分类与现有分类体系不一致。

**处理方式：** 匹配规范主题和真正同义别名；检索细词只用于候选定位，不能把更窄概念当粗主题别名。未知细节转文本，不在查询中自动晋升或新增规范主题。

## 步骤 11：受控工具执行

冻结范围/版本和材料能力 → 一次P-ACT直接输出动作 → 校验并执行 → 多路融合、文章覆盖与按需重排 → P-RESPOND支持检查及回答/补查 → 校验交付。允许组合动作；不强制按层逐级调用。

普通查询有限补查，完整集合独立分页汇总。原文缺失时读取笔记并明确依据，精确原话无法核对就说明不足。JEV仅在API核实和旁路评测后替换明确判断节点，不增加必经分类层。具体预算唯一见执行契约§10。

# 五、各检索路径的具体执行方式

## 步骤 12A：普通 RAG 路径

1. 固定允许访问的资料范围，判断问题粒度。宽泛问题先查总结检索层；具体原话、说话者、数字和条件等问题进入原文证据层。用户已指定内容时直接限定这些内容，不必先做全库内容召回。
1. 宽泛问题：在标题、主题、概述与已有总结中执行词法／向量召回，按篇去重和排序，再按问题选择相关总结段落作为回答依据。
1. 细节问题：在已确定的相关内容范围内检索字幕块；细节未被总结覆盖、尚不能确定所属篇时，允许在用户原始范围内检索字幕并回收所属内容，避免总结检索层成为不可越过的门槛。
1. 每层分别做关键词／向量召回及 RRF 融合；按任务限制 chunk 和每内容块数，分阶段记录初召回、跨层合并、邻接展开与最终证据截断。top_k 是 chunk 数，不是文章数；完整集合目标不受 top_k 限制。
1. 字幕／ASR 命中证据按前 1＋命中＋后 1 扩展；邻接块只提供上下文，不得假装命中或取得相似度分。宽泛问题不默认扫描全部字幕。
1. 机器将检索依据交给回答生成过程；用户在 AI 问答中直接得到答案与必要的内容引用，无需进入检索层。

**完成标准：** 总结性问题有相关内容及总结依据；原话、数字等具体事实有可定位的原文依据，关键条件未被截断。

**补查触发：** P-EVIDENCE 对必答点评分为 0／1 且有可读材料时，按缺口补查；quick 仅提高不足点的原文补查优先级，不强制查字幕。standard／deep 不因高分而免除依据检查；笔记事实标明笔记来源，原话核验必须有原始材料。每题不固定执行全部层。

查询改写、多查询、HyDE 等属于这一过程中的可选策略，必须由失败类型触发，不能默认每题全部运行。

## 步骤 12B：主题集合、枚举与统计路径

**图直接查询：** “收藏夹里有多少人工智能视频／美食餐饮视频”“同时涉及旅行户外和美食餐饮的内容有哪些”。

1. 固定收藏夹等用户范围、统计时间及媒体类型／作者等属性条件。
2. 将主题规范词及同义别名映射到当前规范词表 ID，按 AND／OR／排除、主次角色及讨论程度关联内容，平铺去重。
3. 经 LLM 理解为规范主题／元数据集合任务后，图覆盖完整即由数据库计数、排序、分页，不再让模型读取总结或重新计算数值。
4. 图加工缺失或过期时补建缺口；不能完成则报告已确认数及待处理项。

**词表外语义条件转文本：** “有多少讲 RAG 的视频”“有哪些美食教学视频”。RAG、教学等不在规范主题词表内，不创建规范主题下级；候选／正式细词可加速发现，但仍执行 L3 文本核实，原话、数字、局部提及等必要细节进入 L4。已有“人工智能／美食餐饮”主题可用于优先安排候选；除非用户明确限定该主题，否则不能因此排除原始范围内其他内容。

用户只需若干相关内容时可返回检索候选；要求“全部／总共有多少”时，按统一语义逐篇检查原始目标集合，记录匹配／不匹配／未确定／未处理及所用材料。只有范围检查完成且无未知项时，才给出该材料口径下的完整总数；top-k 数量不能冒充总数。结果是本轮查询记录，不持久扩充主题词表。

**分页例：** 若图关系查询按过滤条件共有 53 项，API 返回 `total_count=53`；`limit=20, offset=0` 显示第 1–20 项，`offset=20` 显示第 21–40 项，`offset=40` 显示第 41–53 项。`page.count` 是当前页行数，`has_more` 表示仍有后页；分页只限制显示窗口，不伪作全集总数。反之，文本 `top_k=24` 代表最多 24 个 chunk 候选，可能来自同一篇或多篇，绝不代表 24 篇资料。

**预算：** 固定主题统计主要执行数据库查询；细节语义统计可能调用模型逐篇判断，成本和时间另行记录。预算不足时保存进度，返回已确认数量与剩余项，展示分页不限制检查范围。初召回、合并、最终输入有不同的有界 chunk 配额；这些起点不是已验证最佳值，当前具体数值以执行契约 §10 为准。

### 路由例子：选择与跳过

- 正例（broad）：“C01 主要讲什么？”→先查 L3 总结块。摘要支持主线时不额外扫字幕。
- 正例（detail）：“C02 原文给的切片大小是多少？”→查 L4 原文块并保留定位；不能用 deep 总结或向量高分代替原文。
- 正例（mixed）：“这两篇的观点和具体参数分别是什么？”→需要概括的答复点查 L3，精确参数点查 L4；两层独立召回后按点合并。所选两篇 ID 都作为保护目标。
- 正例（all）：“所选资料里所有讲 RAG 的内容有哪些？”→冻结当前完整范围逐批语义判断，保留 match／no_match／unknown；检索 top-k 和细词图关系都不能替代全量检查。
- 反例（避免多查）：“所选收藏夹里有多少人工智能视频？”→已发布分类覆盖完整时由 L1/L2 数据库计数；不调用字幕检索或让 LLM 重数。
- 反例（不误判找全）：“给我最相关的几条 RAG 材料”→走有限候选，不启动 all 扫描，也不把候选条数说成范围总数。
- 反例（unknown）：“有多少篇讲 RAG？”→摘要未提及不能作为 no_match；正文不可用、分类未完成或扫描未完成时保留 unknown 并返回部分确认数。

**计数边界：** 只统计明确关联的规范主题；体育与健身都按运动健身收纳，不建立两套主题反复计数。单篇多主题的并集只计一次，各主题数量相加可能超过内容总量。“人工智能数量”仍不能代替“RAG 数量”。

## 步骤 12C：轻量图关系检索路径

1. 确定查询中的起点对象、目标对象或关系类型。
1. 在用户范围内找到相关节点。
1. 只沿计划允许的关系展开。
1. 控制跳数、分支数和重复访问。
1. 将候选路径映射回来源内容及原文。
1. 核验每条关系的方向、时间、条件和状态。
1. 返回有证据支持的路径及未证实部分。

**完成标准：** 路径上的关键关系都有来源依据。

**必须防止：**

- 两跳连接被自动解释成因果。
- 从某主题不断扩散到全库。
- 使用范围外资料生成的关系解释。
- 用关系相似度替代事实核验。

图中没有找到关系时，应转向范围内的正文补查，或说明关系索引不足，而不是直接宣布“不存在关系”。

## 步骤 12D：结构化查询与 Text2SQL 路径

1. 确定查询对象和计数口径。
1. 优先使用已支持的过滤、排序、分组操作。
1. 复杂查询才由模型生成受约束查询。
1. 校验表、字段、只读性和用户范围。
1. 执行并限制时间和结果规模。
1. 核对结果是否符合用户问题。

**完成标准：** 返回经过实际计算的结果及口径。

特别注意：“某主题共有多少视频”需要先得到主题匹配集合，再统计；不能统计向量检索返回的候选数量来代替总数。

## 步骤 12E：跨篇问答中的集合综合

1. 通过主题关联和总结检索层检索确定待分析集合；“收藏夹中的 RAG 教程有哪些学习要点”先找出相关教程，再围绕学习要点综合，而非直接对全库字幕做一次 top-k。
1. 根据本轮问题确定提取结构，优先读取每篇已有总结中的相关内容；在预算内逐篇或分批处理，不默认把所有长总结一次输入模型。
1. 临时提取要点、比较维度及内容来源，按主题或问题维度分组；不新增常驻的观点／要点文件或索引表。
1. 合并重复观点，保留分歧和少数意见。总结足以回答的概括直接基于总结形成；涉及精确数字、原话、关键条件或来源冲突时，只针对这些缺口检索字幕核实。
1. 直接生成 AI 问答中的学习要点、比较或综合答案，附所用内容引用；用户无需打开每篇总结或证据层才能得到综合结果。
1. 记录已处理、失败及未处理内容；要求覆盖整个集合时检查处理范围，不能用有限候选数量代替全量覆盖。

不同任务采用不同提取结构：

- 决策总结：背景、候选方案、条件、决定、理由、未决项。
- 方案比较：目标、步骤、资源、适用条件、风险。
- 行动建议：用户目标、可借鉴方法、反例、约束、待验证假设。
- 全局主题概览：主题分布、代表内容、交叉关系、覆盖缺口。

批次间按同一问题维度合并，临时要点均关联来源；不得在合并中丢弃少数意见或失败内容。问答答案按既有会话规则保存，临时提取结构不升级为常驻主题分析产物。

# 六、从检索结果到最终交付

## 步骤 13：逐答复点判断证据是否足够

统一各路径的内容集合、总结／原文依据、关系路径和真实计算结果，标明来源及版本。程序先作共用检查 C1–C5，再把真实材料与答复点交给 P-EVIDENCE。

评分采用执行契约 §6 的 0／1／2：无支持、部分支持、足以支持。完整回答要求全部必答点为 2，原话核验必须原文，笔记中的事实须明确归因、引用有效、范围合法且关键冲突已处理；概括可以依据总结。不用检索相似度或总结强度替代这一判断。

至少一个点足够时允许部分回答并列缺口；还有材料且预算允许则定向补查。结构化计数由程序核验去重和覆盖；语义计数只有目标范围处理完成、未知和失败为零才给完整总数。评分含依据 ID 和短引文，程序校验 ID／版本／位置，模型语义判断本身仍需留出集盲评。

## 步骤 14：决定补查、澄清、降级或结束

| **当前情况** | **下一步** |
| --- | --- |
| 问题已充分覆盖 | 进入结果生成 |
| 某个子问题缺证据 | 只针对该子问题补查 |
| 实体或范围有关键歧义 | 向用户澄清 |
| 图索引不足 | 使用正文核实直接关系，标明图覆盖不足 |
| 索引部分失败 | 返回已处理范围及未处理项 |
| 证据互相矛盾 | 保留冲突，必要时检查条件和时间 |
| 达到时间或费用限制 | 保存进度并返回部分结果 |
| 仍无可靠依据 | 明确说明无法回答或无法确认 |

所有补查沿用原始范围和执行契约预算。P-RESPOND 同时提出缺口与动作，程序校验后执行，不另调计划模型；最多补查轮数与调用上限不由模型自行放宽。没找到相关内容、找到但材料不含答案、原文不可用、索引／服务失败分别表述。未经用户允许的模型或外发路径不能成为自动降级目标。

## 步骤 15：按任务生成结果

| **任务** | **结果应包含** |
| --- | --- |
| 找内容 | 标题、作者、链接、匹配原因和必要候选差异 |
| 枚举 | 去重后的列表、筛选条件、覆盖状态、分页或继续检查入口 |
| 解释 | 直接回答、关键条件、原文引用 |
| 决策总结 | 提案与决定区分、依据、时间变化、未决项 |
| 比较 | 统一维度、各自证据、差异和不可比较项 |
| 关系探索 | 关系路径、逐边依据、限定条件和不确定部分 |
| 行动建议 | 用户约束、建议步骤、替代方案、证据、假设和验证动作 |

行动建议尤其要区分：

- 来源材料明确说了什么；
- 用户提供了什么条件；
- 系统据此推导了什么建议。

推荐不自动变成整理、删除、移动或其他写入操作。需要执行归类时，交给独立操作流程处理明确的 Content 集合。

## 步骤 16：结果校验并交付

交付前进行可编程检查和必要的语义检查：

1. 对实际答案及引用执行共用检查 C1–C5，检查生成后是否引入不存在的引用 ID 或位置。
1. 核实“全部”“最终决定”等措辞、明确要求是否遗漏，以及压缩是否改变条件。
1. 分别标明依据总结或原文；不为总结句子虚构时间坐标。

检查失败时，优先修正具体问题；无法修复时，返回受限结果，而不是掩盖失败。

同时保存本轮问题、执行计划、范围、结果集合、引用、关键中间状态和费用信息。用户可见的是简洁的处理说明，例如“已检查所选 24 份资料，2 份仅有摘要”；开发者可以查看更详细的执行记录。

# 七、持续维护与评测流程

## 步骤 17：处理内容变化

| **变化** | **更新范围** |
| --- | --- |
| 正文修改 | 受影响片段、内容卡、向量、主题和相关关系 |
| 仅展示简介修改 | 展示字段及相关词法索引；不必无条件重建全部向量 |
| 标签或收藏夹改变 | 集合关系与范围缓存 |
| 删除内容 | 从有效查询中排除，并使相关派生结果失效 |
| 经批准变更固定主题词表或定义 | 词表版本、别名、内容关联和集合视图；AI 不自行合并或拆分规范词表 |
| embedding 模型变化 | 构建新索引版本，验证后切换 |
| 重排模型变化 | 重跑相关评测，通常不重建 embedding |

更新任务需支持断点恢复和重复执行不产生重复数据。遵循 AI 问答 PRD：新身份启用后仅查询新索引已处理内容，显示真实覆盖，不混入旧身份结果。停用索引保留 14 天；切回时仅复用身份与文本匹配的向量，重新启用取消待删，活跃索引不按期限删除。旧版本用于符合条件的切回或回退，不是新索引缺项时的隐式补集。

## 步骤 18：运行分层评测，决定是否发布

评测分为两组。

**组件评测：**

- 清洗是否破坏事实；
- 分块是否保留证据；
- 主题分类是否正确；
- 实体合并和关系抽取是否可靠；
- 路由是否选对计划；
- 召回、重排和引用映射是否有效。

**用户任务评测：**

- 能否找到具体帖子；
- 是否漏掉应列出的内容；
- 是否把提案当成决定；
- 是否准确比较不同方案；
- 关系解释是否过度推断；
- 建议是否符合用户条件；
- 降级是否诚实且仍有帮助。

本轮确认的检索分层还需专项验收：宽泛提问优先使用总结检索层且能跨篇综合；原话、数字和说话者问题能定位字幕；主题未命中时可补检内容并按需下钻；用户没有手动标签也能依靠范围内 AI 主题关联查找资料。上述项目为目标验收项，当前均待实现后验证，不代表已通过。

固定调参集和留出集，按任务类型报告结果。自动指标、模型裁判和人工复核分别记录；不能用一个平均总分掩盖越界、错引和虚构决定。

| 验收对象 | 样例与可核对证据 |
|---|---|
| 主题分类 | 只输出本稿 32 项规范 ID，主次与多主题均有依据；体育／健身统一为运动健身，知识／娱乐等退役类不再输出，Vlog 已恢复为 T32；真正交叉不因相近而被拒绝，RAG 等可作内部检索细词但不生成规范主题 |
| 图精简与路由 | 检查图字段不含总结／字幕／逐篇描述；元数据查询、分类计数、指定篇概览、语义查找、原文定位和跨篇比较分别命中步骤 11 的路径；自然语言理解后分类计数由数据库计算，结构化筛选可完全跳过生成模型 |
| 总结检索层召回 | 同义问法、长短视频并存、无用户标签；分别报告篇级 Recall@k 与候选去重 |
| 字幕定位 | 原话、数字、否定、条件及相邻片段；核对原始位置、上下文完整性和引用正确性 |
| 图覆盖、枚举与统计 | 固定收藏夹金标准内容 ID；检查节点／主题加工覆盖、版本、去重、多主题重叠、AND／OR、未知项，以及图完整时不重复逐篇调用模型 |
| 跨篇问答 | 重复、冲突、少数意见及缺失材料；核对要点遗漏、条件和逐项来源 |
| 生命周期与费用 | 范围变更、删除、模型切换、失败恢复；保存实际调用次数、Token、费用与 p95 耗时 |

题集、通过门槛与初始预算按执行契约 §10–12：区分调参／留出集、阻断错误、细词状态与强度×材料等级验证；尚无真实运行结果，文档静态检查不代表这些质量标准已通过。
