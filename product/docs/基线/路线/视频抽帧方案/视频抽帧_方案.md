## 一、要解决的问题

产品的信息通道只有文字：字幕命中即跳过 ASR（`asr_skipped_reason="subtitle_hit"`），链路止于 `transcript → chunks → summary`。当画面自带独立信息——幻灯片、代码、表格、示意图、纯画面演示——这条通道无法把它带回来，文字轨越完整，画面丢得越干净。

要补的不是「会不会看图」，而是**什么情况下值得看、看哪几帧、每帧给多大、一共几张**。这四个问题既决定成本，也决定内容会不会缺失。

取舍原则：**本地不花钱的做满，云端要花钱的按需限量，判不准就降级，绝不阻塞任务。**

## 二、边界

- 「图像识别」= 抽帧 → 拼图 → 多模态模型看图。不含独立视觉服务、向量检索、本地视觉模型。
- 画面结论不能当原话引用，只能写「画面显示…」；要引用台词必须走 OCR。
- 不上传原视频，外传的只有拼图，且受张数上限约束。

## 三、处理流程

```text
闸 1 字幕命中 → 跳过 ASR（已有，只需量命中率）
闸 0 探针     → 容器头 + 每秒 1 帧变化分 + 语音覆盖，5–10 秒
闸 2 送不送   → 静止度 × 语音覆盖
闸 3 送哪帧   → 切点（尖峰）+ 积分（长镜头）
闸 4 每帧多大 → 档位 1/k + 最小可读格
闸 5 几张     → 240 秒/张，超了先并快剪
→ 拼图 → 并入本轮总结请求 → 归档
```

在线视频没有本地容器头，闸 0 之前必须先把片源下到本地（见 4.8）；本地文件直接读盘。

任何一道闸判「不送」，后面一分钱、一秒 CPU 都不花。

闸 2 是整套流程的判据核心。参考实现没有这一层——它假设「用户点了就是想看图」；本产品是「读完写一篇」，必须自己判断值不值：

| | 静止帧占比高 | 静止帧占比低 |
|---|---|---|
| **语音覆盖低** | 无声演示、录屏 → 送 | 动画、纯画面 → 送 1–2 张定性 |
| **语音覆盖正常** | 讲解 + 幻灯片 → 送 | 口播、采访 → 不送 |

两个维度都是免费算出来的：静止度来自探针的逐秒变化分，语音覆盖来自已有 transcript，不额外跑模型、不问用户。

## 四、算法与判据

### 4.1 单帧变化分（0–255）

缩到 **64×36** 网格，HSV 三通道加权差：色相走环形距离、按饱和度降权（灰阶色相无意义），再加 `|ΔS|`、`|ΔV|`。12fps 逐帧计算。

抗误切三层：

- **运动补偿 mc**，搜索半径 4 格。整屏平移 8 格时，`radius=2` 误报 194 分，`radius=4` 只有 5 分；换镜头时两边都高。
- **背景模型**：最近 6 帧的稳定背景。
- **外圈守卫 + 未来帧确认**：挡住前景运动造成的假台阶。

全黑帧按 0 质量跳过。

### 4.2 切点

主判据：`score ≥ 12`、`> 2.5 × 邻帧`、`mc ≥ 20`、距上一刀 `≥ 0.4s`。
补充出口：`score ≥ 6 && mc ≥ 60`（机位切换）、`score ≥ 80`（强台阶）。

### 4.3 长镜头采样：积分，不是固定刻度

每帧累加自己的分，累计到 `4 分 × 12fps × 3 秒 = 144` 记一个采样点并清零。动得快补得密，静止镜头一个点都不补。

固定 30 秒刻度只作最后兜底：静止 5 分钟会补 10 张几乎相同的帧（2220 token 白花），剧烈变化的 30 秒又只给 1 张（内容丢失）。

二级切分优先级：ASR 语义段（免费、最准）→ 硬字幕带变化（极低）→ 30 秒兜底。

**fps 口径**：以上阈值均按 12fps 标定。若改 fps，积分阈值按 `4 × fps × 3` 换算，平滑窗与背景窗按 `帧数 / 12 × fps` 折算，否则同一片源换 fps 会得到不同张数。

### 4.4 单帧价值分级

一格 = 一个镜头；格子边长 = 该处切点密度（1/1 … 1/8），按行 DP 装箱、裁到内容、铺满画布。

**最小可读格（本方案加严）**：PPT / 代码类片源不得低于 1/4 档（≈200×115）。参考实现是「可反复问」的产品，糊了能对某段高清重取；本产品一次读完写一篇，糊了就是永久糊。触底时合并相邻镜头或另开一张，不继续缩。

### 4.5 张数与画布

- 预算 **240 秒/张**：30 分钟 ≈ 8 张，2 小时 ≈ 30 张。超出时先合并快剪段——预算不够先砍快剪，不砍长镜头；12 张只作降级地板。
- 画布 **798×462**：798 宽正好 19 列（42px 对齐），800 会被 pad 到 812 = 19.3 列，白算一整列；462 = 450 + 12px 音轨带。单张 ≈ **222 token**。
- 音轨带 12px：画响度柱、静音灰块、切点刻度，吃行高余量，**不增加 token**。
- 格间 2px 缝、烧格号。**不烧时间码**——占像素、降可读性、不可检索。

### 4.6 硬字幕带

先验「信息在底部」，用行方差峰值定位条带，密采样后本地 OCR。输出独立字段 `screen_text[]`，带 `source="ocr_hardsub"` 与时间范围；**不写入 `Transcript`**，不参与 `asr_skipped_reason`。

模型转述会改写、漏字、编造，不能当原话；与转写冲突时两版都保留并标注差异，不自动择一。

### 4.7 探针

容器头（时长、fps、分辨率、有无音轨）+ 每秒 1 帧算变化分，输出 `ProbeResult`（含静止帧占比、切点粗估）。语音覆盖率由调用方注入，探针不跑 ASR。5–10 秒出结果，多数视频在这里就能定下来送不送。

### 4.8 取流与体积

视觉要视频轨，ASR 只要音频轨——这是两者唯一的结构差别。**生产链路的取流函数是 `bilibili.py:452 download_bilibili_audio`**（`link.py:708` 唯一调用点），它用 yt-dlp、`format="bestaudio/best"`（`:467`），取**最高码率**纯音频；`bilibili.py:361 fetch_video_audio_urls`（wbi `x/player/wbi/v2` 的 `dash.audio`）在生产链路**零调用**（仅测试引用），方案早期版本把它当现状是错的。

yt-dlp 的同一次 `extract_info` 已解析出全部 format，取视频轨道不需第二次请求；但视觉应新增独立取流函数（或给 `download_bilibili_audio` 加视频分支），低码率视频用 `worstvideo[height<=360]` 一类选择器，只要视频轨、不做音轨合并，省掉 ffmpeg merge 与带宽。

| 素材 | 取流方式 | 30 分钟片体积（量级） |
|---|---|---|
| 本地文件 | 直接读盘，不复制 | 0 |
| 在线视频 · ASR（现状） | yt-dlp `bestaudio/best`（最高码率） | 实测 26–61 MB |
| 在线视频 · 视觉（本方案） | yt-dlp `worstvideo[height<=360]`（仅视频轨） | 约 100 MB |
| 在线视频 · 若误用 `bestvideo` | 1080p 全码率 | 600 MB 以上 |

三点：

- **不需要原片清晰度。** 拼图单格 200×115 起步，360p 的源像素已经过剩；选高档只多花带宽，不提升可读性。
- **抽帧完成即删视频，不等任务终态。** 归档只留拼图与 `storyboard.json`；指纹缓存已存帧清单，重跑不需要视频本体。
- **探针省解码时间，不省带宽。** B站是分片 fMP4，没有本地容器头，闸 0 必须先下载再读；现状代码只解析 `duration`，分辨率与 fps 拿不到元数据。想省带宽只能按字节区间取片段，B站 m4s 多数没有可用索引，本轮不做。

### 4.9 磁盘与内存开销（实测）

| 项 | 现状（只有 ASR） | 加视觉 | 说明 |
|---|---|---|---|
| 任务期间临时文件 | 音频 26–61 MB（实测） | 音频 + 视频最低档，30 分钟片约 130 MB | 视频是音频的 3–4 倍 |
| 任务结束后临时文件 | 0（正常终态） | 0 | 抽帧完成即删，不挂到终态 |
| 归档新增 | — | 拼图约 0.3 MB/张 + `storyboard.json` 数十 KB | 30 分钟片 3–4 MB |
| 进程常驻内存 | — | +21 MB | PyAV + numpy 库，一次性 |
| 解码峰值 | — | +27 MB（640×360），合计约 71 MB | 与片长无关，只随分辨率变 |

实测条件：本机 `.venv`（Python 3.12 / PyAV 18.1.0 / numpy 2.5.2），640×360 mpeg4、900 帧合成片源。导入 0.85 s；解码 **7.4 ms/帧**（含 rgb24 转换与 64×36 降采样）。按 25 fps 推算，30 分钟片全片扫描约 5.5 分钟，与 §三 的 4–6 分钟一致。真实 H.264 源会有出入，R1 用 5 条真实片源复测。

结论：**内存不是约束**（+50 MB 量级）；磁盘才是，且只要按时删就与音频同量级。若把解码放进子进程（与现有 ASR runtime 同构，避免抢主进程 CPU），峰值变成再一个约 70 MB 的进程，仍可忽略。

## 六、实施轮次

顺序按成本排：先出数字（零 token），再出图（人工可验），最后接模型。做反了会把 token 花在调参上。

| 轮次 | 交付 | 主要落点 | 验收 |
|---|---|---|---|
| R1 | 抽帧地基 + 探针（只出数字，不出图） | 新增 `app/adapters/vision/`：`probe.py`、`frames.py`、`score.py`、`fingerprint.py`；临时目录前缀 `knowledge-vision-`，启动时清扫同前缀残留 | 5 条片源（口播 / PPT / 纯音乐 / 代码录制 / 快剪 PV）输出探针 JSON；抽帧结束临时目录为空；不产图、不调模型（视觉能力探测除外） |
| R2 | 送不送判定 | `decide.py` → `metadata["vision_decision"]` | 5 条判定与人工预期一致；`skip` 不解码、不出图 |
| R3 | 逐帧打分、切点、积分 | `score.py`、`cuts.py` | 12fps 与 15fps 切点数一致（±1 帧）；静止片 0 切点 0 采样；< 0.5s/刀 的召回与人工标注一致 |
| R4 | 档位排布 + 张数预算 | `tiers.py`、`pack.py`、`sheet.py` | 30 分钟 PPT ≤ 8 张且最小格 ≥ 200×115；90 秒 PV ≤ 3 张且不丢刀；单图 ≈ 222 token |
| R5 | 硬字幕 OCR | `subtitle_band.py` → `screen_text[]` | 与转写并存且可区分；不进转写文本；无硬字幕不产字段 |
| R6 | 接入总结 + 降级 | 见下 | 注入解码异常时任务仍完成；阶段轴 6 段正确高亮；`skip` 耗时 ≈ 0 |
| R7 | 归档落盘 + 指纹缓存 | `archive/writer.py`、`store.py`（**新建**指纹表 + schema 迁移，含命中逻辑；现无此表） | 重跑命中 ≤ 2 秒且不重解码；全路径 ≤ 259 字符 |

## 七、不做

| 不做 | 理由 |
|---|---|
| 逐帧 VLM 描述 | 成本是拼图的几十倍；产品只写一篇，不需要逐帧说明 |
| CLIP / 向量索引 | 那是「反复问同一部片」的形态，本产品是「读完写一篇」，错配 |
| 本地视觉模型 | 本机 torch 是 CPU 版，跑不动；云更便宜 |
| 全量送图 | 省不下几块钱，但每条多花 5–20 分钟本地时间 |
| 时间码烧进画面 | 占像素、降可读性、不可检索；用 `storyboard.json` 映射 |
| 硬字幕冒充字幕轨 | 转述与 OCR 都不能当原话，必须单列 |
| 二次补图（对某段高清重取） | 参考实现有 `video_zoom`；本轮不纳入，记为待定 |
