# 分 PRD｜内容接入

> v5.1 · 2026-10-14 · 状态：需求草案。PI 编号在本册内唯一。当前代码、目标行为与未决内容以段落说明区分。

## 1. 前置引用

本模块属于《多源内容知识库》总 PRD 的「内容接入」模块。产品整体目标、目标用户与全局约束以 [总 PRD](00_总PRD.md) 为准；本文只规定内容接入的局部价值、范围与规则。

调研依据可从[平台登录与授权搜索参考](../../过程/调研/平台登录与授权方案_搜索参考.md)追溯；它提供候选实现路线，具体需求仍以本文为准。
社交内容接入的背景研究见[主动导入与证据追溯专题](../../过程/调研/专题研究/social-content-knowledge-base/FINDINGS.md)。

## 2. 本模块价值与局部痛点

**模块价值**：让用户在创建处理任务前看清输入来源、材料可得性与提交范围，降低把不可处理内容或超出预期的集合误提交的风险。

**局部痛点**：链接、平台集合、本地文件和文字输入的可读内容、授权状态与可处理范围并不相同。仅识别出平台不代表已经取得正文；若预检结果不清楚，用户无法判断能否继续、会处理哪些条目，以及确认前是否已经产生任务。

## 3. 本模块目标与衡量指标

**目标**：用户在花费处理时间前，能够判断输入对象、材料可得性和提交范围。至少一种真实可读取的单条来源完成预检与确认；取消不建单。集合能力按已验证范围单独验收。

**衡量指标**：预检可提交率＝可提交候选数/有效输入数；提交一致性＝实际建单数/用户确认的有效候选数。分别按平台和对象类型记录，当前均无基线。

## 4. 本模块 Non-Goal

本期不把平台识别等同于正文读取；S1 不承诺私密集合访问、持续同步或全部本地格式。

## 5. 本模块专属关键使用场景

1. 用户在平台或网页看到想保存的内容时，打开内容接入并提交链接或选择本地材料，先查看预检结果。
2. 查询结果同时包含可读、重复或受限条目时，用户在确认提交前逐项选择需要处理的内容和归类。
3. 来源要求重新登录或材料不可读时，用户在提交前看到原因，决定去设置、修改输入或结束本次查询。

## 6. 本模块用户故事

1. 作为正在收藏内容的用户，我希望先看到输入的来源、可读材料和重复状态，以便判断是否值得提交处理。
2. 作为需要从集合中挑选内容的用户，我希望逐项选择候选并在确认前查看处理范围，以便只创建自己确认的任务。
3. 作为遇到受限来源的用户，我希望看到明确原因和下一步，以便修复输入或授权后再继续。

## 7. 功能规则、交互流程、验收标准与非功能需求

### 7.1 范围与交互流程

**主流程**：输入 → 逐项识别 → 预检材料/授权/重复 → 候选选择与可选归类 → 用户确认 → ImportBatch/Job。取消路径终止于查询，不产生持久 Job。

**B 站扫描候选导入（2026-11-09 修订）**：收藏夹、UP 主、合集、稍后再看扫描只取得候选基础信息。用户勾选并点击导入后直接创建任务，不再逐条查询字幕或下载音频，也不受链接查询的单次 50 条及确认 100 条限制。任务轮到执行时才获取材料、转写和总结；等待时间不计入整批链接查询的 180 秒超时。单条失败记录在该任务，后续任务继续；取消后重试仍先排队。多 P 在任务读取来源时拆成独立任务，继承标签与收藏夹。普通粘贴链接查询及知乎正文读取维持原流程。实施与验证见[本轮记录](../../过程/2026-11/11-09_扫描候选先建单后取材_实施记录.md)。


| 层级 | 用户可得到什么 | 不能由此推断 |
|---|---|---|
| P0 来源识别 | URL/文件的来源平台、对象类型和规范地址 | 能读取正文、能登录 |
| P1 查询预览 | 标题/作者/封面等确实取得的元信息，材料可得性 | 能完整转写或总结 |
| P2 单条导入 | 用户确认后可创建任务，取得可处理材料 | 能扫描集合或自动同步 |
| P3 集合扫描 | 在明确范围内列出候选，用户逐条选择 | 能读取私密收藏或全部历史 |
| P4 增量同步 | 按授权、频率和游标发现新内容 | 其他平台也具有同等能力 |

S1 不把 P4 放进范围。当前 B 站单条/部分候选与本地入口有代码基础；小红书、抖音、知乎、YouTube、普通网页和本地格式按真实样本确认 P0～P3。文件选择器当前可见 TXT、MD、SRT、VTT；DOCX/PDF 不能因思维导图有目标描述就说已支持。平台登录会话和凭证处理见 [设置](04_设置_PRD.md)。

### 7.2 页面交互与信息呈现

| 入口/字段 | 默认与展示 | 操作/边界 |
|---|---|---|
| 平台链接/本地识别 | 双入口，显示实际支持的来源和格式 | 输入为空时查询不可继续 |
| 候选列表 | 标题、来源、对象类型、可读性、重复提示 | 逐项勾选；全选只作用于当前结果 |
| 确认区 | 总数、已选数、标签与收藏夹 | 点击确认才建单；关闭/取消不建单 |

内容接入首页有两个平等入口：**平台链接**与**本地识别**。链接支持粘贴一条或多条；本地识别提供文件选择、路径和文本输入。两个入口共用“查询 → 预检/候选 → 统一确认 → 创建任务”的后半段。默认先呈现当前入口的输入和明确的“查询”按钮，输入为空时不能继续。

| 页面状态 | 用户看到的内容 | 可执行动作 |
|---|---|---|
| 空白 | 输入提示、已支持格式/来源的真实清单、设置依赖提示 | 输入/选文件；不出现虚假的处理结果 |
| 查询中 | 来源识别与扫描进度、已获得候选数量、停止入口 | 停止当前查询；已取得候选保留可检查 |
| 可确认 | 每项独立选择框、来源/标题/类型/可读性/重复说明；底部“总数/已选数” | 搜索、全选当前结果、逐条取消、选标签/收藏夹、确认 |
| 不能提交 | 登录过期、来源被删、材料不可读、平台受限、格式不支持等具体原因 | 去设置、改链接、换可用材料或关闭；不显示可点的提交动作 |
| 提交后 | 成功、跳过、失败数量及任务入口；非阻塞运行提示 | 留在本页继续查询，或前往任务 |

选择标签可以为空；标签与一个或多个收藏夹的选择互不影响。新建标签在候选区置顶、高亮、默认选中，取消选择不建立内容关系。查询窗口关闭或取消确认，不创建任务，也不把临时选择写入知识库。

### 7.3 功能规则

下表只写触发与产品行为；验收集中在第 7.5 节。事实、约束、触发、推论与计算按规则性质区分，不为凑类别虚构公式。

| ID | 规则与可见行为 |
|---|---|
| PI-01 | 用户点“查询”时分别校验每条输入；空值、格式错误、无法解析短链按项返回原因 |
| PI-02 | 预检分别显示来源识别、材料可得、授权与重复状态；未知字段留空而非编造 |
| PI-03 | 集合查询仅扫描识别出的对象及用户允许的范围；UP 主、合集、收藏夹不能互相扩大范围 |
| PI-04 | 候选每项可独立选择；搜索和“全选”仅作用于当前结果，显示总数与已选数 |
| PI-05 | 同次提交相同规范来源合并；历史已有内容提供“查看已有/再次导入”明示 |
| PI-06 | 用户确认后才创建 ImportBatch/Job；取消、关闭确认窗口不创建任何 Job |
| PI-07 | 登录过期、验证码、HTTP 受限和平台不可达分开提示；需要人工操作时停止自动请求 |
| PI-08 | 批次归类选择写入对应内容关系；标签/收藏夹可各自为空或多选 |
| PI-09 | 一批中个别项预检失败不抹掉可提交项；结果分别列成功/跳过/失败 |
| PI-10 | 每个平台只公开经真实样本验证的能力层级与对象类型 |

PI-05 的“历史再次导入创建新内容”来自当前信息对象图，区别于“编辑已有总结版本”。历史重复的默认按钮文案及是否预先选中再次导入仍待产品决定；**保守表现**是默认提示已有内容，不静默创建第二个 Content。

**阶段归属**：S1 核对 PI-01、PI-02、PI-05～PI-09 的单条与混合批次路径；S2 核对 PI-03、PI-04 的集合边界和选择；PI-10 是每次开放新平台能力时都必须满足的发布条件。当前代码已有的候选界面也应按 S2 场景复测，而不因“已有按钮”判为验收通过。

### 7.4 异常处理、非功能需求与数据边界

**质量约束**：查询耗时和平台请求量按来源记录；页面在正常/窄窗都要辨认候选与不可读项；账号秘密不得进入候选、日志或模型输入。

- 短链跳转失败、原文删除、无权查看、平台限流应保留原始输入和已获得的来源身份，不将失败推成“内容不存在”。
- 集合扫描必须有平台级请求节奏和终止条件；具体页数/候选上限尚无真实基线，S2 开始前应在 B 站样本上确定，不能默认无限扫描。
- 获取网页正文、图片或媒体时把实际取得的材料交给 AI 文案（当前发文本；后续可能增加图像识别，抽帧拼图随文发送）；“图文链接可识别”不意味着图片已 OCR 或视觉理解。
- 平台会话不得进入候选导出、普通错误日志或模型输入。同步阶段的账号连接不得以用户粘贴 Cookie 为主流程。

### 7.5 验收标准

| 覆盖需求 | Given／When／Then 验收 |
|---|---|
| PI-01 | 给定空值、错误短链与可读链接，当逐项查询，则只把可读项列为可提交候选，Job 数仍为零。 |
| PI-05/06 | 给定同次两个等价链接和一个历史已导入链接，当确认再次导入，则同次只建一项，历史新 Content 保留旧项并有数字后缀。 |
| PI-07 | 给定过期会话，当查询，则显示重新登录路径，不连续自动请求或假称可处理。 |

**逐条观察点**：下表与第 6 章需求一一对应，复用上面的场景前提执行。

| ID | 可观察结果 |
|---|---|
| PI-01 | 给可读链接、错误链接和空输入，只有可读项进入候选；无任务产生 |
| PI-02 | 一条只识别平台但正文不可得的链接不会显示“可完整总结” |
| PI-03 | 合集输入只列合集成员；超范围/限流中止并显示最后扫描位置与原因 |
| PI-04 | 搜索后全选、取消一项，确认页和最终提交数一致 |
| PI-05 | 同批两条等价链接只建一项；再次导入按新 Content 规则保留旧项并生成数字后缀 |
| PI-06 | 查询、切换候选或关闭弹窗后任务数不变；确认后任务数等于有效选择数 |
| PI-07 | 失效会话/风控样本不连续重试，页面指向重新登录或稍后处理 |
| PI-08 | 不选归类仍创建任务并在成功后进入总库；选标签不自动生成收藏夹 |
| PI-09 | 混合批次可单独提交可读项，失败项保留原输入与原因供修改 |
| PI-10 | 平台仅 P0/P1 可用时，页面不出现 P2/P3/P4 的可点击入口 |

验收记录须写明素材/任务 ID、客户端版本、运行环境、自动检查结果与人工观察结果。页面外观、理解质量和真实平台授权须人工核对；未做的项标“待人工验收”，不能因源码可见直接标“通过”。

## 8. 风险与开放问题

### 8.1 依赖、风险与开放问题

依赖[任务](02_任务_PRD.md)的建单与请求预算、[知识库](03_知识库_PRD.md) 的重复与归类规则、[设置](04_设置_PRD.md) 的授权状态。记录“输入数、成功预检数、可提交数、确认提交数、实际建任务数”和按平台/对象分组的失败原因，不将识别成功率误当处理成功率。

**待决**：集合默认扫描上限、历史重复按钮默认选项、更多本地格式的引入顺序。负责人为个人开发者；决定前按上述保守规则运行。首轮验收素材至少覆盖单条可读 B 站链接、集合边界、等价重复链接、受限来源、本地文本和一次混合批次，按 PI 编号记录自动与人工结果。

**决策边界**：集合扫描上限、历史重复默认按钮和新增本地格式顺序由个人开发者在 S2 或对应开放前决定。
