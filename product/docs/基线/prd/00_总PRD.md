## 1. 问题陈述

### 1.1 问题本身

一位准备转岗的学习者，上周在 B 站收藏了教程，在小红书收藏了经验帖，又把一篇网页文章留在浏览器书签。今晚他想继续学习其中提到的“项目复盘方法”，却只记得观点，不记得标题和平台；几个收藏夹都要翻，找到视频后还要拖动进度条确认相关片段。手工复制要点并重新分类又会打断学习，于是他暂时放弃，下一次仍从搜索引擎重新找资料。

这是一条**待用户访谈核实的典型情境**，不是已观察到的用户记录。它揭示的共性问题是：内容可以被迅速收藏，却散在不同平台和格式里；用户难以判断长内容是否值得看、将其整理到自己的主题下，以及在产生新问题时找回并核对旧资料。即使得到 AI 总结或问答，若看不出使用了哪些原材料、答案依据在哪里，仍无法放心用于学习或工作。这里描述用户的任务和阻碍，不把“缺少知识库”当作问题本身。

### 1.2 问题影响

- **任务被打断**：查找、重看和重新摘录占据原本用于学习或工作的时间；找不到时可能重复搜索或直接放弃。
- **投入难以累积**：收藏数量增加，但旧资料没有形成可找回、可继续整理的个人积累。
- **判断与信任成本增加**：无法快速确定长内容的价值；无法核对总结和回答的出处时，用户还要自行回看原文，或承担误用的风险。

这些影响的发生频率和损失大小尚无证据。首轮研究应请潜在用户展示最近一次跨平台找回、判断视频价值或复用旧资料的实际经历，再记录用时、放弃点与情绪；不能把以上情境或下文目标值写成既有调研结论。

## 2. 目标群体与关键使用场景

### 2.1 目标群体

三类按**主要障碍**区分，可发生在同一个人身上。年龄与职业只用于招募不同样本，未经研究验证，不是产品使用限制。

| 群体         | 暂定访谈样本（年龄／职业）                           | 区分这一群体的主要障碍                        |
| ---------- | --------------------------------------- | ---------------------------------- |
| 学习者        | 18–35 岁的学生、备考者、转岗与持续学习的在职人士，并纳入其他年龄的学习者 | 面对长教程或大量参考资料，难以在投入完整阅读前判断内容结构与学习价值 |
| 跨平台收藏者     | 20–45 岁的知识工作者、研究人员、内容从业者和有长期兴趣主题的普通用户   | 记得主题或观点，却记不起保存平台、标题或具体收藏夹          |
| 收藏过多、难以归档者 | 22–50 岁的教师、产品／设计／咨询／运营人员、自由职业者等资料密集型使用者 | 保存速度快于整理速度，已有收藏和笔记难以形成可维护的个人资料库    |

划分的目的在于比较不同障碍是否都值得解决：学习者先检验“能否看懂”，跨平台收藏者先检验“能否找回”，归档困难者先检验“是否愿意持续整理”。不因年龄或职业相似就推断三类需求相同。

### 2.2 关键使用场景

场景只写触发时刻和当时的资料条件；它们不重复定义人群，也不提前规定页面动作。

| 触发时刻       | 当时的资料条件            | 需要做的判断                                     |
| ---------- | ------------------ | ------------------------------------------ |
| 周末准备学习一门技能 | 收藏了一段较长视频，尚未完整观看   | 这段内容讲哪些知识点，是否值得投入时间，关键部分在哪里？               |
| 工作中想引用旧观点  | 同主题内容散落于视频、网页和图文收藏 | 曾看到的观点在哪份资料中，能否回到原内容核对？                    |
| 想整理积压的收藏   | 多个平台、多个收藏夹已有一批未读条目 | 哪些资料值得留下，怎样按自己的主题整理后仍找得到？                  |
| 要回答一个新问题   | 已有数份相关归档，观点可能不同    | 我的资料里有哪些依据，各自怎么说，有哪些不确定之处？此场景对应尚未开放的 AI 问答 |

### 2.3 MVP 用户故事

- 作为**准备学习新技能的学习者**，当我导入一条已收藏的长教程时，我希望看到依据实际字幕或正文生成的主题总览，并能从要点回到原内容，以便在完整观看前判断哪些部分值得学。
- 作为**在多个平台收藏资料的知识工作者**，当我只记得上周读到的一个观点时，我希望能按关键词找到已归档的网页、图文或视频，并打开来源核对，以便在当前工作中引用它。
- 作为**积压了许多未整理收藏的人**，当一条资料处理完成时，我希望把它放进自己命名的主题，并在隔天通过该主题重新打开，以便下一次使用时不用重新翻平台收藏夹。

**后续问答用户故事**：作为已归档多份“项目复盘”资料的学习者，当我想比较不同作者的做法时，我希望限定这批资料提问，看到每条结论所引用的原文，并能打开相应位置，以便决定哪种方法适合自己的项目。引用与范围验收见[AI 问答分 PRD](05_AI问答_PRD.md)；此能力当前未开放。

## 3. 市场背景与竞品分析

中长内容的 AI 总结已经不是空白市场：B 站自带的 AI 字幕、AI 总结和「视频笔记」把最基础的需求免费吃掉了，BibiGPT、bilinote 这类 SaaS 把它做成了订阅生意，bilibili-rag、BiliNote 等开源项目也把单平台路径走完了一轮。但这些方案的产出都停在它们自己的界面里——平台笔记不可导出、SaaS 结果存在自家云端、开源项目基本只认 B 站，小红书、抖音、知乎至今没有等价的笔记与导出能力。所以本产品不靠“总结得更好”取胜（那是在和免费功能比），而靠三件平台与 SaaS 都不愿做的事：把多个平台的收藏收进同一套本地目录、把总结变成能长期保存的文件、让三个月后的人还能按自己的主题找回来。总结是入口，归档与找回才是差异点。

### 3.3 平台原生能力（间接竞争：不是同类产品，但会吃掉同一块需求）

| 平台原生能力   | 已覆盖                               | 未覆盖                                                              | 对本产品的含义                                                 |
| -------- | --------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------- |
| B站「视频笔记」 | 时间戳绑定、跳回片段、多端云同步、汇总到「我的笔记本」、公开／私有 | **仅对知识区或 UP 主授权的视频开放**（娱乐、影视多为关闭）；**不支持原生导出**，只能逐条复制；检索限于笔记内的关键词 | “给 B 站视频记笔记”本身不构成卖点；能站住的只剩“平台上没有笔记入口的那些视频”＋“导出到本地可长期保存” |

- **判断**：平台原生功能是最容易被忽略的替代方案，也是用户最容易拿来回答“我不需要”的理由。任何“给某平台加笔记”的需求，必须先回答“平台自己已经有，你为什么还做”。
- **官方 AI 总结／AI 字幕**：B 站已在移动端与网页端提供 AI 字幕，部分视频提供 AI 总结。其入口位置、覆盖比例、能否导出均**未核实**；但方向上与 3.2 的独立产品重叠，且免费。**这是本产品最不该正面比的一块。**
- **不做的事**：不在本产品里复刻 B 站的笔记编辑器（公开笔记、评论互动、时间轴样式）。复刻即正面竞争，且随平台改版同步失效。
- **可站住的位置**（待调研验证，尚无数据）：① 未被授权开放笔记的视频；② 跨平台统一（小红书、抖音、知乎没有等价物）；③ 本地长期留存与导出；④ 不依赖平台是否开放入口。

### 3.4 浏览器插件（间接竞争）

形态不落地存储，只在页面内当场总结；零安装成本，是用户最可能先试的一类。

| 类别 | 已覆盖 | 未覆盖 | 对本产品的含义 |
|---|---|---|---|
| 页面内一键总结类扩展 | 打开即用、免装客户端、贴合当前视频上下文 | 结果留在会话里，不进个人归档；不跨平台聚合；随宿主页面改版失效 | 它抢的是“这一刻想知道讲了什么”，本产品抢的是“三个月后还想找回”。两者可并存，但**不要在总结质量上正面比较** |

> 具体插件名单未逐一核实（B 站相关扩展更替快）。补做时记录：插件名、安装量、能否导出、是否支持非 B 站来源。

### 3.5 不做任何事（廉价替代）

| 现状做法 | 成本 | 为什么它是最强对手 |
|---|---|---|
| 继续用平台收藏夹，需要时拖进度条、手动复制到备忘录 | 零安装、零学习、不交登录态 | 用户不需要被说服“值不值得换”，只需判断“换的成本是否低于现在的麻烦”。第 4 节的隔日找回率正是测这一点 |

**定位假设**：为跨平台收藏、学习长内容的个人用户，提供本地优先的“输入—理解—归档—找回”路径，并在资料可核对的前提下扩展问答。差异化不能仅写成“多源＋AI”；应让目标用户用同一批真实资料比较各方案的完成成本、可找回程度和信任感。

**“本地优先”的阶段属性**：“本地优先”是本产品在 S0–S2 阶段对平台授权与服务器成本的取舍，不是产品身份，也不构成远期承诺。产品身份是“输入—理解—归档—找回”这条路径本身；它最终由独立软件、插件还是托管服务承载，按 §10 的条件选择。因此§6.2 的非目标只约束当前 MVP，不预先否决任何远期分发形态。

## 4. 产品目标与成功指标

### 4.1 目标与北极星结果指标

**产品目标**：让用户把一条原本可能被遗忘的收藏转化为能够再次理解、找到并使用的资料。完整产品还应支持基于已归档资料提出问题并核对引用。

**探索型北极星结果指标：有效复用率。**&#x5728;真实学习或工作任务中，用户再次找到先前归档的资料，并用其中的信息完成一项判断、引用或学习任务，且能说清资料起了什么作用，才记为一次有效复用；只打开页面不计入。分母为开始首轮试用的 20 人，分子为第 14 天前至少发生一次有效复用的人数；未归档或失访均计为未复用，并单独报告原因。**首轮探索目标：≥50%（至少 10／20 人）**。这是为决定是否继续投入而设的目标线，不是当前实测数据；若实际招募不足 20 人，同时报告人数和个案，不宣称达到总体目标。

### 4.2 可观测过程指标

**首轮试用设计**：邀请 20 名符合第 2 节画像的用户，每类障碍至少覆盖 5 人；第 1 天带来自己真实保存的资料，第 7 天观察导入与找回，第 14 天访谈实际复用。以下目标值是**产品假设与继续投入的判断线**，不是历史基线、行业标准或已达成结果。每项同时报告分子、分母和失败原因。本机产品不以“注册用户”作分母。

| 指标       | 首轮目标值           | 口径与用途                                                                | 阶段        |
| -------- | --------------- | -------------------------------------------------------------------- | --------- |
| 七日多源归档率  | ≥40%（至少 8／20 人） | 第 7 天前成功归档至少三条、且来自至少两种来源的用户数／开始试用的用户数；检验多源收集是否真的发生                   | 当前 MVP    |
| 隔日找回率    | ≥60%            | 归档隔天及以后，在不提示平台和标题的情况下，通过搜索或分类找到指定旧资料的用户数／参加该找回任务且有已归档资料的用户数；观察资料能否找回 | 当前 MVP    |
| 总览辅助判断率  | ≥70%            | 看过基于可读材料生成的总览后，能说出“继续看或跳过”及理由，并在原内容定位至少一处依据的人数／参加该任务的人数；检验总览是否有用且可信  | 当前 MVP    |
| 问答有依据完成率 | 试开放探索目标 ≥60%    | 问答正式开放后，用户用自己归档的资料提出真实问题，得到可核对引用、回源后认为回答帮助完成任务的人数／参加问答任务的人数          | 问答开放后另行试用 |

这些指标先在**本机或经用户知情的试用记录**中采集，不默认上传资料正文、问题内容或凭证。第 14 天根据实际分布、失败原因和访谈结果调整目标，不能为“过线”事后改口径。任务处理耗时、模型成本和错误率属于各分 PRD 的功能质量与运行指标。

### 4.3 暂时不能量化的价值假设

用户可能因为“少花时间找资料”“看长视频前先掌握全貌”“整理积压收藏更轻松”而持续使用，也可能更在意隐私和可回查出处。MVP 应通过真实资料任务、隔日找回和简短访谈辨别哪种价值成立；不能在此预设减少了多少分钟或提高了多少学习效率。平台接入稳定性、模型费用和个人开发者维护成本是产品可持续条件，单独监测，不混入用户收益指标。

### 4.4 分发与运营指标口径

第 4.1～4.3 节是本机试用期的**验证口径**，不是运营口径：分母是试用者，结论靠访谈判定，无法自动采集，也不能用来衡量增长。分发与运营指标在分发形态确定后另行定义，至少覆盖三项——交付完成率（装得上、配得通）、二次使用率（14 天回访）、付费转化与单位成本（单条处理成本对最低档年费）。两套口径不互相替代，也不把试用期数据当作市场结论。

## 5. 整体方案与 MVP 实验

### 5.1 整体运作路径

**输入**用户选择的链接或本地资料 → **识别与理解**实际可取得的正文、字幕等材料并给出有边界的总览 → **储存与组织**来源、内容和用户自己的分类 → **找回与复用**按主题再次阅读；在 AI 问答开放后，用户还可在明确范围内提问并回到引用资料。

这个路径描述产品怎样帮助用户完成一件事，不规定内部任务对象、数据库结构或页面布局。用户必须能分辨“只保存了入口”“取得了材料”“形成了可读归档”这几种不同结果。

### 5.2 当前 MVP 验证什么

最小实验选择一条可读取的真实内容：用户主动导入 → 看总览并核对一个要点 → 按自己的主题归档 → 隔天在不提示平台的条件下找回。它检验用户是否愿意把收藏转成可复用资料。AI 问答是完整产品的下一项复用能力，当前仅保留锁定入口；不得以导入和总结的成功推断问答价值已经成立。

## 6. 范围与非目标

### 6.1 按能力划分的范围

| 方面    | 当前 MVP 关注点                 | 后续能力                  |
| ----- | -------------------------- | --------------------- |
| 输入    | 用户主动导入已验证可读的来源和本地资料        | 逐来源扩大集合处理与自动发现        |
| 识别与理解 | 对实际取得的材料生成可回查的总览；材料不足时明确告知 | 图文 OCR、更多内容类型及更深的理解   |
| 储存与组织 | 成功内容进入本地知识库，可分类、找回和核对来源    | 大规模整理、跨内容关联和长期备份体验    |
| 问答    | 当前锁定，不读取资料或调用模型            | 在索引覆盖、范围、引用和隐私验收后逐步开放 |

### 6.2 当前明确不做

- 不把“识别出平台或标题”当成已读取、理解完整内容。
- 不在当前 MVP 开放知识库 AI 问答、全平台自动同步或无界扫描收藏。
- 不做移动端、云端多人协作、自动发表内容或企业权限体系。
- 不生成无材料依据的确定结论，也不绕过平台访问限制。

以上四条只约束当前 MVP。移动端、云端与托管形态在 §10 的远期路线中按条件另行判断——本节既不永久排除它们，也不提前承诺。范围外需求要先证明它解决了目标用户的真实障碍，再调整本总 PRD 与对应分册，不能因已有按钮或技术可行就默认为已承诺。

## 7. 产品风险与应对

风险在总 PRD 中只保留会影响**用户价值是否成立、资料可信度或产品能否持续提供服务**的事项。具体平台错误、任务恢复和模型异常的处理规则由分 PRD 承接。

| 风险                  | 触发信号                                              | 应对与取舍                                                              |
| ------------------- | ------------------------------------------------- | ------------------------------------------------------------------ |
| 用户仍习惯只收藏、不再回来使用     | 七日多源归档率达标，但隔日找回和有效复用明显低于第 4 节目标；访谈中说不出再次使用的任务     | 优先改进找回入口、分类负担和回访引导；不以继续扩大来源数量掩盖复用不足                                |
| 来源受限导致“多源”价值落空      | 目标用户真实收藏中，常用来源只能识别标题或反复无法读取；完整材料覆盖不足以完成场景任务       | 按来源公布可读边界；优先验证最常见的可读路径，受限来源保留入口和失败说明，不承诺全平台通用                      |
| AI 总结或问答形成无依据的信任    | 试用者无法从关键结论回到材料，或将未读取内容误当成已总结内容                    | 把材料范围和引用核对作为展示条件；无依据时明确说明不足，问答维持锁定直到引用与克制验收通过                      |
| 私人资料与平台凭证泄露         | 诊断、导出、模型请求或日志出现不该外发的正文、问题或凭证                      | 本地优先，外部处理前说明材料类别；对秘密和导出做脱敏检查，发现泄露即停止相关路径并修复后复验                     |
| 单人维护成本高于用户价值        | 新来源适配、处理费用或故障修复持续挤占核心找回体验，首轮用户也未形成复用              | 收缩到已验证来源与单条闭环，记录每种来源的处理成本和维护负担，再决定是否扩展                             |
| 分发形态不可行（装不上、不敢交登录态） | 试用者认可产物，但不愿安装环境或不愿把平台登录状态交给软件；安装完成率长期低于一半         | 先用模板或宿主入口（插件／扩展）验证产物价值，独立软件后置；不靠说明书硬推安装                            |
| 竞品密集导致无差异           | 用户已在用 Cubox／Readwise／BibiGPT，且说不出本产品为什么值得换        | 差异化只落在“找回的具体动作＋来源可核对”上；不用增加平台数量或摘要数量代替差异化                          |
| 平台原生功能已覆盖同一需求       | 目标用户答“这个 B 站自带的笔记就能做”；试用者实际使用中从不打开本产品的笔记层，只把它当摘要把 | 不复刻平台编辑器（§3.3）；产品只保留“平台没入口／跨平台／可导出留存”三段；调研阶段先测“是否知道自己平台有这功能、为什么不用” |


风险判断需要同时看指标和用户原话；样本小不能因一次异常宣布产品失败，也不能因导入量增长而忽视信任与复用问题。

## 10. 远期目标与分发形态

### 10.1 远期目标

产品要分发出去，服务本人以外的用户。分发不等于是上云：本地、托管、宿主入口三种承载方式都可能成立，取决于条件而非偏好。因此本节只定条件与顺序，不定单一答案。

### 10.2 三个承载形态的共性

三条路不是三个产品，是同一内核换三个壳。它们共用四处接缝，换形态时只动后三处：

| 接缝          | 内容                     | 换形态时是否改  |
| ----------- | ---------------------- | -------- |
| A 内容对象与证据锚点 | 来源、正文、媒体、证据位置、版本       | 不改，冻结    |
| B 取数适配器     | 链接 → 统一内容对象；凭证改由入参注入   | 只换凭证来源   |
| C 理解服务      | ASR／OCR／LLM，本地与外部可互换   | 只换实现     |
| D 凭证仓库      | 本机安全存储／云 KMS／宿主 cookie | 三种形态各一实现 |

推论：宿主入口最省改动，因为它把接缝 D 外部化——用户的登录态不曾进入本程序。

### 10.3 承载形态与采用条件


| 形态              | 分发半径 | 主要代价             | 采用条件             |
| --------------- | ---- | ---------------- | ---------------- |
| 开源自建            | 小    | 装机门槛             | 需求成立但无付费意愿       |
| 独立软件（买断／赞助）     | 中    | 支持成本随用户线性上升      | 装机容忍度达标，且愿为维护付费  |
| 宿主入口（插件／扩展／MCP） | 大    | 受宿主规则与审核约束       | 用户不愿安装独立程序       |
| 托管服务            | 大    | 内容经手他人，合规与变动成本最重 | 出现订阅意愿，且单条成本可被覆盖 |

### 10.4 阶段与退出条件

S0 调研 → S1 模板上线 → S2 小范围真实使用 → S3 独立软件 → S4 分发形态。各阶段的退出条件与决策触发器以 `过程/2026-10/10-24_分发形态与远期路线_解决方案.md` 的 R4 为唯一正本，本节不复制阈值，避免两处口径不一致。

### 10.5 与本文其他章节的关系

§3 的“本地优先”是 S0–S2 的阶段取舍；§6.2 的非目标只约束当前 MVP；§4.4 的运营指标在本节确定形态后启用。本节描述条件，不授权任何代码实施。
