# 分 PRD｜设置

> v5.1 · 2026-10-14 · 状态：需求草案。SG 编号在本册内唯一。当前代码、目标行为与未决内容以段落说明区分。

## 1. 前置引用

本模块属于《多源内容知识库》总 PRD 的「设置」模块。产品整体目标、目标用户与全局约束以 [总 PRD](00_总PRD.md) 为准；本文只规定本机配置、数据管理与诊断规则。

## 2. 本模块价值与局部痛点

**模块价值**：让用户看懂平台、模型和存储配置的当前状态，知道配置会如何影响任务与数据，并能安全完成恢复和诊断。

**局部痛点**：设置跨平台连接、ASR、总结模型、存储和运维等多个区域。若状态、保存结果、外发路径或清理影响不明确，用户难以判断配置是否生效，也可能无法从失败任务返回原上下文或找回数据。

## 3. 本模块目标与衡量指标

**目标**：用户知道平台、模型与存储是否可用，什么材料会离开本机，配置失败后如何恢复。邀请试用前须演练备份恢复与秘密脱敏。

**衡量指标**：记录配置检查成功/失败类别、由配置页返回后的任务结果、备份/恢复与诊断脱敏结果；不收集凭证值。当前无基线。

## 4. 本模块 Non-Goal

本期不做多人账号、租户、云端账单或企业权限审批；本机配置检查成功不代表模型文案质量已通过。

## 5. 本模块专属关键使用场景

1. 用户首次安装后准备导入内容时，打开设置查看必需配置、选择总结路径并检查可用状态。
2. 任务因模型或平台配置缺失而停住时，用户从任务进入设置，修复并检查后回到原任务。
3. 用户准备清理数据、迁移目录或恢复备份时，先打开运维区查看影响范围和恢复结果。

## 6. 本模块用户故事

1. 作为首次配置本机环境的用户，我希望看到必需配置状态和检查结果，以便知道下一步该完成什么。
2. 作为从任务进入设置的用户，我希望保存并检查后回到原任务上下文，以便继续决定是否重试。
3. 作为备份或清理数据的用户，我希望先预览操作影响并检查秘密脱敏，以便安全管理本机资料。

## 7. 功能规则、交互流程、验收标准与非功能需求

### 7.1 范围与交互流程

**主流程**：从设置或任务/接入进入 → 看当前状态与缺项 → 修改配置 → 保存并检查 → 显示结果 → 返回来路。清理与恢复先预览影响再确认。

### 7.2 页面交互与信息呈现


设置页有“平台、ASR、总结、存储、运维”二级导航。桌面侧栏紧凑，窄窗时转成单行可横向滚动，不拆字。每个分区先显示状态、缺项和用户下一步，再显示高级字段。界面主题提供当前日间/夜间选择，变更后核心文字、状态和焦点仍可辨。

| 分区 | 首屏回答的问题 | 典型动作 |
|---|---|---|
| 平台 | 哪个账号已连接？本次能读单条还是集合？何时失效？ | B 站扫码/检查、重新登录、断开；其他平台只按已验证能力显示 |
| ASR | 当前使用本地还是外部转写？本地模型是否已安装？ | 选路径、下载/检查本地组件、测试外部配置 |
| 总结 | 哪个模型、模板和 Prompt 生效？内容会发送到哪里？ | 获取模型、保存/清除配置、查看 Prompt 保存状态 |
| 存储 | 内容保存到哪个本机目录？空间是否足够？ | 选择/保存归档目录，查看保留与迁移说明 |
| 运维 | 环境哪里出错、能否备份/恢复和安全清理？ | 系统自检、预览清理、备份、恢复与脱敏诊断 |

从接入或任务因缺配置跳入设置，应记住发起页面；保存并检查后返回该产品父级，不直接跳到无关首页。设置自身的分区切换不是新的产品页面层级。

### 7.3 功能规则

下表只写触发与产品行为；验收集中在第 7.5 节。事实、约束、触发、推论与计算按规则性质区分，不为凑类别虚构公式。

| ID | 规则与可见行为 |
|---|---|
| SG-01 | 平台连接区分未连接、已连接、过期、需人工验证、受限；只开放该平台已证实的动作。本版平台区只列 B站与小红书（`app.js` 的 `PLATFORM_LABELS`），检查入口也只覆盖这两家；知乎、抖音、微信公众号保留平台定义，但不进入设置页、不参与检查 |
| SG-02 | 登录会话仅保存在约定本机安全位置；页面、普通日志和备份说明不回显 Cookie/密钥 |
| SG-03 | ASR/总结的本地与外部路径分开选用；路径不可用时显示缺项，不自动改走另一外发方案 |
| SG-04 | 用户在设置中能看懂发送到外部模型的资料类型和目的；新任务按提交时配置快照执行 |
| SG-05 | 保存平台、模型、Prompt 与目录有可见结果；失败保留用户刚填内容并可重试 |
| SG-06 | 存储清理先预览对象和影响，再确认；任务记录清理与知识内容删除分开 |
| SG-07 | 备份包含能恢复知识对象的材料、来源、标签/收藏夹、版本和必要设置；恢复前提示覆盖范围 |
| SG-08 | 系统自检显示本机运行时、归档路径、模型组件、网络和密钥配置状态，提供可行下一步 |
| SG-09 | 诊断或反馈导出前脱敏并可预览；任务错误可按时间、阶段、错误类别关联 |
| SG-10 | 配置完成后返回原接入/任务上下文，不自动替用户重新提交 |

ASR 和总结配置的“检查成功”只说明服务或组件可用，不证明总结质量。真实模型调用、长视频费用与证据质量仍需在 [知识库](03_知识库_PRD.md) 的固定样本上验证。

**阶段归属**：S1 需验收 SG-01～SG-05、SG-08～SG-10，使已验证来源和模型能安全完成单条闭环；SG-06、SG-07 的清理/备份恢复必须在开放给身边试用者前完成目标机器验证。云端、多账号与计费仍属后续独立需求。

### 7.4 异常处理、非功能需求与数据边界

**质量约束**：凭证不回显、不进普通日志/诊断/导出/文案；保存失败保留输入；恢复先在隔离位置核验，窄窗设置仍可辨状态与主动作。

本地归档是当前默认，平台会话不迁到云端。原始媒体、字幕、缓存和失败中间材料可能有不同保留期限；清理前用户看到类别和实际数量。失败中间材料按当前产品对象规则保留 24 小时用于续跑，超过后重试从头处理。用户主动编辑的文案和知识归类是持久内容，不可按缓存策略误删。

若未来提供云端归档、多人共享或收费，需另定账号归属、跨设备冲突、删除请求、外发同意、费用和平台授权边界；本册不将其暗含为已支持。平台验证码或风控出现后转人工处理，设置页不提供自动规避控制。

- 首次设置时按真实使用顺序提示“先选择总结路径 → 检查可用 → 回到接入查询”；不要求用户在首次使用前填写所有高级项。
- B 站二维码过期要能重取；保存凭证失败要明确“未连接”，不能在 UI 中留下假绿色状态。
- 本地模型下载中断、磁盘不足、目录无权限和备份损坏各有独立原因与恢复动作。
- 目标窗口的日间/夜间、正常/窄宽状态要人工核对主按钮、警告和焦点可辨；具体像素值沿用已确认的现有视觉实现。

### 7.5 验收标准

| 覆盖需求 | Given／When／Then 验收 |
|---|---|
| SG-02/04 | 给定本地和外部两种模型配置，当分别提交并检查诊断导出，则任务路径可追溯且 Cookie/密钥不出现。 |
| SG-05/10 | 给定保存配置失败，当从任务进入设置，则保留输入和错误；修复后回到原任务筛选，不自动重跑。 |
| SG-06/07 | 给定备份和待清理任务，当预览、恢复与清理后，则知识对象关系可抽查，清任务不删除 Content。 |

**逐条观察点**：下表与第 6 章需求一一对应，复用上面的场景前提执行。

| ID | 可观察结果 |
|---|---|
| SG-01 | B 站有效/过期与非 B 站仅识别样本显示不同操作，不把平台图标当成功连接 |
| SG-02 | 检查设置、诊断、普通导出和模型输入，均不含秘密明文 |
| SG-03 | 断网、本地模型缺失、外部密钥失效三种样本均停在正确故障并给动作 |
| SG-04 | 改配置前后各提交一项，可分别追溯本地/外部选择，不把旧任务偷偷切路径 |
| SG-05 | 模拟写入失败/无权限目录，仍见输入和明确错误，不显示“已保存” |
| SG-06 | 清缓存、清任务、删内容各执行一次，影响范围符合说明，可恢复项可找回 |
| SG-07 | 在隔离位置恢复并抽查关系和版本；损坏备份不覆盖现有数据 |
| SG-08 | 人为缺失每类依赖一次，页面指出缺项而非笼统“系统异常” |
| SG-09 | 一条失败任务能定位故障，输出无 Cookie、token、完整私密正文 |
| SG-10 | 从两种来路进入并返回，原输入/筛选仍在，重试需用户明确动作 |

验收记录须写明素材/任务 ID、客户端版本、运行环境、自动检查结果与人工观察结果。页面外观、理解质量和真实平台授权须人工核对；未做的项标“待人工验收”，不能因源码可见直接标“通过”。

## 8. 风险与开放问题

### 8.1 依赖、风险与开放问题

记录配置预检失败类别、用户完成配置后的任务成功与否、备份/恢复结果、清理影响数量和脱敏诊断使用情况；不记录密钥值。依赖[内容接入](01_内容接入_PRD.md)的能力分级、[任务](02_任务_PRD.md)的配置回流与资源恢复、[知识库](03_知识库_PRD.md) 的内容/版本关系。

**待决**：默认本地/外部模型推荐口径、不同中间材料的默认保留天数、备份中是否包含原始大媒体文件。由个人开发者基于真实磁盘占用、恢复演练及试用反馈决定；在决定前界面只陈述实际保存内容，不做超出能力的恢复承诺。

**决策边界**：默认推荐模型、各类中间材料期限与备份是否包含大媒体，须根据磁盘占用和隔离恢复结果在开放试用前决定。
