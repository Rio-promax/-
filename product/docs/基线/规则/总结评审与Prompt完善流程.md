# 总结评审与 Prompt 完善流程

主Agent执行入口；协议`summary-review-v2`，计分接口不变。本次修订：重要性优先、失败后继续循环。[评审标准](总结评审标准.md)仅供评分，本文负责执行与决策。历史等权成绩不得混用；旧标准评审保留作历史证据，新比较双方按本次标准评价，可复用配置一致的正文。

## 1. 启动

- “审核”只评价指定输出；“完善”执行下表闭环。维护本流程只改规则，不启动真实评测。
- 读取本文、评审标准、当前任务记录及指定材料。确定原文身份、材料目录、基线/候选完整配置、样本分组、预算；先查已有记录，关键来源或权限仍不明才询问。不猜分P、不重开链接、不调用ASR或识图。
- 基线取记录中已验证的最佳配置；没有则用当前正式配置建立基线，不按版本号或单次最高分选优。固定来源、模型、参数及Prompt组装，每轮只改候选Prompt。
- 候选编号取已有最大编号加一，在现有目录准备`Agent2_V数字/Prompt.md`；不覆盖正文。正式设置只读，候选显式传产品API；拒绝候选只需保留当前最佳，不操作正式配置。
- “完善”默认持续循环，沿用用户已授权的模型/API；用户未给调用或费用上限时，不得自行设置一次筛选预算、声称额度耗尽或反复索要续跑许可。执行前说明每轮预计调用数，实际限制按证据报告。无校准记录可探索，但不得宣布最终通过。

## 2. 状态与转移

### 优化事实与限制（2026-11-14用户确认）

- 优化对象是适用于所有视频的通用总结指导Prompt，不是为某一视频改写、填充预先准备的答案。重新以V12为起点，旧视频内容注入轮次的成绩不得作为通用Prompt改善依据。
- 禁止把待评视频的原话、事实提要、参考总结、高分答案、案例特定实体/数据/阶段清单或其改名换数版本加入指导Prompt。视频原文仅在来源材料区域出现；标题只用于正常来源身份，不给生成器提供答案索引。
- 鼓励AI主动编写并增加正例/反例，帮助模型理解清楚、连贯、忠实和版型匹配的表达。正例展示希望采用的写法，反例展示应避免的错误，并说明差别；不是禁止示例，也不以有无、数量多少作为合规否决条件。使用与待评视频内容无关的AI虚构素材，标明教学用途，不复制或变相复述待评视频原话/事实/总结，不以示例替代来源。正例符合高分标准是设计目标，不冒称已独立评分或经用户校准。
- 共用Prompt不同时列简要、通用、详细三套要求。当前请求只注入被选择版型的要求；模式选取沿用产品既有组装，不把其他版型指令带入请求。
- 每个新候选生成前监测：核对Prompt全文、是否向指导区注入待评视频内容，以及去除来源区域后的三种实际请求；正反例本身是鼓励项，不能因使用示例而拦截。只对待评视频原话/事实/答案的直接或变相注入、非当前版型要求等实际违规给出证据并阻止生成；生成后检查是否误把教学示例事实写入真实总结。示例教学效果通过独立质量检查和实际输出比较判断，与注入合规分别记录。语义检查由独立、无历史Agent执行；字符扫描只能辅助，不能代替语义核验。
- 监测在本次优化循环内持续执行，候选/请求变化即重新检查；不安装框架、不创建后台定时任务，不将记录通过等同于质量改善。

| 状态 | 动作 | 判断与下一步 |
|---|---|---|
| 准备 | 核对已有产物、校准记录和样本分组；同视频三版不跨组 | 缺输入先补查；已完成阶段凭证据续接 |
| 提案 | 优先选择影响主旨理解的1—2类重复问题，先排除次要细节的合理省略；区分来源噪声/生成错误/评审误判；一个最小改动，记录证据、假设、预期、回归风险 | 有候选进筛选；审核任务跳过提案 |
| 筛选 | 默认通用，问题专属精简/详细则选该版；用目标及已有非目标样本，一个新Agent评审 | 问题减少且无严重新错才晋级；否则拒绝本候选，返回提案生成下一候选，不结束任务 |
| 复审 | 补三版并跑既定验证样本；三个新Agent分详细/通用/简要，各评四维；只比较当前最佳与候选 | 结果齐全才计分，失败版不减分母 |
| 决定 | 对照基线逐维列出已改善、未解决、新增/退步及其原句证据；仅微涨/冲突时复核争议片段 | 有证据改善且无严重新错/重要遗漏则保留为当前最佳，否则拒绝。综合≤9或仍有严重错误则返回提案；三版完整且综合>9、无严重错误/核心未决才进阶段验收 |
| 阶段验收 | 定稿后用未见视频盲验并由用户确认阅读效果 | 满足验收条件才建议正式升级，未授权不写设置 |

优化集用于诊断，不作为指导Prompt中的答案示例；正反例须另行虚构且与待评视频独立。验证集用于选候选，最终集只阶段验收。P1历史曾被写入示例，仅属优化集，相关成绩不能证明通用Prompt改善；仅有P1时可调试，不编造其他样本、不宣称泛化。最终集反馈用于改Prompt后转为验证用途。

## 3. 评审派发与续跑

新建无历史Agent；只给**评审标准、版型、完整原文、匿名正文、已确认校准样例**。A/B随机排列，身份映射由主Agent保存。不传本文、旧评审、版本号、目标阈值、优化理由；禁止子Agent搜索目录或创建子Agent。只在模型/标准变化或发现漂移时重校准。

派发指令：
> 只读指定标准、来源和匿名正文，不查其他文件。先独立评分再比较，按标准返回逐篇原始JSON，给出逐维原因、问题原句、来源位置、等级和最小改写；无法确定标待核实。不改文件、不创建子Agent。

主Agent保存完整原始输出，再无损组装计分JSON，不用摘要代替证据。每轮在任务记录追加：阶段；基线/候选配置与路径；样本/版型；协议/评审模型；实际调用/已给定的剩余额度；目标问题与改动；已改善/未解决/新增退步及对应维度、证据；决定；连续无改善次数；下一候选方向。无变化也明确说明，不能仅报总分升降。中断从记录及真实文件续跑，正文缺匹配证据不能算完成。

## 4. 命令

在仓库根按状态逐条执行，禁止整段直接运行；筛选未通过不得运行full。先从记录确定`$version`，下例V16仅占位，先准备候选Prompt。此生成器只适用当前P1；其他视频沿用对应产品调用，不复用其硬编码身份。

```powershell
$base = 'D:\Codex\临时导出\2026-11-12-视频总结核对'
$version = 'V16' # 替换为本轮版本
$reviews = Join-Path $base "Agent2_$version/复审评审.json" # 主Agent组装后才计分
product/.venv/Scripts/python.exe product/src/services/core/tools/summary_eval_generate.py $version --base $base --dry-run
product/.venv/Scripts/python.exe product/src/services/core/tools/summary_eval_generate.py $version --base $base
# 专项筛选在版本号后加“简要”或“详细”；筛选通过才补齐
product/.venv/Scripts/python.exe product/src/services/core/tools/summary_eval_generate.py $version --base $base --stage full
product/.venv/Scripts/python.exe product/src/services/core/tools/summary_eval_score.py $reviews
```

生成器不派Agent/评分；默认screen单版、full补三版并复用匹配输出，dry-run不联网/读凭据/写文件。旧local入口仅兼容转发。计分输入：`{"protocol":"summary-review-v2","stage":"screen或full","reviews":{"详细或通用或简要":原始评审对象}}`。一个文件对应一个样本和候选，验证集逐样本检查，不以单个总分代替。

## 5. 决策与停止

- 计分状态：`screen_only`仅筛选；`incomplete`补缺失版；`blocked`先解决严重错误/核心疑问；`below_threshold`未过线；`score_threshold_met`仅分数过线。正式条件：综合严格大于9、三版完整、无严重错误/核心未决、验证集无明确退步、未见视频和人工验收通过。比较材料原本缺版可跳过比较，不缩减产品达标分母。
- 完善闭环：提案→筛选→失败回提案；通过→三版复审→综合≤9回提案；严格>9且质量条件满足→阶段验收。单版过9、拒绝一个候选、保存记录或创建commit均不是任务完成。
- 连续3个候选无可信改善时重新诊断重要性判断、来源、重复规则和生成链路，调整假设后继续，不自动终止。仅用户要求停止、明确额度上限已达到、或核实后无法自行解决的阻塞才暂停；保存检查点并说明实际原因。不为涨分重抽、放宽标准或换模型。
- 技术失败先定位，仅重试失败步骤；来源错回准备；评审冲突查原文；需用户裁决的核心问题暂停相关结论。已有成功产物不重抽，权限不足只暂停受影响步骤。
- 每轮简报必须包含目标问题、实际改动、改善、残留/新增退步、分维分数、继续方向；筛选标明“单版，非综合分”，不以数字细枝末节代替核心诊断。到验收或真实阻塞才结束本次完善。规则检查不等于质量通过；人工项保持待人工验收，不新增材料固定化或优化框架。
