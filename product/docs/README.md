## 当前状态入口

[当前进度台账](基线/当前进度台账.md)是唯一的状态入口：哪个功能已达成、哪些待人工验收、哪些待实施或待授权，只在这里汇总。各方案末尾的「进度总结记录」是单轮证据，不重复回答全局状态。

[总结评审与 Prompt 完善流程](基线/规则/总结评审与Prompt完善流程.md)是总结质量评测的执行正本，含20/20/40/20标准、分阶段审核与完善指令、生成及计分命令。

需求决策查证时，从[调研报告](过程/调研/)、[九项专题研究索引](过程/调研/专题研究/INDEX.md)、[人工笔记](过程/笔记/)和[生成内容与样例](过程/产出/)进入；外部原件位于[调研来源](过程/调研/来源/)。形成明确产品决定后，将结论写入对应的 `基线/需求/` 或 `基线/路线/` 正本，并从正本链接回支撑材料。

## 时间与正本规则

- 需求、路线和执行规则按主题进入 `基线/`；带日期的方案、问题处理、验收与回执按发生月份进入 `过程/YYYY-MM/`。09-24 的两份完善方案已并入 `过程/2026-09/`，不单独占用文档根层。
- 调研、笔记、生成内容和证据附件属于形成决定的过程材料，进入 `过程/`；后续新增有日期的单次材料可放入发生月份，长期可查的来源和汇总放入相应主题入口。
- 同一主题只维护一份正本。后续方案仅在明确列出的条款上修订上位文档；摘要引用正本，不复制一套独立要求。
- 00–03 表达目标结构，04 表达当前事实。自动检查通过不等于人工验收通过；未获用户确认的项仍为“待人工验收”。
- 04 图最后更新于 2026-09-10，内容最新记录停在 2026-08-31，已落后于 09 月之后的多轮实施；它只作结构基线，当前事实以[当前进度台账](基线/当前进度台账.md)为准。
- 带日期的方案、问题处理与回执必须进 `过程/YYYY-MM/`，`docs/` 根层只保留本 README 与四个目录。
- 文档发生冲突时记录具体条款和较晚的用户决定，再同步修正正本与摘要。草稿定稿后迁入基线或过程；被替代材料移入 `历史参考/`。
